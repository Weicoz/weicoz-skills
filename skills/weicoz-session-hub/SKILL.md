# 会话总控台

一个**总控会话**负责拆分任务、派发、收汇报和验收；多个**子会话**各自独立运行，用户可以随时直接进入任一子会话下指令。总控不替子会话干活，只管分工、边界和验收。

适合：多条相互独立的工作线并行推进，用户想随时插手其中某一条，且要一处汇总。不适合：一次性小委派（用宿主子代理即可），或多条线争写同一批文件（先串行化）。

## 选路线

| 路线 | 总控宿主 | 子会话 | 汇报方式 |
|---|---|---|---|
| A. 会话消息 | 仅 Claude Code（需有 `ListAgents`、`SendMessage` 工具） | 本机 Claude Code 会话、后台任务、云端会话、Remote Control 会话 | 本机会话用 `SendMessage` 回发总控；云端会话不能回发，总控读其会话记录 |
| B. Herdr pane | 任何能执行 `herdr` 命令的宿主 | Herdr 支持的任意代理（`herdr agent` 列出 kind） | 总控用 `herdr agent read` / `herdr pane read` 读输出 |

两条路线可以混用。工具是否存在以当前运行环境为准：没有 `ListAgents` 就不能走 A；`HERDR_ENV` 不等于 `1` 就不能走 B，要告诉用户原因，不要从 Herdr 外部操控用户的 Herdr 会话。

## 开工前

1. **列出工作线**：每条线写清目标、输入、产出、范围、完成判据。判据要能验证（文件、提交、测试命令、页面），不能只写“做完”。
2. **定唯一写入者**：同一文件、同一分支、同一外部状态（数据库、部署、对外消息）只能由一个会话写。并行改代码时每条线用独立分支或 worktree。
3. **查负载**：派单前实测本机负载（如 `uptime`、`top -l 1`）。负载高时默认不新开会话，先告诉用户。
4. **授权不扩大**：子会话继承的只是本次已授权的范围。提交、推送、部署、付费、对外发送照旧要用户授权，派单时写明。

## 路线 A：Claude Code 会话消息

1. **开子会话**：由用户在别的终端、桌面端或云端开 Claude Code 会话，或开后台任务。总控不能凭空创建本机交互会话。
2. **列出**：调用 `ListAgents`。地址用表里打印的名字原样填写；只有重名或报错要求区分时才附 `[ref]`。
3. **派单**：`SendMessage({to: "<名字>", message: "<派单说明>"})`，内容用下文模板。对方用户只先看到第一行预览，所以第一行要写清这条消息是什么。正文里的 `@文件路径` 在对方那边不会附带文件，要发原文或让对方自己读路径。
4. **等完成**：本机会话可以加 `notify_when_idle: true`，它下次空闲或退出时总控会收到一次通知。不要循环调用 `ListAgents`，也不要反复发“好了吗”。
5. **汇报**：本机子会话按模板最后一条用 `SendMessage` 回发总控；收到的消息带 `from` 属性，回复时原样填进 `to`。云端会话收得到消息但发不回来：不要叫它回复，到它的会话记录里读结果。Remote Control、云端和桌面端会话不会回报是否被读，沉默不等于同意。
6. **送达不等于执行**：权限模式和总控不同的会话，会把跨会话消息先交给它的用户审批，也可能过期或拒收；本机会话会返回 `[Cross-session delivery notice]`。
7. **不转嫁权限**：总控里被拒绝或会被拦下的操作，不得派给子会话代做，要交回用户决定。
8. **补充指令**：同样用 `SendMessage`。用户直接在子会话里改了方向的，以用户为准，总控更新自己的分工表。

## 路线 B：Herdr pane

先确认 `test "${HERDR_ENV:-}" = 1`，再读 `herdr --skill` 和 `herdr agent`、`herdr pane` 帮助。命令语法以已安装版本为准。

1. **复用优先**：`herdr agent list`、`herdr pane list --workspace "$HERDR_WORKSPACE_ID"` 查现有 pane，同任务优先复用。
2. **开 pane**：`herdr pane split --current --direction right --cwd "$PWD" --no-focus`（宽 pane 向右、窄 pane 向下），从返回的 `.result.pane.pane_id` 取 ID，不要猜。
3. **起代理**：`herdr agent start <名字> --kind <codex|claude|kimi|...> --pane <pane_id>`。名字取有意义的短名（如 `billing-api`），后续都用它。
4. **派单**：`herdr agent prompt <名字> "<派单说明>" --wait --timeout <毫秒>`。返回 `agent_blocked` 说明代理在等审批或提问：读出界面内容交给用户决定，总控不要替用户点同意。
5. **读结果**：`herdr agent read <名字> --source recent --lines 200`；普通命令 pane 用 `herdr pane read <pane_id>`。等待用 `herdr agent wait` 或 `herdr pane wait-output --match ...`，不要循环 sleep 轮询。
6. **用户接管**：用户可以随时进 pane 直接输入。总控再派单前先读一遍最新输出，避免与用户的指令冲突。

## 派单说明模板

```text
【工作线】<名称>（总控：<总控会话名或 pane>）
目标：<一句话结果>
输入：<文件、票据、链接、前置结论>
范围：只改 <路径/分支>；不得改 <路径>；不得提交/推送/部署（除非这里写明已授权）
完成判据：<可验证的检查，如命令与预期输出、文件路径、页面>
产出：<交付物位置>
汇报：完成、失败或受阻时，把「状态、改动文件、验证命令与结果、未完成项」<用 SendMessage 发给 "<总控名>" | 输出在本 pane 末尾，以 "[汇报]" 开头>。
```

汇报状态只用：已完成且已验证、已完成未验证、失败（附关键报错）、受阻（附需要谁做什么）。

## 验收与汇总

- 子会话说“完成”或 Herdr 显示 `done`，只说明它停下了，不说明结果对。总控必须回读产物：看 diff、跑完成判据里的命令、打开页面或文件。
- 不通过的打回原会话，并附上具体证据；不要在总控里悄悄改掉，否则会出现两个写入者。
- 给用户的汇总按工作线列：状态、证据（`路径:行号`、提交号、完整命令）、待用户决策项。没跑的检查标“未验证”。
- 收尾：关掉本次新开且已无用的 pane（`herdr pane close`），保留用户原有的 pane 和会话。

## 常见坑

- 让云端会话“做完回复我”：它回发不了，总控只会白等。
- 把总控被拒的命令派给权限更宽的子会话去跑：这是绕过用户的权限决定。
- 两个会话同时改一个文件或同一分支：后写的覆盖先写的。先分好写入者再派单。
- 用 `--current` 以外的方式定位 pane 时误操作了用户焦点所在的 pane：一律用返回的 ID 或代理名。
- 跨机器（`herdr --machine`）时沿用本机 pane ID：远端 ID 要在远端重新查。
