# 国内需求挖掘 + 刘小排视角

目标：用 `last30days-cn` 做中文平台近 30 天雷达，先从真实抱怨和工作流卡点里找需求，再用刘小排视角判断能否低摩擦执行，最后判断能否变成可持续交易。不要只找热点，不要把种草当需求，不要把“用户想要”直接写成“产品值得做”。

## 总原则

- 先证据后观点。没有来源、链接、评论或平台上下文，不写成确定结论。
- 先抱怨后产品。吐槽、求替代、反复卡住、现有凑合方案，比泛泛种草和趋势词更重要。
- 先窄 wedge 后大平台。输出必须落到具体人群、具体场景、痛苦任务、可交付结果。
- 先人工闭环后全自动。默认建议低摩擦入口、AI 草稿/整理、人工审核、异常升级。
- 先交易后功能。有痛点不代表产品成立，必须判断用户是否愿意持续交换钱、时间、数据或注意力，企业是否能低成本交付并获得利润。
- 国内平台营销、软广、种草和舆情噪声高；必须标注证据强弱和来源失败。

## 触发后的工作流

### Step 0: 定义搜索任务

- 有明确赛道：围绕该赛道扩展痛点词、工作流词、替代方案词和人群词。
- 没明确赛道：默认覆盖小微商家、内容创作者、电商/本地生活、私域/企微、财务/报销/对账、求职/教育、办公自动化、客服/运营。
- 用户给数量：按数量找候选，但最终只保留达标方向。
- 用户没给数量：默认找 5-10 个候选需求，主报告只放“真痛点”和最高潜力“待补证”。

### Step 1: 运行 last30days-cn

使用真实脚本路径：

```bash
python "$WEICOZ_OFFICIAL_LAST30DAYS_SKILL/scripts/last30days.py" "<topic>" --emit compact
```

常用变体：

```bash
python "$WEICOZ_OFFICIAL_LAST30DAYS_SKILL/scripts/last30days.py" "<topic>" --quick --emit compact
python "$WEICOZ_OFFICIAL_LAST30DAYS_SKILL/scripts/last30days.py" "<topic>" --deep --emit md
python "$WEICOZ_OFFICIAL_LAST30DAYS_SKILL/scripts/last30days.py" "<topic>" --search xiaohongshu,zhihu,bilibili,weibo,douyin,wechat --emit compact
python "$WEICOZ_OFFICIAL_LAST30DAYS_SKILL/scripts/last30days.py" "<topic>" --as-of 2026-05-01 --emit compact
python "$WEICOZ_OFFICIAL_LAST30DAYS_SKILL/scripts/last30days.py" --diagnose
```

要求：

- 写明日期范围、启用平台、失败平台。
- 输出区分 confirmed findings、weak signals、failed sources。
- 如果平台返回少或失败，不要补编；改换关键词或缩小平台后再试。
- 如果用户要求报告落盘，默认保存到 `${WEICOZ_OUTPUT_ROOT:-$PWD}/outputs/YYYY-MM-DD-cn-demand-liu-xiaopai.md`。

### Step 2: 用中文痛点词扩搜

不要从产品名出发，先从用户痛苦语言出发。

高信号词：

```text
太麻烦了, 有没有办法, 有没有工具, 求替代, 求推荐, 不想手动,
每天都要, 搞不定, 崩溃, 被坑, 避雷, 太贵了, 用不起,
反复弄, 效率太低, 老是出错, 怎么自动化, 有没有平替,
有没有模板, 有没有批量, 一直审核不过, 客服回不过来
```

工作流词：

```text
报销, 发票, 对账, 记账, 客服, 私域, 群运营, 订单, 发货, 售后,
简历, 投递, 面试, 论文, 写作, 剪辑, 字幕, 笔记, 课程, 直播,
小红书运营, 抖音运营, 商家后台, 企微, 飞书, 钉钉, Excel,
合同, 标书, 数据清洗, 图文排版, 选题, 爆款标题, 店铺运营
```

组合方式：

```text
"赛道/任务" + "太麻烦了"
"赛道/任务" + "有没有工具"
"赛道/任务" + "怎么自动化"
"目标人群" + "每天都要" + "任务"
"现有工具" + "太贵了" / "不好用" / "替代"
```

### Step 3: 按平台理解证据权重

- 小红书：生活方式、消费、工具体验和真实使用吐槽密度高，但种草/软广多；必须看评论区是否复现。
- 知乎：职业、教育、工具比较、决策成本和长文解释较多；警惕营销号和 SEO 软文。
- B站：教程、工作流、UP 主实操、评论区失败案例有价值；看是否有“照着做也卡住”的评论。
- 微博：热点、情绪、吐槽快；噪声高，适合作雷达，不宜单独定性。
- 抖音：场景表达强，评论可暴露大众痛点；但转化和证据需谨慎。
- 公众号：行业分析、私域经验和长文观点多；常是二手观点，不能替代用户原话。
- 百度/头条：补充大众讨论、搜索意图和更下沉表达。

### Step 4: 判定痛点强度

真痛点必须尽量同时满足：

- 具体人群：谁在痛，不是泛泛“用户”。
- 具体场景：什么时候、在哪个平台或流程里卡住。
- 具体任务：要完成什么，不是抽象需求。
- 成本明确：情绪、时间、金钱、风险、机会损失至少有一个清楚。
- 现有凑合方案：Excel、手工复制、多工具拼接、外包、模板、客服人工、脚本等。
- 评论区复现：其他人补充类似场景、失败原因、替代方案或付费暗示。

分级：

| 等级 | 标准 |
|---|---|
| 真痛点 | 场景、成本、凑合方案、评论复现中多个信号成立，危险信号不占主导 |
| 待补证 | 有抱怨或求助，但成本、频率、支付意愿或复现不足 |
| 淘汰 | 纯种草、纯营销、热点围观、信息搜索、一次性好奇、只有单条情绪 |

不要把点赞、转发、收藏、评论数直接等同于需求强度；看评论有没有补出真实工作流细节。

### Step 5: 写窄 wedge

每个达标方向必须写成：

```text
帮 [具体用户] 在 [具体场景] 把 [痛苦任务] 变成 [具体结果]。
```

好：

- 帮小红书商家在每天发货后，把售后私信、订单号和退款原因整理成可审核处理队列。
- 帮自由职业设计师把客户散落在微信/飞书里的修改意见合并成一版可交付修改清单。
- 帮小微财务把每月发票、银行流水和报销单整理成可人工复核的对账表。

差：

- AI 商家助手
- AI 办公平台
- 小红书运营工具

## 刘小排视角评估

在证据判定后，为每个“真痛点”和最高潜力“待补证”方向加“小排评估”。直接给结论，不角色扮演本人。

维度：

1. 需求真实性：是否来自真实抱怨、评论区复现、现成凑合方案；是否是“今天就卡住”的工作流。
2. 杠杆与单位经济：解决一次后能否复用到同类客户；交付成本是线性人工，还是 SOP / 模板 / 模型可复用。
3. 低摩擦入口：用户能否 30 秒内体验价值；是否无需复杂接入，先上传文件、粘贴表格、转发消息、连接一个账号就能跑。
4. SOP 密度：哪些步骤能标准化，哪些必须人工审核，是否适合“AI 先整理/起草，人最后确认”。
5. 模型与工具匹配：应使用 OCR、抽取、分类、改写、排程、检索、校验、规则、脚本还是 LLM；确定性校验层是什么。
6. 分发真实性：目标用户聚集在哪些平台；能否用模板、免费小工具、案例贴、搜索词和垂直社群获得早期反馈。
7. 风险与止损线：什么指标说明是假痛点；哪些隐私、精度、责任边界必须人工兜底。

模板：

```markdown
### 刘小排视角评价

一句话判断：...

- 需求真实性：...
- 杠杆：...
- 低摩擦 MVP：...
- SOP / 模型分工：...
- 分发入口：...
- 风险与止损线：...

建议第一刀：...
不建议做：...
```

## 可持续交易评估

产品经理不是只做用户需求，而是在用户价值和企业价值之间设计一场可持续交易。用户用钱、时间、数据或注意力交换明确结果；企业用有限资源交付结果，并获得收入、利润、复购或增长资产。

评估维度：

1. 用户交换意愿：用户现在是否已为这个问题付出钱、时间、人力、外包或工具成本；不解决会损失什么。
2. 交易频率：问题是每天、每周、每月发生，还是一次性；用户下次遇到同类问题是否会回来。
3. 企业交付成本：是否依赖大量人工；是否能 SOP 化、模板化、自动化；客户越多，边际成本是否下降。
4. 收入与毛利：收费对象是谁；收费依据是省时间、少损失、增收入还是降风险；模型/API/人工/客服成本是否会吃掉毛利。
5. 规模化和复购：是否能从一次任务扩展为持续工作流；是否沉淀数据、流程、账户或历史记录。
6. 企业资源匹配：当前团队能否低成本获客；是否需要重销售、重集成、重服务。

结论规则：

- 真痛点 + 可低摩擦执行 + 可持续交易 = 可做。
- 真痛点 + 执行重/交付重 = 先服务化验证，不直接产品化。
- 真痛点 + 不可交易 = 不做产品，可做内容、免费工具或获客入口。
- 待补证 + 交易想象强 = 先补证，不写成机会。
- 无真实抱怨 = 淘汰。
