# 任务单模板

一张票一个文件：`docs/tasks/<阶段>-<序号>-<归属>-<标题>.md`。执行者可能是能力较弱的模型，所以每一节都写成可照做的条目，不写“同某票”“按惯例”这类需要回查的引用。

```markdown
# <票号> <归属>：<标题>

- 执行者：<implementer / DSH 经 T3 / …>
- 分支：`<fe|be>/<短名>`；worktree：`<工程>/.worktrees/<分支名中 / 换 ->`
- 依赖：<已合并的票>
- 先读：`AGENTS.md`、<设计文档的具体章节>、<契约文件的具体接口>

## 要做
1. <一条一个可验证的改动；写清文件位置、函数名、数据格式>

## 不做
<容易越界的相邻工作>

## 可写范围
<目录列表；超出即停下报告>

## 完成判据（逐条照做，交付时逐条回报“通过/失败 + 关键输出”）
1. `node <weicoz-cocos-run>/scripts/cocos-verify.mjs --project <worktree>`：最后一行“结论：通过”。
2. <本票特有的断言，如“试玩脚本新增步骤 X 返回 ok”>
3. <截图路径与要看的内容>
4. 提交到当前分支（中文提交信息），不合并、不推送。

同一步连续失败两次：停下报告，附该步输出，不扩大改动范围。

## 交付说明
提交号；判据逐条结果；截图路径；改动文件；偏离任务单的地方与原因。
```
