# 验收包模板（H2 灰盒门 / H3 竖切门）

一条消息发给制作人。先跑 `cocos-verify.mjs`（不带 `--quick`）：结论为“不通过”时不发验收包，先修；修不好就向制作人报告阻塞项，不让制作人去试一个已知有问题的版本。制作人只做“试玩 + 选择”。

```markdown
## <游戏名> <灰盒门 / 竖切门> 验收

**怎么玩**（任选一个，已由我确认能打开）
- 手机浏览器：<cocos-preview.mjs --lan 输出里带 ✅ 的地址；不能开 --lan 时写“仅本机：http://127.0.0.1:<端口>/”并说明原因>
- 微信真机：<开发者工具预览二维码截图路径>（竖切门必选）

**请重点感受**（3 分钟内）
1. <本阶段要判断的核心问题，如“点下去爽不爽”>
2. <第二个问题>

**我已自动验证**
| 项 | 结果 | 证据 |
| --- | --- | --- |
| 单测 / 类型检查 | 通过 | <命令> |
| 试玩脚本 | n/n 通过 | <脚本路径>、联系图 `temp/contact.png` |
| 体验指标 | 帧率、每关点击数与耗时 | `cocos-verify.mjs` 输出的指标行 |
| 对标指标 | <达标 / 差距列表> | `docs/benchmark.md` |
| 包体（竖切门） | 主包 x MB | `cocos-build.mjs --release` 输出 |
| 验证等级 | <核心循环已验证 / 目标平台已验证> | |

**请一起回复**（编号作答即可）
1. 方向：(a) 对，进入下一阶段 (b) 调手感后再看 (c) 换方向
2. <积压待定项 1>：(a) … (推荐) (b) …
3. <积压待定项 2>：…
4. （灰盒门）下一阶段要锁定的问题：从设计文档的 [待定] 项、范围拆分、占位资源方案里挑会改变业务结果的，每题给推荐默认值
5. 其他意见：录屏 + 一句话最准

**未验证**：<哪些没测、为什么、需要谁做什么>
```

收到回复后：把选择写进 `docs/PENDING.md`（已决）与 `GLOSSARY.md` / `docs/adr/`，再继续。制作人只答了部分题时，已答的落地，未答的留到下一个节点，不追问。
