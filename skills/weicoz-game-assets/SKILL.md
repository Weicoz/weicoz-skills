# 游戏素材

灰盒阶段不做本 skill。用户在灰盒门确认玩法后才开始，见 `weicoz-game-flow`。

## 1. 美术方向

1. 写 3–5 条方向：配色、线条与形状语言、光影、UI 风格、动效手感。用户已定的直接照抄（如“亮色背景 + 统一黑色线条”）。配色按角色给色值：背景、主体、可交互、危险、奖励、UI。玩家要一眼分出“能点的、危险的、能拿的、装饰的”。
2. 先出一张**风格锚点**：一个最重要的游戏物体放在真实棋盘截图上的效果图。用户认可后才批量出图。

完成标准：方向写进项目 `docs/art.md`，锚点图经用户确认。

## 2. 素材契约

每类素材出图前写一行契约，写进 `docs/art.md` 的素材表：

| 字段 | 例 |
| --- | --- |
| 角色 | 可点击的线头箭头 |
| 运行时尺寸 | 棋盘格 48 px 内，箭头 32 px |
| 透明 | 透明背景，四周留 4 px |
| 朝向 | 默认朝右，代码旋转 |
| 帧 | 单帧；或“受击 4 帧，1 行 4 列，循环” |
| 禁止 | 水印、文字、Logo、裁掉的边、帧之间粘连、背景杂物 |

## 3. 出图

- 用当前宿主可用的出图能力，例如 `gpt-image-2`。提示词写进契约字段，并附锚点图作风格参考。
- 同类素材（图标组、状态帧、道具组）**一次出成网格图**，保证风格一致；单张只用于锚点和定点重做。
- 出图顺序：首个循环必需的玩法物体与反馈 → 最小 HUD 与结算界面 → 背景与装饰 → 次要动画和变体。
- UI 图里不生成文字，文字由 `Label` 渲染。
- 生成原件放 `generated/`（不进 `assets/`），挑选后再复制进 `assets/`。复制时不带 `.meta`，不覆盖已有文件。
- 某一格出错：只重做那一格，不整套重出。

## 4. 切分与审查

```bash
python3 <本目录>/scripts/sheet.py split generated/icons.png 2 4 generated/icons --pad 4
python3 <本目录>/scripts/sheet.py check generated/icons
```

`split` 逐格裁掉多余透明边并统一留边；背景没去掉的格子原样保存并标 ✗。`check` 报告背景残留、留白过多、尺寸过大。

脚本通过后再做人工审查，把素材放进真实游戏截图里看：

- 在手机实际尺寸下还认得出，朝向线索没丢。
- 帧之间角色、比例、朝向一致。
- 和锚点图风格一致。

完成标准：`check` 无 ✗，游戏内截图已给用户看过。

## 5. 导入 Cocos

- 导入、建 SpriteFrame、九宫格、图集按工程内 `funplay-cocos-ui-composition` 执行；导入后用 `check_asset_ready` 确认资源就绪。
- 序列帧做成 `AnimationClip` 并挂到节点上，不留没被引用的散 PNG。方向素材的朝向在源图里就要对，不靠节点旋转偷偷纠正。
- 首包只放第一个可玩画面需要的素材，其余放 Asset Bundle。贴图优先合图集，少用大块透明 PNG 和大背景图。
- 导入后用 `weicoz-cocos-run` 重新构建，对比包体变化。

## 6. 音效

- 首个循环至少留四个音效位：合法操作、非法操作、胜利、失败。没有正式音效时放占位文件，并在 `docs/art.md` 标“占位”。
- 外部音效先核对授权（CC0 或明确可商用），把来源写进素材表。
- 微信小游戏用 mp3；音效短、单声道，避免首包膨胀。
