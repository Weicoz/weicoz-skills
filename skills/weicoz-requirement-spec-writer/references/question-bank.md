# 需求文档补问问题库

只有在现有上下文不足以支撑文档质量时再问。目标是少问、准问，而不是把用户拖进长问卷。

---

## 使用方式

先判断现在缺的是哪一类信息：

- 缺目标
- 缺范围
- 缺边界
- 缺角色
- 缺业务术语
- 缺关键决策
- 缺流程
- 缺规则
- 缺接口 / 数据
- 缺验收
- 缺边界 / 风险

每轮默认问 3-6 个关键问题，按主题分组；如果用户明显想快速推进，只问最关键的 1-3 个。

## 一、目标类问题

适合在“为什么做、做到什么算成”不清楚时问。

- 这次需求最核心要解决的一个问题是什么？
- 谁会因为这个需求直接受益？
- 第一版成功的判断标准是什么？
- 如果只能优化一个指标，你最希望优化什么？
- 这个需求是为了验证方向、提升效率、降低成本、减少错误，还是支持新业务？

## 二、范围类问题

适合在“这次到底做多大”不清楚时问。

- 这次第一版必须做哪些，哪些明确不做？
- 如果时间只够做一半，最核心的闭环是哪一段？
- 这次目标是验证需求、先上线可用版，还是直接做正式版本？
- 这次是否需要兼容旧流程 / 旧数据 / 旧系统？

## 三、边界条件类问题

适合在“哪些情况要处理、哪些情况不处理”不清楚时问。

- 哪些异常情况第一版必须处理？
- 哪些边缘场景可以先不处理，但要写进待确认？
- 有没有数量、次数、时间、权限、成本、配额等上限？
- 有没有明确不能发生的行为或结果？
- 如果外部依赖不可用，流程是中断、重试、降级，还是人工处理？

## 四、角色类问题

适合在“谁在用、谁在操作、谁在验收”不清楚时问。

- 主要使用者是谁？
- 除了主要使用者，还有哪些角色会参与？
- 不同角色看到的内容和可操作范围是否不同？
- 最终谁来判断这次需求算完成？

## 五、业务术语类问题

适合在“名词不统一、概念容易混淆”时问。

- 这个需求里有哪些核心名词必须统一叫法？
- 每个核心名词分别代表什么对象、角色、状态或动作？
- 有没有两个看起来相似但必须区分的概念？
- 这些状态或角色之间是否有层级、归属或流转关系？
- 文档里哪些词必须沿用用户或业务方的原始说法？

## 六、关键决策类问题

适合在“需要拍板，否则实现会分叉”时问。

- 当前有哪些方案已经确定？
- 哪些点还需要你做选择？
- 如果有多个方案，优先级是速度、质量、成本、可扩展性，还是用户体验？
- 哪些决策会影响后续架构、排期、成本或上线风险？
- 有没有你已经明确否掉的方案？

## 七、场景 / 流程类问题

适合在“用户怎么走完整个流程”不清楚时问。

- 用户从哪里进入这个流程？
- 完成一次任务的终点是什么？
- 中间最容易失败或卡住的是哪一步？
- 如果流程被打断，是否需要支持恢复？
- 这个流程里有没有审核、确认、回退、重试之类的节点？

## 八、规则类问题

适合在“系统按什么逻辑判断”不清楚时问。

- 哪些规则会直接影响结果？
- 有没有明确的阈值、区间、优先级、排序规则？
- 有哪些默认值、初始值、上限或次数限制？
- 有哪些场景必须人工确认，不能自动处理？
- 如果规则冲突，哪条优先？

## 九、数据 / 接口类问题

适合在“输入输出和系统边界”不清楚时问。

- 核心输入是什么，来自哪里？
- 核心输出是什么，给谁用？
- 是否需要和外部系统 / 第三方服务对接？
- 是否有必须保留的字段、格式、历史记录？
- 数据失败、重复、延迟、缺失时怎么处理？

## 十、AI / 模型类问题

适合在需求含 LLM、TTS、OCR、分类、生成时问。

- 模型负责生成什么，哪些内容必须可控？
- 是否需要固定输出结构？
- 模型失败时流程是否还能继续？
- 是否有超时、成本、调用频率限制？
- 是否需要人工审核模型输出？

## 十一、验收类问题

适合在“怎么判断做完”不清楚时问。

- 什么结果算成功？
- 哪些情况一定算失败？
- 第一版最少要通过哪些手测 / 冒烟点？
- 有没有必须达到的性能、时延、稳定性指标？

## 十二、风险 / 边界类问题

适合在“看起来都对，但容易返工”时问。

- 有没有明确不做但别人很容易误以为会做的部分？
- 有没有依赖外部资源、权限、账号、配额才能跑起来？
- 有没有高成本、高风险或高投诉可能的地方？
- 有没有需要记录日志、审计、埋点的关键动作？

## 十三、极简提问模板

当你只能问 1 个问题时，优先问：

- “这次第一版必须做到哪里，哪些明确不做？”

当你可以问 2 个问题时，优先问：

- “这次第一版必须做到哪里，哪些明确不做？”
- “谁在用，谁来验收？”

当你可以问 3 个问题时，优先问：

- “这次第一版必须做到哪里，哪些明确不做？”
- “谁在用，谁来验收？”
- “什么情况算成功，什么情况算失败？”

## 十四、SPEC.md 前置追问模板

生成 `SPEC.md` 前，默认按这个结构问：

```markdown
我需要先确认这几个点，确认后再生成 SPEC.md：

## 目标
1. 这次需求最核心要解决的问题是什么？
2. 第一版成功的判断标准是什么？

## 边界
3. P0 必须做哪些？哪些明确不做？
4. 哪些异常、限制或失败场景第一版必须处理？

## 业务术语
5. 需求里有哪些核心名词必须统一定义？

## 关键决策
6. 当前哪些方案已经确定，哪些还需要你拍板？
```

如果用户已经回答过某项，不要重复问，把它列入已确认信息即可。
