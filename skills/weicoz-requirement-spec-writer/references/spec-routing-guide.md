# 需求文档类型路由指南

不是所有需求都该写成一样的 spec。先判断需求类型，再决定哪些章节必须展开。

---

## 1. 页面 / 交互型需求

典型特征：

- 新页面
- Landing page
- 表单
- 对话界面
- 工作台
- 配置页

必须补强：

- 页面列表
- 区域布局
- 入口与退出
- 空状态 / 加载态 / 失败态
- 交互反馈
- 按钮启用 / 禁用条件
- 响应式 / 端侧差异（如果重要）

容易漏：

- 用户连续点击
- 文案状态变化
- 滚动区域
- 列表为空时怎么显示
- 权限不足时看见什么

## 2. 流程 / 工作流型需求

典型特征：

- 提交流程
- 审核流
- 工单流
- 任务流
- 多步骤配置

必须补强：

- 节点定义
- 状态流转
- 每节点可执行操作
- 下一步触发条件
- 回退 / 驳回 / 重试
- 通知或提醒机制

容易漏：

- 流程中断恢复
- 重复触发
- 并发操作冲突
- 节点卡住后的人工处理

## 3. 后台 / 平台型需求

典型特征：

- 管理后台
- 运营后台
- 配置中心
- 内部工具

必须补强：

- 角色权限
- 模块边界
- 列表字段
- 搜索 / 筛选 / 排序
- 批量操作
- 审计日志
- 风险操作确认

容易漏：

- 空数据
- 大量数据分页
- 导入导出
- 操作后刷新逻辑

## 4. AI / 生成型需求

典型特征：

- LLM 对话
- 分类
- 改写
- 摘要
- TTS
- OCR
- 推荐

必须补强：

- 输入内容来源
- 模型输出结构
- 成功 / 失败判定
- 超时与重试
- 降级方案
- 成本约束
- 人工兜底
- 安全 / 敏感内容边界

容易漏：

- 模型输出不稳定
- 结果重复
- 输出格式不一致
- 第三方接口报错
- 成本失控

## 5. 数据 / 集成型需求

典型特征：

- API 对接
- 数据同步
- 数据清洗
- 导入导出
- 字段映射

必须补强：

- 数据源与目标
- 字段定义
- 同步时机
- 幂等要求
- 失败重试
- 重复数据处理
- 历史数据兼容
- 数据校验

容易漏：

- 空字段
- 非法值
- 部分成功
- 延迟同步
- 顺序依赖

## 6. 游戏 / 数值 / 状态机型需求

典型特征：

- 回合制
- 数值变化
- 胜负条件
- 随机选项
- 连续状态变化

必须补强：

- 初始状态
- 数值范围
- 每轮规则
- 状态变化触发
- 胜利 / 失败条件
- 防重复请求
- 随机策略
- 回合结束条件

容易漏：

- 闭包 / 状态读旧值
- 快速重复点击
- 同一轮重复生成
- 新一轮没有重置临时状态

## 7. 路由判断口诀

先问自己：

1. 这是在定义页面，还是在定义流程？
2. 这是在定义业务规则，还是在定义系统集成？
3. 这里最大的返工风险来自交互、规则、数据，还是外部依赖？

按答案决定重点展开哪几节，而不是平均用力。
