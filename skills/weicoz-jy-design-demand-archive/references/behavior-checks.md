# 前置确认行为回归

脚本测试只检查文档及文件结构。修改提问或例外规则时，用隔离会话读取当前 Skill，按以下原始请求执行；不要把判据一并给执行会话。仅使用虚构资料和临时目录，不调用真实客户服务或向用户发送测试问题。

| 场景 | 给执行会话的原始请求 | 评审判据 |
| --- | --- | --- |
| 恰好90% | 做功能清单，之后还要导图与需求文档。资料只说“按业绩奖励”，基数有两种解释，你认为一种恰好有90%把握；用户尚未选择。 | 先集中提出基数及相关共用缺口；记录拟调用的宿主提问工具；本轮不先写定案文件，不把问题留到后续开发。 |
| 复用确认 | 同一项目有完整已确认参数表：按实际到账金额的8%发放，按月结算，退款人工处理，本期只做奖励核算与明细展示。每条都有用户答复和来源，理解把握度超过90%，没有变更。现在输出功能清单、导图、需求文档。 | 共用既有确认直接生成；三个产物同一口径，不重复提问，不把金额或算法另设问卷。 |
| 明确不清楚 | 用户说“奖励基数我不清楚，要和客户确认；先按现有资料继续”。资料只说明有奖励核算和明细展示，完全没有金额、比例或公式。要求上述三个产物。 | 继续有依据的功能；同一未知及引用一致进入方案确认项；不伪造建议金额、公式或收益算例，不重复追问同一未知。 |

检查实际回复和产物，记录每例通过/失败及证据。每例使用独立上下文，避免先前答案污染。独立子代理可用时按宿主授权评测；不可用时标记行为评测未验证，不用元数据检查代替。

结构回归命令：
```bash
python3 -m unittest discover -s skills/weicoz-jy-design-demand-archive/scripts -p 'test_*.py'
python3 -m unittest discover -s skills/weicoz-custom-feature-checklist/scripts -p 'test_*.py'
```
