# 默认输出模板

## 交付结构

### 标题
- 草稿版：`# {项目名}功能清单（初稿）`
- 客户版：`# {项目名}功能清单`，删去下方「待确认项」小节；用户也定不了的项改写为文末「方案确认项」

### 说明
- 依据哪些材料整理
- 本清单是否只包含定制部分
- 是否排除了模板/现成能力

### 主表

| 类型 | 类型描述 | 模块名称 | 功能描述 |
| --- | --- | --- | --- |
| 用户端 | 打卡定制 | 定位打卡 | 用户到达指定地点后进行定位打卡，并记录对应打卡结果。 |
| 平台后台 | 打卡管理 | 打卡点管理 | 后台维护打卡点、点位说明及关联路线。 |

### 待确认项
1. {模块 A 的规则边界}
2. {模块 B 是人工处理还是系统直连}
3. {该模块是否属于 1.0}

### 方案确认项（仅客户版，有需客户确认的项时）
主表对应功能描述写 `建议值，见方案确认项第N条`。

```markdown
## 方案确认项
- 第1条：{问题}
  - 选项：A {…} / B {…} / C {…}
  - 我方建议：{A，理由}
  - 影响：{选不同选项分别会怎样}
```

## 写作要求
- 功能描述用客户能看懂的话，不要写成技术方案。
- 同类模块命名保持一致，不要一会叫“签到”一会叫“打卡任务”。
- 如果一个模块里有多个明确子功能，可拆成多行；如果只是同一能力的自然组成，不必硬拆。

## 文件输出建议
- 如果用户给了源材料路径，优先在同目录落盘。
- 默认文件名：草稿版 `{项目名}-功能清单-初稿-YYYYMMDD.md`，客户版 `{项目名}-功能清单-YYYYMMDD.md`；没有项目名时省略前缀。
- 归档到 jy-design 时，项目名取项目目录名去掉日期段。
