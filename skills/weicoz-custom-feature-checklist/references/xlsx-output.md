# XLSX 输出规则

## 触发条件
- 用户要求“做成 xlsx / Excel / 表格文件”。
- 用户给了一个 `.xlsx` 作为“参考格式 / 参考样式”。
- 用户希望功能清单可直接交付客户确认，而不是只在聊天中预览。

## 推荐顺序
- 用户要求 `.xlsx` 时，内部核对范围、表头和待确认项后直接生成。
- 只有用户明确要求“先确认内容再导出”时，先给主表并等待。
- 未要求文件时，按请求交付聊天版或 Markdown；不把额外格式加入完成条件。

## 默认文件结构
- 工作表：默认使用参考文件中第一个有内容的工作表；无参考文件时创建 `Sheet1`。
- 标题：第 1 行，`A1:D1` 合并，内容为 `{项目名}{版本范围}定制功能清单` 或用户指定标题。
- 表头：第 2 行，固定四列：
  `类型 | 类型描述 | 模块名称 | 功能描述`
- 主表：从第 3 行开始写入功能点。
- 主表到最后一条功能即结束，不在下方追加配置表、口径、算例、来源或内部说明。这些内容保留在沟通记录或需求文档；业务描述必须表达的规则写在相应功能行中。
- 对外文件名、A1 标题、工作表名使用业务名称；“客户版”仅用于内部分类。默认 `audience=client`；明确内部草稿才传 `audience=internal`。
- 空白 Sheet：如果参考文件含空白 Sheet，可保留，不必主动删除。
- 方案确认项（仅客户版）：payload 传 `confirm_items` 时，脚本追加 sheet `方案确认项`，列为 `条目 | 问题 | 选项 | 我方建议 | 影响`，条目自动编号 `第N条`。模板里已有的 `方案确认项` sheet 一律先删掉再按本次条目重建，不沿用旧项目条目；不传 `confirm_items` 就不生成该 sheet。主表功能描述写 `建议值，见方案确认项第N条`，编号必须与条目一一对应。

## 样式规范
- 有参考模板时：优先复用参考模板的工作表结构、列宽、标题/表头/内容区样式。
- 无参考模板时：使用通用默认样式：
  - 标题行：蓝色填充、居中、加粗
  - 表头行：浅蓝填充、居中、加粗
  - 内容区：浅绿色填充、黑色细边框、垂直居中、自动换行
- 列宽参考：
  - A 类型：约 12
  - B 类型描述：约 17
  - C 模块名称：约 23
  - D 功能描述：约 58
- 行高根据功能描述长度调整，避免内容被截断。
- 同一 `类型` 连续多行时合并 A 列；同一 `类型描述` 连续多行时合并 B 列。

## 颗粒度规则
- 独立页面或独立业务模块可以单独成行，例如：商家列表、商家详情、金额输入、订单确认、在线支付。
- 同一功能的自然组成不要拆成多行，例如：余额 + 流水可合并为“资产管理”。
- 后台列表和详情通常合并成一个管理功能，除非用户明确要求页面级清单。
- 支付、提现、结算、审核等如果属于现成模板能力，不写入定制主表；只写客户项目特有的业务规则或显示字段。

## 生成脚本
使用 `scripts/create_feature_checklist_xlsx.py`。

- 必须用脚本生成；禁止用 openpyxl/xlsxwriter 另手写标题行、表头或三表结构。
- 用户未指定模板时，优先用 `jy-design` 同业务类型最近一份客户版（文件名不含“初稿”“内部版”）`.xlsx` 作为 `template`，保留其标题行、表头行、A/B 合并和配色；不要自造一套表结构。查找：`ls -t "$WEICOZ_JY_DESIGN_ROOT"/*/*功能清单*.xlsx | rg -v '初稿|内部版' | head`。

说明：
- 传入 `template` 时，脚本优先复用模板工作表。
- 不传 `template` 时，脚本使用通用默认样式生成新的 `.xlsx`。
- 多个独立业务用 `sheets` 数组，每项含 `name`、`title`、`rows`，统一复用模板；不再同时传顶层 `title/rows`。脚本重建业务表，避免带入模板的旧业务；`confirm_items` 仍只生成一个独立工作表。

`confirm_items` 每项字段：`问题`（必填）、`选项`、`我方建议`、`影响`；按数组顺序编号。

输入 JSON 示例：
```json
{
  "title": "爱贝帮扶一期定制功能清单",
  "output": "/abs/path/爱贝帮扶一期定制功能清单.xlsx",
  "template": "/abs/path/参考功能清单.xlsx",
  "rows": [
    {
      "类型": "用户端",
      "类型描述": "普通用户定制",
      "模块名称": "用户注册认证",
      "功能描述": "用户通过手机号注册，并完成人脸识别后进入平台。"
    }
  ]
}
```

命令示例：
```bash
python3 scripts/create_feature_checklist_xlsx.py input.json
```

多个业务的输入示例（路径字段同上）：
```json
{
  "output": "/abs/path/项目-功能清单.xlsx",
  "sheets": [
    {"name": "服务商体系", "title": "服务商体系定制功能清单", "rows": [
      {"类型": "用户端", "类型描述": "身份管理", "模块名称": "身份查询", "功能描述": "查看当前身份和晋升进度。"}
    ]},
    {"name": "招商挑战", "title": "招商挑战定制功能清单", "rows": [
      {"类型": "用户端", "类型描述": "活动管理", "模块名称": "战队查询", "功能描述": "查看本人所属战队。"}
    ]}
  ]
}
```

## 验证要求
- 生成后确认 `.xlsx` 文件存在且非空。
- 生成器在替换输出文件前自动核对模板、四列表头、功能内容、行数、合并、表尾、确认页和对外名称；不覆盖参考模板。保存同一份输入 JSON 供最终核对。
- 任何二次处理之后，对最终交付文件重跑：`python3 scripts/check_feature_checklist_xlsx.py input.json --file 最终文件.xlsx`。以 payload 中已核对的功能行数为边界，表尾多行、第五列、样式/列宽或内容改变均失败。预览不回写文件。
- 尽量用可用工具读取前几行和末尾几行，确认标题、表头、内容完整。
- 如果当前环境支持渲染，渲染 `A1:D{last_row}` 检查不是空白、样式可读、文字未明显截断。
- 如果无法渲染，至少说明已做文件存在和内容读取验证。
