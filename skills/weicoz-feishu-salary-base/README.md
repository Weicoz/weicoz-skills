# 维护者备注

不属于使用说明（使用看 [SKILL.md](SKILL.md)）。这里只放口径与实现细节；
真实 token、table id、人名与金额不写进来，只活在 `~/.config/weicoz-feishu-salary-base/config.yaml`。

## 口径

- **绩效奖金不由本 skill 计算**。它是 `weicoz-feishu-receipt-base` 按月算完开发绩效后写进来的**结果**。
  本 skill 的职责是：读写工资记录、灌税务数据、把结果发出去。两边都改绩效时，先确认是谁算的。
- **`应上天数` 用「普通工作日」还是「法定应出勤」是两件事**。默认前者；金额敏感时先给草稿让用户拍板。
- **本地估算的实发薪资只是估算**，最终以飞书公式列重算结果为准，不要把估算值当结论报出去。

## 实现坑

- `record-batch-update` **必须串行**。并发会撞 `800004135: OpenAPIBatchUpdateRecords limited`；
  撞上就重新读表、找出没更新的，再串行补写 —— **不要猜哪些成功了**。
- 公式列（`基本实发薪资` / `加班奖金` / `实发薪资`）**异步重算**，写完等几秒再读，别拿旧值当结果。
- `record-list` 的列序是「字段最近使用顺序」会漂移；`record_id` 要和 `data` 数组**同序**对应着取，
  不要按排序后的下标猜。
- `--json` 的文件参数只吃**当前目录下的相对路径**（`@./tmp_x.json`）；`@/tmp/x.json` 会被拒。
  稳的做法是 `cd` 到工作目录再写临时文件，用完 `rm -f`。
- `record-list --limit` 上限是 **200**，传 300 会直接 `invalid_argument: must be between 1 and 200`，
  报错信息里不会提示上限，容易误以为是权限问题。记录超过 200 条要翻页。
- 发消息用 `$'...'` 传真实换行，别把 `\n` 当字面量发出去。
- 姓名是 select 时传 `["<姓名>"]`，不是 `{"name":"<姓名>"}`。

## 人员名单口径（2026-10 确认）

在职 6 人，写在配置的 `name_options` 里；另 2 人已离职，写在 `departed_names` 里。

**离职者的 select 选项不要删** —— 历史工资记录仍在引用，删选项会让那些行变成空值。
离职者不再产生新记录，绩效核算也不会算到他们。

`姓名` 是单选，写入前先核对值在 `name_options` 里；表里没有的人要先加选项，否则写入报错。

## 工资表结构（2026-10-14 核对）

Base 里就一张表，15 个字段，分三组：

- **定位列（3）**：`文本`（写入主键 `YYYYMM-姓名`）、`时间`（text，`YYYYMM`）、`姓名`（select）
- **可写输入列（9）**：基本薪资、应缴社保、个税、应上天数、实上天数、请假小时、加班天数、绩效奖金、补贴
- **公式列（3，只读）**：
  - `基本实发薪资` = 基本薪资 × 实上天数 ÷ 应上天数
  - `加班奖金` = 加班天数 × 20
  - `实发薪资` = 基本实发薪资 + 加班奖金 + 绩效奖金 + 补贴 − 应缴社保 − 个税

字段 ID 存在配置的 `field_ids` 里，用来在字段改名后兜底定位。`record-list` 只回 field_id 加值数组，
**列序会漂移**，不要按下标猜列。

`姓名` 是单选，写入前先核对值在选项里（名单在配置的 `name_options`）；表里没有的人要先加选项，否则报错。

`payroll.overtime_day_rate` 必须与 `加班奖金` 公式里的乘数一致（当前 20），否则本地估算的实发与实际不符。

## 税务 `.xls`

- 只认 `xlrd==1.2.0` 读 `.xls`；`openpyxl` 读不了老格式。
- 月份必须从 `税款所属期起/止` 读，**不只信文件名**；一份文件里出现多个所属月份就停下来问用户。
- `应缴社保` = 养老 + 医疗 + 失业 + 住房公积金（个人部分四项相加）。
- `个税` = `应补(退)税额`，保留源值正负号；**不要**用累计应纳税额、累计应扣缴税额或已缴税额替代。
- `.xls` 有、工资表没有的人：只报告，不自动新增；工资表有、`.xls` 没有的人：默认不动。
