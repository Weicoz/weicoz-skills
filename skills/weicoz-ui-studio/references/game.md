# 游戏的场景、视觉与状态

先读 [完整游玩规范](free/play.md) 与其素材/3D 分支。这里补场景和验收，不能把五次点击范例当作所有游戏玩法实现。

## 场景层级

分别列出背景气氛、可交互主体、即时反馈、HUD/余额、主操作和结果层。主体占据明确舞台，HUD 不遮挡手势区，结果层保留来源。用真实视口检查顶部安全区、底部手指遮挡、横竖屏与键盘。

材质、光向、镜头、色板和角色比例贯穿场景。每种素材写裁切、透明边缘、接触阴影、远近关系与使用状态；角色翻转/侧面/摔落需要对应素材或几何，不把正面图当全角度模型。

空间、碰撞或透明材质影响玩法时使用实时 3D。先让几何、输入和结果正确，再加后处理。限制贴图与绘制量，实测目标设备；WebGL 丢失、资源失败和低性能有可读降级，关键动作有 DOM 或等价键盘入口。

## 业务与演出分开

定义 idle → pressing/aiming → committed → presenting → result。提交点前取消不扣费；提交后结果和扣费由一个真实事务决定，演出不能第二次结算。刷新恢复已提交结果，重复消息幂等，失败保留可确认的业务状态。

暂停冻结演出及允许暂停的输入，不改已结算结果；重开按业务规则清理，不能重置用户余额。手势处理 pointercancel、失焦和中断，键盘等价触发，触摸热区跟随主体。减少动态效果直接展示计算终态，不能停掉玩法。

## 检查

走正常一次、连按、边缘松手、中途取消、暂停/恢复、重开、刷新读回、资源失败、保存失败、次数用尽、离线恢复。使用可重复输入与随机种子定位，不用固定延时猜动画结束。

正常速度看录屏核对加速、减速、碰撞、回弹、音效和奖励去向。先修读不清、误触、状态不同步，再磨镜头和粒子；粒子不盖下一次目标。帧率、功耗和真机体验未测时标未验证。
