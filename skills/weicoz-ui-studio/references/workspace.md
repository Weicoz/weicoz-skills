# 后台与工具的工作区

先问用户的工作对象、操作频次、上下文切换和比较需求，再选布局。

| 任务 | 布局 | 必验 |
| --- | --- | --- |
| 查找后处理单条记录 | 列表—详情 | 当前选择、筛选保留、后退、键盘、手机单栏 |
| 观察流转与优先级 | 看板 | 空列、溢出、键盘移动替代拖放、移动失败恢复 |
| 比较与批量操作 | 表格 | 排序、筛选、全选范围、分页、批量结果 |
| 创作与调参数 | 画布—检查器 | 选中对象、撤销、缩放、检查器滚动不带动画布 |
| 多步骤配置 | 步骤式工作区 | 已完成、当前步、校验、返回不丢输入 |

导航表示位置，工具栏表示当前对象动作，状态栏表示结果。三个区域职责清楚。仪表盘指标必须关联下一步行动；装饰数字不代替可操作记录。

筛选或搜索后当前选中项不在结果里时，详情面板与其中的表单必须一起清空或换成结果里的第一项，绝不能继续显示上一条、还能提交。会产生例外的决定（有不符项仍批准、存在档期冲突仍放行）要求一次明确确认，并在意见里写明例外理由。

决定区（批复、推进、提交这一组主动作）在桌面上始终可见：详情再长，也用粘性面板或独立滚动区，让人边读边做决定，不必翻到底才找到按钮。提交成功后给一个短时间窗口可以撤回，并告诉用户撤回后回到什么状态。原型里，已做的决定和没提交的意见要在刷新后仍在（本地存储即可，并说明是演示）。“清除筛选”只清筛选条件，不改动当前的状态分页和选中项。

状态推进一次只走一步，并且与真实进度绑定（例如一次套一块版），不能一键跳到完成；任何回退或清零都要有确认或撤销，完成后主按钮停用，不要变成“重新开始”。默认排序按任务紧急度（交期、优先级），未完成的排前，已完成的沉底，最急的一条要能一眼认出。

列表—详情布局里，选中对象后详情面板的主动作必须落在目标视口首屏内（1440×900 下实测按钮底边），否则用户每处理一条都要滚动一次。列表行给出判断所需的全部事实（如负责人、数量、交期、状态）和一个可辨认的缩略图，详情面板以对象本身为主角，再列事实与下一步。

把设计变量贯穿导航、表格、表单、图表和浮层：相同密度、边框、字体、选中态、错误态。用真实长数据检查完整页面，不能只美化首屏。

组件馆 `workspace.html` 是版画社的“本周印制”：订单行带图版缩略图与事实，详情以图版为主角并显示四块版的套色进度，提供列表—详情、看板、表格切换、搜索、状态筛选和键盘可用的推进按钮；它是本地数据范例，不包含认证、服务端分页或真实业务权限。
