# 动效、滚动叙事与小游戏

完整动效先读 [动效规范](free/motion.md)；落地/品牌/发布/展览页面再读 [滚动叙事](free/scroll-narrative.md)，保留弹簧、共享元素、分镜、倒放和跳中段检查。本文只作补充。

每段动画说明触发、信息、终态、中断、减少动态效果。普通反馈使用 CSS transition；复杂拖动/Canvas 用 requestAnimationFrame。业务状态立即提交，不等待动画。连续操作从当前位置接力；关闭页面、隐藏标签、销毁组件时取消帧与计时器。

## 三个任务时刻

1. 进入：内容就绪才出场；必要文本不依赖滚动事件才显示。
2. 状态变化：保留对象连续性，例如缩略图到详情、按钮到编辑面板。
3. 动作结果：明确保存、加入、失败和恢复；强调一次，不持续抖动。

反馈通常 100–180ms，展开 180–320ms，品牌出场按阅读节奏安排。列表错峰总时长有限；频繁重新渲染不重播入场。内容没换时避免新旧内容交叉淡化造成重影。

## 滚动叙事

先画章节与每章的一个信息变化，再选择出场、视差、固定舞台或镜头推进。使用项目已有成熟库或浏览器滚动进度，内容始终可读，键盘/PageDown/锚点可达。不接管滚轮、不截断用户返回。小屏重新构图，减少动态效果时静态展开各章。

滚动叙事讲几步，画面就要演几步：文案说“先墨版、再石绿、最后椿红”，画面就分三层逐层出现，而不是一次擦除就揭开全部颜色。验收方法：在每一章的中段截图，看画面是否只出现了这一章说到的内容。

特效必须对应产品里的一个真实动作或材料：印刷品用网点和套色，墨与纸用洇染，工具用刻线。说不出对应哪个动作的流光、粒子和渐变就删掉。Canvas 需要读取图片像素时，`file://` 打开会污染画布，先离线把需要的数据算好写进脚本。一条 SVG 路径里有多段子路径时，Chrome 会在每段开头重置虚线图案，用 `stroke-dashoffset` 做“描线”动画会让所有子路径同时开始；要按顺序描，就拆成独立路径，由脚本按长度依次推进。

范例的刻线（SVG）、网点放大镜（Canvas，网点由真实版画明暗离线算出）、水印晕染（CSS 加湍流位移）、墨洇（WebGL）和滚动套色各有降级；每种特效都对应产品里的一个真实动作，不放无来由的装饰动效。标签页隐藏时暂停，不用每帧修改布局几何。WebGL 使用真实 shader；不支持时给可读状态和 CSS 后备。

## 游玩

先做输入→判定→反馈→下一回合的最小闭环，再添加演出。需要精准操控的任务用 Pointer Events，处理 pointercancel、离开、失焦和重开。键盘有等价操作；音效不能成为唯一反馈。固定随机种子和时间才能验收稳定画面。

难度、得分、胜负、暂停、失败与重置来自状态机。范例为套色对位：色版持续漂移，按“压印”记录这一张的偏差，共五张，按钮和键盘都可完成，减少动态效果时改用固定偏差；真实时间压力和物理碰撞另按游戏规则接入。使用 3D、生成角色、分层背景时先检查素材比例与交互 hitbox，再调粒子、镜头和音效；粒子不盖住下一次输入目标。

实际正常速度走一遍，再连按、反向、暂停和减少动态效果；未测帧率不得报告 60fps。
