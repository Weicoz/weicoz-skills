# 存量改造

先保存主路径的当前截图、设计变量、组件清单和行为。检查共享样式、调用方、状态与接口；只改变用户授权的范围。

| 请求 | 保持 | 改动与验证 |
| --- | --- | --- |
| 优化 UI | 业务含义、信息、品牌 | 调整层级、空间、字体、默认视觉；对比前后完整视口与关键状态 |
| 改流程 | 视觉语言、业务契约 | 画入口到结果，处理返回、取消、错误和权限；走通真实任务 |
| 加功能 | 现有交互和设计系统 | 嵌入已有导航与组件；覆盖新状态及受影响旧路径 |
| 重设计 | 被明确保留的资产与契约 | 重新探索方向；保留数据与导航迁移路径 |

范围不清先通过现状定位问题；只有不可逆业务选择才澄清。先修共享源，避免同类组件继续分裂；避免顺手换框架、重写接口或重命名存储字段。

记录改动影响：哪个用户任务变快/更清楚，旧能力如何保留，哪项需要后续真实运行确认。不同档位方案只有在用户需要比较时制作。
