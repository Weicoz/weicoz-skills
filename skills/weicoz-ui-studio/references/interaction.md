# 交互、状态、表单与浮层

## 状态契约

每个异步主动作列：idle → pending → success / error；并列加载、空、部分结果、离线、无权限。状态由业务结果驱动；乐观更新失败时恢复旧值并解释。保留用户输入；防重复提交；离开和取消使用 AbortController，旧响应不得覆盖新请求。

URL 能表达的筛选、排序、选中项支持刷新与后退；表单草稿存储遵守项目隐私约定。对副作用失败，不猜测未执行，先查状态。

按钮命名动作与对象；disabled 时说明原因。操作后在原对象旁反馈，后台进度使用 aria-live/status，紧急错误用 alert。等待时保持布局，用与最终内容同形的骨架屏占位，不用无期限旋转取代错误恢复。

每个状态只有一个主动作。出错时“重试 / 重新载入”是唯一的主动作：内容没有成功载入，就不能基于页面上残留的旧数据编辑或提交，否则保存时会覆盖服务器上更新的内容；图片、预览这类内容也要标明“未载入”，不能看起来像已经正常显示。空状态的主动作是“创建”；无权限时给出找谁开通，而不是一个灰掉的按钮。状态切换时内容要有一次可感知的变化（短暂的淡入或位移），否则用户分不清页面是否刷新过。

## 表单

使用真实 label、适合的 input 类型、autocomplete 和原生校验。错误连接到字段（aria-describedby、aria-invalid），提交失败聚焦首错或错误摘要。必填、范围、格式在输入前可知；客户端校验不能代替服务端验证。

编辑流程包括：初值、脏状态、提交中、保存成功、服务错误、取消和恢复。字段错误显示在对应字段下方，用页面自己的样式，写明怎么改，并用 aria-describedby 关联；不要只依赖浏览器原生气泡。关闭有改动的弹窗时，要么先确认，要么保留成草稿，下次打开时原样恢复并说明，不能静默丢掉输入。演示“取消提交”这类时间窗口很短的行为时，提供一个慢速开关，让人真的点得到。支付、账号等不可逆动作遵循产品已有确认。批量删除要表达数量与对象；优先可撤销而非反复弹确认。

本 Skill 的组件馆保存动作是明确的本地范例，真实业务接入时替换持久化接口和失败策略，不能把计时器标成真实 API。

## 弹窗与浮层

模态框优先原生 dialog.showModal：有标题、关闭入口、Escape、初始焦点、焦点圈定、关闭后回到触发器；内部表单提交失败保持打开。背景不可操作。危险操作不把默认焦点放在确认按钮。

轻提示不抢焦点；需要操作的错误不能自动消失。菜单使用合适的 button/菜单或 disclosure 语义；键盘可达，点击外部关闭，菜单层级不被父元素 overflow 截断。详情微抽屉保留卡片上下文，只承载短任务；复杂任务进入完整详情。

## 边界状态清单

除了正常流程，逐项想清楚并实现：整组不可用时给出最近的可选项（整天售罄 → 一键换到有票的日期）；上游条件变化后重新取数并说明（换日期后价格重新加载）；数量上限按整笔订单累计，而不是每个选项各算各的；条件变化让已选内容失效时，提示用户调整，不悄悄删掉。

## 屏幕与输入

按内容断点重排，320/390/768/1440 CSS px 和 200% 缩放验证。手机优先保留主动作与内容，次要检查器变抽屉，表格横向滚动需可见提示。安全区用 env(safe-area-inset-*)。固定栏不得盖住表单错误或最后一项。下单、预订、购票这类组件在手机上把合计和主按钮固定在底部，选择过程中一直看得到总价和下一步；成功态按内容收紧高度，不留半截空白。

窄屏重排时，保留主视觉的概念：连续的画带、时间轴不要折成两行打断叙事，改为横向滚动并给出可见的滚动提示，或者换一种同样连续的形态。手机上需要写意见、理由的输入框用多行，并能看到全部内容。

所有功能同时可用键盘与触摸；目标至少 44px 的设计尺寸，焦点明确；hover 只增强，不隐藏唯一入口。检查长中文、长英文、不间断标识、字体加载失败、大数据量。低对比文字不承担必要信息。
