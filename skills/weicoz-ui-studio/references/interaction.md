# 交互、状态、表单与浮层

## 状态契约

每个异步主动作列：idle → pending → success / error；并列加载、空、部分结果、离线、无权限。状态由业务结果驱动；乐观更新失败时恢复旧值并解释。保留用户输入；防重复提交；离开和取消使用 AbortController，旧响应不得覆盖新请求。

URL 能表达的筛选、排序、选中项支持刷新与后退；表单草稿存储遵守项目隐私约定。对副作用失败，不猜测未执行，先查状态。

按钮命名动作与对象；disabled 时说明原因。操作后在原对象旁反馈，后台进度使用 aria-live/status，紧急错误用 alert。等待时保持布局，不用无期限旋转取代错误恢复。

## 表单

使用真实 label、适合的 input 类型、autocomplete 和原生校验。错误连接到字段（aria-describedby、aria-invalid），提交失败聚焦首错或错误摘要。必填、范围、格式在输入前可知；客户端校验不能代替服务端验证。

编辑流程包括：初值、脏状态、提交中、保存成功、服务错误、取消和恢复。支付、账号等不可逆动作遵循产品已有确认。批量删除要表达数量与对象；优先可撤销而非反复弹确认。

本 Skill 的组件馆保存动作是明确的本地范例，真实业务接入时替换持久化接口和失败策略，不能把计时器标成真实 API。

## 弹窗与浮层

模态框优先原生 dialog.showModal：有标题、关闭入口、Escape、初始焦点、焦点圈定、关闭后回到触发器；内部表单提交失败保持打开。背景不可操作。危险操作不把默认焦点放在确认按钮。

轻提示不抢焦点；需要操作的错误不能自动消失。菜单使用合适的 button/菜单或 disclosure 语义；键盘可达，点击外部关闭，菜单层级不被父元素 overflow 截断。详情微抽屉保留卡片上下文，只承载短任务；复杂任务进入完整详情。

## 屏幕与输入

按内容断点重排，320/390/768/1440 CSS px 和 200% 缩放验证。手机优先保留主动作与内容，次要检查器变抽屉，表格横向滚动需可见提示。安全区用 env(safe-area-inset-*)。固定栏不得盖住表单错误或最后一项。

所有功能同时可用键盘与触摸；目标至少 44px 的设计尺寸，焦点明确；hover 只增强，不隐藏唯一入口。检查长中文、长英文、不间断标识、字体加载失败、大数据量。低对比文字不承担必要信息。
