# 深色视频画面密度与氛围工程

解决两件事：画面空得像没做完；改一版漂一版，字幕、音效、文档全跟着错。

## 1. 什么时候用

- 客户或自己觉得「背景太空」「太素」「没有质感」
- 想加素材库视频/图片来填画面
- 已经加过素材，但片子变得像模板广告
- 片子改过几轮后，字幕和旁白对不上、音效错位、文档帧号过期

## 2. 先诊断，不要先加素材

「空」有三种成因，处理方式完全不同。加素材只能掩盖第一种。

| 成因 | 表现 | 手段 |
|---|---|---|
| 底色无材料 | 大面积纯色，网格几乎看不见 | A 程序化氛围层 |
| 主体偏小 | 一个物件占画面 20–30% | D 重构图（放大 + 加层） |
| 只有一层信息 | 全屏只有一个数字或一个环 | D 第二层信息 |

### 2.1 量化门禁

跑 `scripts/measure_density.py`，得到每镜**内容覆盖率**（亮度 > 阈值 的像素占比）。

| 内容覆盖率 | 判定 |
|---|---|
| < 6% | 极空，必须处理 |
| 6–12% | 偏空，至少加氛围层 |
| 12–20% | 正常 |
| > 20% | 偏满，检查是否抢字 |

另看**中位亮度**：纯墨底约 0.04，加了材料应到 0.08–0.11。低于 0.06 说明底色仍是死黑。

深色讲解片的中位覆盖率应落在 **12–16%**。低于 8% 时客户一定会有「空」的感觉。

## 3. 四种手段与取舍

### A 程序化氛围层（首选，零许可风险）

四件套，全部是 frame 的纯函数 + 固定种子，逐帧可复现：

| 层 | 作用 | 参数基线 |
|---|---|---|
| 半调网点 | 给底色加印刷质感 | 格 12px，不透明度 0.075，380f 呼吸 |
| 斜向柔光带 | 制造光位，避免死平 | 520f 横移一周期，不透明度 0.085 |
| 数据雨 | 让画面「在运转」 | 40 条细刻度，固定种子，不透明度 0.16 |
| 扫描列 | 暗示读表动作 | 420f 扫一次，宽 420px，不透明度 0.07 |

必须叠一层**四角压暗**（径向渐变 0.5），保证字幕区干净。
单层亮度上限 0.05，四层叠加 0.09 封顶。超过就会抢字。

组件模板见 `references/atmosphere.tsx`。

### B 可商用静帧材质（叠加，不替换底色）

纸纤维、混凝土、拉丝金属、印刷网点、胶片颗粒。用于给**纯平米色卡**加质感——平色卡是最明显的廉价信号。

来源：Unsplash / Pexels / Pixabay 免费商用。必须逐张记录来源与许可，写进 `CREDITS.md`。

### C 可商用视频素材 + 遮罩（只在有具体场景语义的镜头用）

**不要全片铺。** 背景里出现真人、写字楼、键盘，会和数字抢注意力，并立刻读作素材库模板。

正当用法：只在旁白讲到具体场景时，用重度遮罩：

- 不透明度 8–15%
- 高斯模糊 20–28px
- 局部遮罩（竖条 / 角落），不全屏
- 压暗后亮度低于同帧主体 40% 以上

### D 重构图（治根）

主体放大，并加第二层信息。第二层必须**从同一组动作常量派生**，不能写死时间。

可用第二层：

- 左侧账本（参与者 + 状态：待付 / 已付 / 已返）
- 右侧进度（百分比 + 刻度尺 + 「还差 N 人」）
- 底部刻度尺（纯结构，不带新数字）
- 右上状态块（单号 / SKU / 时间戳）

禁止在第二层引入旁白没念的数字——这会违反图文一致性。

## 4. 反漂移工程（比密度更重要）

密度改造会同时改动几十个时间点。不做单一事实源，下一版必错。四条硬规则：

### 4.1 字幕断行表只存位置，不存文案

```ts
// 错：文案副本，改旁白时它不会跟着变，且优先级更高 → 覆盖新旁白
export const CAPTION_OVERRIDE = { u14: "所以我们做四件事：毫秒分润…" };

// 对：只存断在第几个字符之后，文字一律从旁白取
export const CAPTION_BREAKS: Record<string, number> = { u15: 14 };
export const captionText = (id: string, text: string) => {
  const at = CAPTION_BREAKS[id];
  return at && at > 0 && at < text.length ? text.slice(0, at) + "\n" + text.slice(at) : text;
};
```

断行位置必须落在标点后。落在词中间会把词劈成两行（「推 / 荐人」）。

### 4.2 第二层信息的时间从动作常量派生

```ts
// 错：写死，镜头压缩时长后必然错位
const step1 = seg(frame, 60, 22);

// 对：与主体动作同源
const step1 = seg(frame, NODE, 14);
```

### 4.3 改画面后必须重钉音效

每次改动镜头的动作帧，同步改音效表里该镜所有 cue 的 `from`，然后用互相关实测验证。

实测方法：抽无 BGM 版音轨，与音源 wav 做归一化互相关，报「实测起音帧 vs 目标帧」偏差。偏差 > 2f 即不合格。

历史事故：封顶线在 rel 230 落定，音效 cue 还在 rel 268 —— 晚了 1.23 秒，且落在完全静止的画面，只响不砸。

### 4.4 文档帧号从时间轴生成

`storyboard.md` / `decision-table.md` / `README.md` 里的帧数、镜号、时长、音效条数，全部从 `timeline.ts` 生成或核对。手写必过期。

审查时同时核三处：文档表格、代码常量、成片实际。

### 4.5 审前必须从成片抽帧

从源码渲染的静帧不能代表成片。审查对象必须是从 `out/*.mp4` 直接 `ffmpeg -ss` 抽的帧。否则出现「审的是旧状态」——审查期间源码被改、成片被重渲，审查结论作废。

## 5. 工作流

1. 跑诊断脚本，列出极空镜头
2. 给最显眼的一镜做样板（通常是主角镜，不是最空的镜）
3. 样板确认后，A 层铺全片墨底镜头，逐镜调 intensity
4. B 层只加平色卡（纸卡、纯色面板）
5. C 层只加 1–3 个有场景语义的镜头
6. D 层改极空镜头的构图，第二层从动作常量派生
7. 重钉音效 + 重生成文档
8. 重渲，从成片抽帧，跑密度复测
9. 交独立审核

## 6. 验收清单

- [ ] 极空镜头（< 6%）为 0
- [ ] 中位覆盖率 12–16%，中位亮度 0.08–0.11
- [ ] 氛围层单层亮度 ≤ 0.05，叠加 ≤ 0.09
- [ ] 字幕区（底部 220px）无主体侵入
- [ ] 第二层信息全部有旁白背书，无孤立数字
- [ ] 第二层状态与主体视觉同步（说已付时主体确实已付）
- [ ] 所有音效 cue 落在镜内真实动作帧，偏差 ≤ 2f
- [ ] 字幕文字与旁白逐字一致，断行落在标点后
- [ ] 文档帧号与 `timeline.ts` 一致
- [ ] 审查帧从成片抽取

## 7. 已知陷阱

- **把「留白」当高级**：深色片的留白需要材料支撑。没有材料的留白读作没做完。
- **用素材视频填满**：一眼模板广告，且把「认真算过账」的气质换成「招商片」。
- **只加背景不改构图**：覆盖率从 3% 到 5%，客户还是觉得空。
- **第二层写死时间**：镜头时长一变就全错位，且错得很隐蔽。
- **氛围层太淡**：单层 0.02 的不透明度人眼看不见，白做。
- **氛围层周期太短**：< 240f 的循环会被感知成「在动」，抢注意力。
