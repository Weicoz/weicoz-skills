# 项目报价与服务费用核算

## 输出目标

将需求转成可核对报价。开发功能、第三方服务、服务器和上架费用必须分开；每项可追溯到范围、用量和计算公式。

默认输出：`jy-design/<项目目录>/项目名-项目报价与第三方服务费用-YYYYMMDD.md`（项目名取目录名去掉日期段，命名以 `weicoz-jy-design-demand-archive` 为准）。

同一项目当天已有该文件时优先更新，不创建近似副本。

## 出错后果与提问闭环（强制）

> **出错后果**：报价写错（范围多算漏算、用量假设不对、费用算错）影响很大，会失去客户对我们的信任，所以不得出错。任何不确定点都必须问用户，不得自行假设后写进报价。

- 生成前先读取并执行 `weicoz-jy-design-demand-archive` 第4节：共用业务基线前置确认、严格 >90% 把握度、集中工具提问及「保留未知继续」例外均以该节为准。单独调用本 skill 时同样执行；已有确认记录直接复用。
- 本 skill 的必问点：首期包含哪些功能、未确认能力是否计入、用户量/月活/消息量/媒体容量/视频人分钟、服务器区域与是否高可用、首发平台、是否需要上架协助、付款与维护条款。
- 按共享规则获准保留的未知项：客户版进文末 `## 方案确认项`（每条 `第N条` 开头，写问题、选项 A/B/C、我方建议、对费用的影响），只有有依据的建议值才计价并引用 `建议值，见方案确认项第N条`。格式以归档 skill 第 4 节为准。
- 厂商公开价查不到属于外部事实缺口，不是提问项：写“待厂商书面报价”并列所需参数。

## 使用边界

- 用户只要求归档原话或需求文档时，不主动生成报价。
- 用户要求“报价、预算、费用、服务器、第三方服务/API/SDK 价格、上架费用”之一时生成或更新报价文档。
- 不把支付、分润、直播、Android、AI 审核等未确认能力计入首期；列入“未包含/二期可选”。
- 不用“APP 开发”“后端开发”等大包代替功能报价；用户要求逐项时，一个可验收功能模块一行。

## 工作流

### 1. 锁定范围和假设

读取当前用户补充、同项目最新沟通记录、需求文档和思维导图。

- 范围、用量、条款的缺口全部并入提问闭环问清，不得自行假设。
- 发给客户的报价要过归档 skill 的客户版门禁：正文只写已确认取值；获准保留的未知项进「方案确认项」，有依据时写建议值及费用影响，无依据时只列缺口，不编造确定费用；厂商价格查不到时写“待厂商书面报价”并列所需参数。
- 用户明确说先出内部估算、不等回答时，缺少的用户量、月活、消息量、媒体容量、视频人分钟、地区才可以用明确的预算假设，并在文件首行标“内部版”；不得静默假定。
- 记录首发平台、服务器区域、是否高可用、是否需要上架协助。

### 2. 逐项功能报价

每行只放一个可验收模块，至少包含：

| 字段 | 要求 |
|---|---|
| 功能模块 | 可独立验收；不可把多个核心模块混在一项。 |
| 交付范围 | 写清入口、关键规则、后台/客户端范围。 |
| 价格 | 人民币金额或范围；与总报价口径一致。 |
| 排除项 | 影响价格的二期能力单独写。 |

- 功能行金额必须逐项相加，等于“开发服务费合计”。
- 上架协助、项目管理、测试、部署可单列，禁止隐藏在功能价内。
- 总报价、工期、付款节点只在用户要求时写；写了就需同功能表一致。

### AI 辅助报价标准（强制）

默认按 AI 辅助交付报价，不再使用“人日 × 单价”作为面向客户的开发费用公式。AI 已压缩基础页面、CRUD、代码骨架和测试初稿成本；报价应覆盖可验收交付、外部系统风险、资金责任和上线验收。

```text
项目开发报价 = 已确认功能包 + 外部接口包 + 资金风险包 + 上线验收包
```

| 类型 | 报价范围 | 交付边界 |
|---|---:|---|
| 基础配置/CRUD | 1,000-3,000 元/功能组 | 表单、列表、审核、导出、基础后台配置 |
| 业务规则模块 | 3,000-8,000 元/模块 | 可独立验收的业务规则、权限或数据处理 |
| 状态/库存/核销闭环 | 6,000-12,000 元/闭环 | 状态机、并发约束、异常处理、操作记录 |
| 单家第三方服务商接口 | 8,000-15,000 元/服务商 | 鉴权、下单、回调、重试、异常记录；不含厂商费用 |
| 资金闭环 | 12,000-20,000 元/闭环 | 支付、分账、退款回退、对账、结算；不含通道费 |
| 上线验收包 | 5,000-10,000 元/项目 | 联调、回归、部署、试点数据、上线核对 |

- 基础 CRUD 可因 AI 降低 50%-70%；状态、库存、外部接口、资金模块通常只降低 20%-40%。
- 价格区间由已有代码复用率、规则数量、第三方文档/沙箱完整性、资金责任和验收范围决定。
- 未确认服务商、支付主体、结算口径、接口能力时，不得把风险默认为已包含；应列为前置条件、可选包或“待厂商书面报价”。
- 不得把 AI 生成代码本身作为独立收费项；客户付费对象是通过验收的功能和上线责任。

### AI 辅助工时标准（强制）

工时只用于内部排期、资源安排和客户新增/变更范围的核算；除非客户明确要求按工时合同结算，不得直接以“工时 × 单价”作为对外开发费用依据。

| 工作类型 | 预估工时 |
|---|---:|
| 基础后台 CRUD/配置页 | 2-6 小时/功能组 |
| 业务规则模块 | 8-16 小时/模块 |
| 库存、订单状态、核销 | 16-32 小时/闭环 |
| 单家第三方 API 接入 | 24-40 小时/服务商 |
| 支付、分账、退款、对账 | 40-64 小时/资金闭环 |
| 联调、回归、上线 | 开发工时的 25%-35% |

- 工时是“有效工作量”，不含客户确认等待、资质审核、开户、合同签订、沙箱不可用、第三方故障等待。
- 默认以“1 名主开发 + AI + 共享测试”排期；复杂项目可按并行角色拆分，但不把多人并行工时误报成日历工期。
- 报价文档如写工期，必须同时写前置条件：需求冻结、测试账号/沙箱、接口文档、商户资质和客户验收反馈时限。

### 3. 第三方服务逐项计算

逐个列出实际采用服务，不合并成“云服务费”。每项必须写：

1. 服务商和产品名。
2. 项目中对应功能。
3. 官方价格页面或厂商报价来源、查询日期。
4. 计费单位、预测用量、计算公式、结果。
5. 费用类型：一次性、月度、年度或纯用量。
6. 账号归属和付款人。

优先查服务商官方定价页。价格页面不可访问、产品按销售报价、套餐规则不公开时：

- 明确标为“待厂商书面报价”，说明需提供的 MAU、并发、人分钟、存储量、区域等参数。
- 可给预算区间，但不能伪造固定合同单价。
- 在三档预算中单独显示该不确定项。

### 4. 服务器与部署成本

单独写“服务器配置与费用”，不得只写一个月费总数。

- 区域和选择理由。
- 应用服务器：云厂商、实例规格、磁盘、运行职责、月费公式。
- 数据库：引擎、实例规格、存储、备份、监控、月费公式。
- 对象存储/CDN 与应用服务器分开计算。
- ASCII 架构图：客户端、第三方 IM/RTC、CDN/对象存储、API、数据库。
- 写清容量边界、单机/高可用状态、扩容条件、扩容后的新增费用。

首期默认选满足当前规模的单应用服务器 + 单数据库；除非需求明确，不能先报高可用集群。

### 5. 输出与验证

按 [报价文档模板](references/报价文档模板.md) 输出，删除不适用章节。

交付前检查：

- 功能报价总和 = 开发服务费合计。
- 服务费用按月度、年度、一次性分开；三档合计可复算。
- 每个价格有公式或明确“待厂商书面报价”。
- 上架、第三方账号、服务器账单、超预算扩容责任已写明。
- 未确认能力不计入已报价范围。

## 与需求归档 skill 协作

`weicoz-jy-design-demand-archive` 在用户明确要求报价或完整项目评估时调用本 skill；先完成需求归档，再用已归档材料生成独立报价文档。
