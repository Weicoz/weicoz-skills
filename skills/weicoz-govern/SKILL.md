# 项目体检与治理

一句话：**定期把项目里已经失效的东西找出来，确认后再清理**。脚本只给线索，结论由人回读后下。

## 何时用

- 一个阶段结束（版本发布、大功能合并后）。
- 加新功能明显变费劲：文档互相矛盾、测试慢或不可信、agent 常读错文件。
- 隔一段时间（建议每月或每个迭代一次）。
- 用户说“体检”“治理”“清理文档/测试/worktree”。

## 流程

1. 跑脚本（只读，始终退出码 0，脚本自身出错为 2）：

   ```bash
   node <skill 目录>/scripts/govern-audit.mjs --project <项目目录> [--json] [--stale-days 90]
   ```

   输出每行 `级别 路径:行号 说明 建议`，末行 `结论：N 项待处理（高 a、中 b、低 c）`。该结论行表示“待处理项数”，不是验证结论，与 `weicoz-verify` 的结论行无关。
2. **逐条回读确认**。脚本是启发式，必有误报：打开对应文件核对，确认成立才报。典型误报：断言写在辅助函数里的“零断言”、引用别的仓库的路径、示例路径、故意保留的历史记录。
3. 按级别给建议：高（超限、`.only` 遗留）先处理；中（死链、疑似过期、孤儿测试、零断言、有未提交改动的 worktree）逐条决定；低（接近上限、skip、固定长等待、待确认）攒批处理。
4. **删除前列清单**。删文档、测试、worktree 或分支之前，列出对象、依据和后果，征得用户确认；不得自动删除。归档优先于删除。

## 检查项与判定

| 检查 | 要点 |
| --- | --- |
| AGENTS.md | 项目地图与按任务路由表，建议 4–8 KB，超过 10 KB 必拆；CLAUDE.md 只写 `@AGENTS.md` |
| 死链 | Markdown 相对链接指向的文件不存在 |
| 疑似过期 | 文档最近一次提交超过阈值，且反引号里的路径已不存在。错误文档比没有文档更危险 |
| 过程文档 | 阶段计划、审查清单、临时验收日志，阶段结束后归档，不留在主文档目录 |
| 孤儿测试 | 测试文件不在运行器匹配范围内，也没被任何脚本引用；匹配规则解析不了的标“待确认” |
| 假测试 | 零断言、断言常量、固定长等待、`.only` / skip 遗留。判定标准见 `weicoz-verify` 的 `references/oracles.md` |
| 快慢分层 | 快检脚本不得混入端到端和集成重测 |
| worktree | 区分普通合并、squash 合并、没有独立提交、未合入；只列清理候选。squash 合并的分支需 `git branch -D`，先核实内容已在基础分支 |

脚本覆盖 JS/TS 的 vitest、jest、node:test；其他语言的测试要人工盘点。

## 规则严进常删

AGENTS.md 里的规则，三条都满足才写：

1. 同类问题重复出现 2–3 次。
2. 跨模块通用。
3. 无法写成静态检查。

能写成 lint、测试或钩子的，就写成检查，并删掉对应文字。体检时顺带删：误报多的规则、已被检查覆盖的规则、所涉模块已移除的规则、长期只发生过一次的规则。删规则同样先列清单再确认。

## 分工

- `retro`：复盘后往环境里**加**规则和检查。本 skill 负责定期**清**与核对。
- `weicoz-verify`：定义验证命令、结论行与测试质量标准。本 skill 只引用，不重复；发现假测试后，修测试按其第 6 节“防自评”处理。
- 治理产生的整理改动（归档文档、删测试）仍走项目验证命令，通过后再交付。
