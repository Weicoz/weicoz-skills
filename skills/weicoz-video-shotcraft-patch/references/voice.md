# 配音：校准、句界、词级对齐

## 顺序：旁白是时钟

解说片的时间只有一个来源：合成好的旁白。

1. 定稿：字幕稿 → 配音稿（下文「数字与多音字」）。
2. 选声线，合成整片旁白，做识别回读。
3. 取时间：句界（`vo/cues/`）和词级时间（`vo/cues-words/`）。
4. 按时间写镜头：节拍帧引用真实时间，画面在说到那个词的那一刻出现。
5. Remotion 逐帧渲染，最后合入旁白；渲染不依赖实时播放，卡顿不会让声画错位。

稿子或声线改了，从第 2 步重来，再走下文「换配音后重排」。

## 选声线

- 用同一句（稿子第一句）给每个候选生成试听，横向比较。zero-tts 有自带试听页（`zero_tts.py --voices-page`）。
- 代理听不到声音，可以按客观指标初筛：语种和性别、实测字/分钟、音高、识别回读准确率。初筛给 3–4 个候选，每个写明语速、音高和特点。
- 最终由用户听过再定。定下的引擎、声线、实测语速写进 `design-spec.md`。

## 识别回读

旁白合成后，把每段音频用中文语音识别转回文字，和 `vo/script/segNN.txt` 逐字比对（去空白和标点）。差异逐条列出，按「读错 / 漏读 / 多读 / 识别误差」归类。读错和漏读必须修：改稿、写 `vo/pronounce.json`，或单句重合成；修完再回读，直到差异只剩识别误差。

- 识别引擎：带时间戳的中文 ASR（如 funasr 的 paraformer-zh、Qwen3-ASR）。同一次识别同时产出词级时间，回读和对齐合成一步做。
- 它补的是 `check-polyphones.py` 查不到的错：规则表外的多音字、数字读法、吞字。它不能替代抽听带数字和多音字的句子。
- 现状：本 skill 还没有回读脚本，按上面的方法手动跑。


1. 口播稿按段拆成 `vo/script/segNN.txt`，一段一个文件，只放口播正文（不含画面提示和标题）。
2. 运行 `scripts/calibrate-voice.py <工程> --target <字/分钟>`（引擎见下文「选引擎」）。edge 先用默认语速生成，再按比例调整，最多三轮；zero-tts 在样本上校准，见下文。
3. 读输出的「最终 rate」和实测字/分钟，写进 `design-spec.md`。
4. 用实测时长重排 `src/timing.ts`：一段里有几个镜头，就在句界处切分，每个镜头的帧数等于它覆盖的句子时长之和。成片时长以 `timing.ts` 为唯一真相源，`design-spec.md` 与口头汇报只写「见 timing.ts」。一个工程里曾同时出现过设计文档 576 秒、成片 564 秒、口头 557 秒三个数，终检就是拿这个抓出来的。

## 数字与多音字（配音前必做）

TTS 对阿拉伯数字和多音字的读法不稳：`39.8` 可能读成「三十九八」，`2 桶` 读「二桶」，「间推」读 jiān。办法是把「看的稿」和「读的稿」分开。

- `vo/script-display/segNN.txt`：字幕稿，数字写阿拉伯数字（`39.8`、`29688`、`10%`），文案只改这里。
- `vo/script/segNN.txt`：配音稿，由 `scripts/zh-numerals.py <工程>` 生成，数字全是中文（三十九点八、两万九千六百八十八、百分之十）。不要手改，改字幕稿再重新生成。
- 转换规则：整数按位读；小数点后逐位读；`N%`→百分之 N；千分位逗号去掉；2 后接量词或「到」读「两」（两桶、两到三公里），千位、百位、万位的 2 也读「两」。脚本逐处打印替换清单，**必须看一遍**，重点看「两/二」、小数、百分号、带单位的数字。
- 两份稿的句数必须一致（按 。！？ 切句）；`make-captions.py` 按句序号把字幕换成字幕稿，句数不一致直接报错。
- 字幕里的阿拉伯数字和画面上的数字是一个口径；配音稿只服务于读音。

多音字用 `scripts/check-polyphones.py <工程>` 查：
- **高风险**：TTS 常读错的词（单用的「间推」应读 jiàn、「能当 3 块钱」读 dàng、「得回来」读 děi、「不值当」读 dàng 等）。必须处理：优先改稿，换成没有歧义的说法（能当→能抵，不值当→不划算，得回来→要回来）；术语不能改时，在 `vo/pronounce.json` 写 `{"字幕里的词": "配音里的词"}`（如 `{"间推": "间接推"}`），`zh-numerals.py` 生成配音稿时替换，字幕不受影响。
- **需核对**：命中多音字但没有规则确认读音的位置，看语境；拿不准就单句试听。
- 同音字替换（差价→插价）是最后手段，换完必须试听，字幕仍写原词。
- 规则表在脚本里，新踩到的坑直接补进 `RISKY` 和 `RULES`。

### 逐句漂移

零样本 TTS 逐句合成时，个别句子会漂：音高突然升高、音色发亮或发闷，听着像换了个人（一次试跑 80 句里有 8 句，最严重的一句音高比整片中位数高 63%）。`scripts/voice-consistency.py <工程> --voice <音色>` 读逐句缓存，按音高和频谱重心找偏离整片中位数的句子（≥2 秒、音高偏离超过 20%）；加 `--fix` 把这些句子各重合成几遍，留下最接近整片的一遍，再重跑 `calibrate-voice.py`（命中缓存）。需要 numpy（`pip install numpy`），只此脚本用。它只比较音高和音色，不能替代抽听。

完成判据：`check-polyphones.py` 高风险为 0；`zh-numerals.py` 的清单已逐条看过；整片合成后抽听带数字的句子和处理过的多音字。

## 选引擎

| 引擎 | 什么时候用 | 句界从哪来 |
|---|---|---|
| `zero-tts`（主力） | 解说旁白，设置了 `ZERO_TTS_API_URL` 时默认用它 | 逐句合成后累加时长，句间补 `--gap` 秒静音 |
| `edge`（兜底） | zero-tts 服务不可用时试听、先定时间线；成片前换回 zero-tts 并走「换配音后重排」 | edge-tts 一次生成整段，自带句级时间 |

```bash
python3 scripts/calibrate-voice.py <工程> --target 240 --voice <声线>   # 默认 zero-tts
```

- zero-tts 调用 `weicoz-zero-tts` 的 `zero_tts.py`，主力引擎是 Qwen3-TTS（变速由服务端 ffmpeg 完成，默认声线 `sunday`，不加 EQ）。端点、音色、参考音频的规则以那个 skill 为准；本步骤只负责分段、校准语速和生成句界。
- 服务一次只合成一个任务，其余排队。整片生成前先 `zero_tts.py --status` 看队列；排队就等，不用 `--force`（会丢弃别人的任务）。
- 前提：`ZERO_TTS_API_URL` 已设置。脚本位置由 `ZERO_TTS_SCRIPT` 指定，未设置时在同一仓库的 `skills/weicoz-zero-tts/scripts/` 里找。
- 语速用 `--speed` 倍率校准。一次试跑里，加速不成比例（`zhongli` 速度加 5%，字/分钟只涨约 1.7%），所以在不超过 `--sample-chars` 字的样本上用割线法找倍率，再整片生成一次；倍率限制在 0.6–1.6，到了上下限会提示目标可能达不到。
- 同一倍率重复生成，时长会有波动（Qwen3-TTS 每次采样的自然时长约 ±10%），所以默认容差放宽到 ±5，最终以生成出来的实测时长为准重排 `timing.ts`，不要为了凑精确的目标反复重生成。服务可能中途掉线：已合成的句子缓存在系统临时目录（`calibrate-voice-cache`，按音色、倍率、文本的哈希命名），单句失败自动等 60 秒重试 5 次，仍失败时报错退出，服务恢复后重跑会接着做；掉线时脚本可能已经覆盖了部分 `public/audio/vo/`，重跑成功前不要渲染，或从备份恢复。整片生成要等几分钟到十几分钟（取决于字数和 GPU），中间文件在系统临时目录，结束时清理。
- 声线在 zero-tts 试听页挑（编号、标签、样板声），`--voice` 可写别名或编号；不指定时用 `ZERO_TTS_DEFAULT_VOICE`。下面是旧引擎（GPT-SoVITS）时期的观察，换到当前主力引擎后要重新量：商业模式讲解试过 `jingyuan`（战略漫谈）和 `zhongli`（沉稳讲解），speed 1.0 时 `zhongli` 约 228 字/分钟、`jingyuan` 约 189、`sunday` 约 165，仅作选音色参考，换文本和服务状态会变。慢的音色要靠高倍率才能到 240，倍率太高音质可能变差，用 `--dry-run` 出一版听过再写进工程。

## 要点

- 字数口径与目标语速必须同一口径，脚本里是「去空白和标点后的字符数」，数的是配音稿（`vo/script`）。数字改成中文后字数变多（`39.8`→三十九点八），同样的语速换算出的字/分钟会高约 5%，不要拿阿拉伯数字稿的 240 去比。
- edge-tts 的语速是相对百分比。`zh-CN-XiaoxiaoNeural` 在 `+0%` 时实测约 229 字/分钟，`+5%` 约 240 字/分钟；其他声线不同，要重新量。
- 句与句之间几乎没有停顿。240 字/分钟是连续说话速度，数字密集的段落会偏紧；需要换气就在句间加静音，再重新量时长。
- 换声线、换引擎：见下文「换配音后重排」。

## 句界之外：词级时间

edge-tts 的中文声线只给句级时间。镜头里一句话之内的节点（某个数字、某个词出现的那一刻）只能估算，估算会早到 1–2 秒，审查员每轮都会记一条。词级时间（强制对齐：稿子已知，求每个字的起止）解决这个问题。

存放：`vo/cues-words/segNN.json`，每个词一条 `{"start", "end", "text"}`（秒），与 `vo/cues/segNN.json` 同段对应，文字以配音稿为准。

来源按优先级：

1. 配音引擎随音频返回的字/词时间（部分云端 TTS 会返回）。
2. 对成品旁白跑带时间戳的识别或对齐模型（funasr paraformer-zh、Qwen3-ASR、Montreal Forced Aligner），和识别回读同一次跑。
3. 剪映字幕识别：只到句级，导出字幕文件要会员，只作兜底。

- 现状：本 skill 还没有对齐脚本，`check-sync.py` 只比对句级 cue。有了 `vo/cues-words/` 后，节拍注释里写明对应的词，手动核对节拍帧落在该词起点之后。
- 没有词级时间时，规则是宁晚勿早：节点放在该词所在位置之后，不早于句首；拿不准的放在句子中点之后。镜头文件顶部的节拍常量用注释写明对应哪一句、是句界还是估算。

## 换配音后重排

换声线或引擎后，镜头时长、节拍帧、音效钉帧、字幕都跟着旁白变。先备份旧的 `vo/cues`、`src/timing.ts`、`src/Sfx.tsx`、`src/captions-data.ts`，再：

```bash
python3 scripts/calibrate-voice.py <工程> ...                       # 生成新旁白、句界、清单
python3 scripts/remap-timeline.py <工程> --old-cues <旧 cues 目录> --old-timing <旧 timing.ts>          # 先看报告
python3 scripts/remap-timeline.py <工程> --old-cues <旧 cues 目录> --old-timing <旧 timing.ts> --apply  # 确认后写入
python3 scripts/make-captions.py <工程>                              # 重新生成字幕与 srt
python3 scripts/check-sync.py <工程>                                 # 节拍与新句界是否对得上
```

`remap-timeline.py` 以句子为锚点做分段线性映射：旧旁白每句的起点对应新旁白每句的起点，镜头内所有节拍帧和音效帧都按这条映射挪，镜头总帧数按新旁白重算。前提是每段句子数不变（句子按 。！？ 切分，换引擎不改句子数）。映射不改动画本身的时长常量，换配音后仍要看报告和静帧。
