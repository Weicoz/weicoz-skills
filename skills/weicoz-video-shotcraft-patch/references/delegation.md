# 派镜头实现

## 派单模板

派给 implementer 类代理，每个代理一批镜头。先把共用约束写成工程里的一份 `brief-shots.md`，各派单只写「你负责哪些镜头」。

`brief-shots.md` 必含：

1. 必读：`design-spec.md`、`src/tokens.ts`、一个已通过验收的范例镜头、`src/timing.ts`（帧数）、所在段的 `vo/script`、`vo/cues` 与 `vo/cues-words`（字级时间，`align-words.py` 生成）。
2. 蒙皮：镜头卡只继承运动、节奏、已调参数；配色、字体、材质全部用 spec 的 tokens。卡上「已知坑」的命门参数保持原值。
3. 同步：画面在说到那个词的那一刻出现。节拍集中写在文件顶部的 `BEATS` 常量，每条注释写字级锚点 `cueN@词`：N 从 0 起，与 `vo/cues/segNN.json` 的数组下标一致（第一句是 cue0），词按配音稿写（数字是中文，如「三积分」）；同一句里出现多次加 `#k`。帧号用 `python3 scripts/align-words.py <工程> --find segNN 词` 查，填它给出的镜头内帧号：
   ```ts
   const BEATS = {
     flip: 210,          // cue3@推成「推成一单」：色波起点
     eq2: 245,           // cue3@三积分「= 3 积分」
     rows: [419, 556],   // cue4@直推 cue5@间推（数组按顺序配对多个锚点）
     inhale: 200,        // flip 前 10 帧的预备动作，不写 cueN，不检查
   };
   ```
   `scripts/check-sync.py` 按锚点核对：早于该词超过 2 帧判红（画面抢在声音前面），晚于超过 6 帧判黄。还没有 `vo/cues-words` 时才退回句级写法（`cue1`、`cue4–6`），句内节点加「估算」，按 [voice.md](voice.md) 宁晚勿早。
4. 安全区：所有文字、数字、标签、算式的最低点 ≤ spec 写的内容最低点（默认 900）。
5. 节奏：每个镜头一个主动效；关键数字落定后静止 ≥1 秒；镜头末尾 ≥1 秒无运动。
6. 确定性：伪随机用固定种子，时间只读帧号。
7. 字幕：旁白字幕只由全局字幕层渲染，镜头组件只负责画面内容。公共的 Frame 组件如果有 `caption` 属性，全局字幕层存在时让它在开发期抛错，在开发期就暴露双层字幕。
8. 真实素材：只用 `public/media/` 里、已登记在 `media/sources.json` 的文件；视频用 `ClipCard`，图片用 `Img` + `staticFile`；不得引用网络地址，不得自己另找素材（缺素材就在摘要里写明，交主会话按 [media.md](media.md) 选材）。
9. 写范围：只能写自己的镜头文件、自己新增的辅助文件、自己的开发入口目录；其余文件只读。

## 完成判据（写进每份派单）

- `python3 scripts/check-shots.py <工程>` 无错误（类型检查真正跑过；字号 ≥32；确定性；色板外颜色逐条说明）。
- `python3 scripts/check-sync.py <工程>` 无红色。
- 用了真实素材时，`python3 scripts/check-media.py <工程>` 无错误。
- 用完整合成（带字幕条）渲染静帧：入场、主动作高点、数字落定、末帧，逐张看过，字幕条没有盖住内容。
- 回复摘要：每个镜头的文件、关键帧号、偏离卡参数的地方、未完成项。

## 涉及第三方接口时

派单写明：测试样例必须从真实接口录制（存进 `tests/fixtures/recorded/`，附重录方法），不得手写；另加一组联网冒烟测试，本机有 Key 的来源真实跑一次、没有 Key 的跳过。手写样例只会复现实现者自己的假设（实测：Pixabay 视频缩略图字段手写错了，离线测试全过，上线才发现）。

## 没有 git 提交时

`worktree` 隔离要求目录里有提交历史，空仓库或全部未跟踪的目录用不了。两种做法：

- 派单前先提交一次基线，再用 worktree。
- 给每个代理划不相交的可写文件，共用文件（tokens、Root、timing、总时间线）只由主会话改。

选哪种，在派单里写明。
