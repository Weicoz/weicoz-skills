# 派镜头实现

## 派单模板

派给 implementer 类代理，每个代理一批镜头。先把共用约束写成工程里的一份 `brief-shots.md`，各派单只写「你负责哪些镜头」。

`brief-shots.md` 必含：

1. 必读：`design-spec.md`、`src/tokens.ts`、一个已通过验收的范例镜头、`src/timing.ts`（帧数）、所在段的 `vo/script` 与 `vo/cues`。
2. 蒙皮：镜头卡只继承运动、节奏、已调参数；配色、字体、材质全部用 spec 的 tokens。卡上「已知坑」的命门参数不得降档。
3. 同步：关键数字与标签落在对应旁白句附近；节拍集中写在文件顶部的 `BEATS`，每条注释写明对应哪一句。句内节点没有词级时间时，按 [voice.md](voice.md) 的规则，宁晚勿早。
4. 安全区：所有文字、数字、标签、算式的最低点 ≤ spec 写的内容最低点（默认 900）。
5. 节奏：每个镜头一个主动效；关键数字落定后静止 ≥1 秒；镜头末尾静止 ≥1 秒。
6. 确定性：不用 `Math.random`、`Date.now`。
7. 写范围：只能写自己的镜头文件、自己新增的辅助文件、自己的开发入口目录。其余文件只读。

## 完成判据（写进每份派单）

- `npx tsc --noEmit` 无错误。
- `python3 scripts/check-shots.py <工程>` 无错误（字号 ≥32、无非确定 API；色板外颜色逐条说明）。
- 用完整合成（带字幕条）渲染静帧：入场、主动作高点、数字落定、末帧，逐张看过，确认字幕条没有盖住内容。
- 末尾 30 帧静止。
- 回复摘要：每个镜头的文件、关键帧号、偏离卡参数的地方、未完成项。同一问题连续两次未通过就停下报告。

## 没有 git 提交时

`worktree` 隔离要求目录里有提交历史，空仓库或全部未跟踪的目录用不了。两种做法：

- 派单前先提交一次基线，再用 worktree。
- 给每个代理划不相交的可写文件，共用文件（tokens、Root、timing、总时间线）只由主会话改。

选哪种，在派单里写明。
