# 派镜头实现

## 派单模板

派给 implementer 类代理，每个代理一批镜头。先把共用约束写成工程里的一份 `brief-shots.md`，各派单只写「你负责哪些镜头」。

`brief-shots.md` 必含：

1. 必读：`design-spec.md`、`src/tokens.ts`、一个已通过验收的范例镜头、`src/timing.ts`（帧数）、所在段的 `vo/script` 与 `vo/cues`。
2. 蒙皮：镜头卡只继承运动、节奏、已调参数；配色、字体、材质全部用 spec 的 tokens。卡上「已知坑」的命门参数保持原值。
3. 同步：关键数字与标签落在对应旁白句附近。节拍集中写在文件顶部的 `BEATS` 常量，每条注释带 `cueN`，N 从 0 起，与 `vo/cues/segNN.json` 的数组下标一致（第一句是 cue0）。数组写法可以列多个 cue（`cue4/5/6` 或 `cue4–6`）。句内节点没有词级时间时，再加「估算」：
   ```ts
   const BEATS = {
     badge: 121,            // cue1 水喝了，钱回来了，还多出两毛
     rows: [419, 556, 708], // cue4–6 直推 / 间推 / 配送
     lead: 430,             // cue3 句内，估算
   };
   ```
   `scripts/check-sync.py` 按这个格式比对节拍与句窗口，格式要照写。句内节点按 [voice.md](voice.md) 的规则，宁晚勿早。
4. 安全区：所有文字、数字、标签、算式的最低点 ≤ spec 写的内容最低点（默认 900）。
5. 节奏：每个镜头一个主动效；关键数字落定后静止 ≥1 秒；镜头末尾 ≥1 秒无运动。
6. 确定性：伪随机用固定种子，时间只读帧号。
7. 字幕：旁白字幕只由全局字幕层渲染，镜头组件只负责画面内容。公共的 Frame 组件如果有 `caption` 属性，全局字幕层存在时让它在开发期抛错，在开发期就暴露双层字幕。
8. 写范围：只能写自己的镜头文件、自己新增的辅助文件、自己的开发入口目录；其余文件只读。

## 完成判据（写进每份派单）

- `python3 scripts/check-shots.py <工程>` 无错误（类型检查真正跑过；字号 ≥32；确定性；色板外颜色逐条说明）。
- `python3 scripts/check-sync.py <工程>` 无红色。
- 用完整合成（带字幕条）渲染静帧：入场、主动作高点、数字落定、末帧，逐张看过，字幕条没有盖住内容。
- 回复摘要：每个镜头的文件、关键帧号、偏离卡参数的地方、未完成项。

## 没有 git 提交时

`worktree` 隔离要求目录里有提交历史，空仓库或全部未跟踪的目录用不了。两种做法：

- 派单前先提交一次基线，再用 worktree。
- 给每个代理划不相交的可写文件，共用文件（tokens、Root、timing、总时间线）只由主会话改。

选哪种，在派单里写明。
