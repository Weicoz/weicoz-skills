# 独立审查循环

制作者对自己的产出有确认偏差，所以每轮审查都派全新上下文的审查员。循环直到 PASS：无「高」、无「中」问题。

## 一轮的步骤

1. 渲出成片，跑 `scripts/extract-review-frames.py` 与 `scripts/check-caption-overlap.py`，把证据目录和扫描结果交给审查员。
2. 派一个新审查员（general-purpose 类），用下面的模板。不要给它上一轮的结论，只给「设计意图补充」。
3. 收到报告：
   - PASS：把轮次和遗留的低严重度项写进交付说明，结束。
   - FAIL：按问题清单修。只改画面时用 `scripts/render-shots.py` 重渲；然后回到第 1 步，换一个新审查员。
4. 同一问题两轮没修好，停下告诉用户，不要硬试第三次。

## 审查员任务书模板

把尖括号换成本工程的值。

```
你是一个全新的、独立的终检审查员。你不知道这支片子是怎么做出来的，也没有任何人的结论可以参考。请完全基于证据审查，不要预设它是好的。

被审查对象：<一句话说明片子和观众>。工程目录：<工程路径>
成片：<各版本文件与内容说明>；无字幕画面：<路径>
审查基准（必读）：design-spec.md；video-shotcraft 的 references/final-review.md 与 aesthetic-rules.md；口播稿与 vo/script；vo/cues 与 src/timing.ts；src/captions-data.ts；src/shots 各镜头顶部的 BEATS；<视觉参考静帧>；<用户原始需求>。
证据（已备好）：<证据目录>（联系表 sheet_*.png、cues_global.txt）。

必须逐条给结论：
P1 风格统一：「镜头 × 背景 / 字体 / 描边 / 配色 / 水波」核对表。相邻镜头之间的背景、字体、配色断层，不论 spec 是否允许，一律按「中」上报。
P2 字幕：与旁白原文逐字对照；同步偏差 >0.5 秒记一条；srt 与烧录一致。
P3 字幕遮挡：每个镜头在字幕在场时至少抽 4 帧，核对字幕条有没有压住文字、数字、标签、算式。
P4 上一轮改动的回归：<逐项列出>。
另做完整终检：数字逐一对照 spec；文字裁切、重叠、错别字、对比度、字号（辅助文字 ≥32 px）；方案一致性与命门参数；旁白与画面同步；音频测量；20 岁普通人能否看懂；节奏（区分必要停留与空等）；镜头交界。

设计意图补充（不是缺陷）：<例如 BGM 有意比旁白低 10–15 dB；旁白慢所以有必要停留；用户已决定不加合规提示；月入类数字沿用口播稿口径并已用小字标明计入项>。

约束：
- 只读审查，只能在 <证据目录> 下写图片等证据文件。不要写 report.md，完整报告放在最终回复里（子代理写报告文件常被拒绝）。
- 证据精确到「镜头 id + 全局帧号 + 时间码」。没看到的标「未验证」。你无法听音，不能声称听过，只报测量值。
- 严重度：高 = 数字或内容错误、坏帧、会误导观众；中 = 明显影响观看或理解、违反 spec、风格断层、字幕遮挡关键内容、字小到看不清；低 = 小瑕疵。

输出结构固定：1 结论（PASS/FAIL，有高或中就是 FAIL）；2 风格核对表；3 字幕结论；4 遮挡表；5 回归逐项；6 问题清单（高中低，每条含镜头 id、帧号、时间码、现象、影响、建议修法）；7 已验证项；8 未验证项。
```

## 经验

- 审查员听不了声音。听感（旁白声线、BGM、音效是否盖住旁白）留给用户，在交付说明里明说。
- 审查员只对照 spec 时，会放过 spec 本身带来的断层，所以 P1 要求它独立于 spec 判断。
- 数字口径沿用原稿时，让审查员检查「画面小字与算式是否一致」，不要让它按口径对错判高严重度。
