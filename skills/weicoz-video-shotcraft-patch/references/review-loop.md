# 独立审查循环

制作者对自己的产出有确认偏差，所以每轮审查都派全新上下文的审查员。循环直到 PASS：无「高」、无「中」问题。

## 一轮的步骤

1. 渲出成片，跑 `scripts/extract-review-frames.py`、`scripts/check-caption-overlap.py` 与 `scripts/check-audio.py --listen`（见下文「音频检查」），把证据目录、扫描结果和 `audio-report.md` 交给审查员。`check-audio` 有红项时先修，不派审查员。
2. 派一个新审查员（general-purpose 类），用下面的模板。审查员只收「设计意图补充」，上一轮的结论留在主会话。
3. 收到报告：
   - PASS：把轮次和遗留的低严重度项写进交付说明，结束。
   - FAIL：按问题清单修。只改画面时用 `scripts/render-shots.py` 重渲；然后回到第 1 步，换一个新审查员。
4. 同一问题两轮没修好，停下告诉用户。

## 审查员任务书模板

把尖括号换成本工程的值。

```
你是一个全新的、独立的终检审查员。你只拥有下列证据和基准文件。请完全基于证据审查，逐项找反证。

被审查对象：<一句话说明片子和观众>。工程目录：<工程路径>
成片：<各版本文件与内容说明>；无字幕画面：<路径>
审查基准（必读）：design-spec.md；media/sources.json 与 media/CREDITS.md（有真实素材时）；video-shotcraft 的 references/final-review.md 与 aesthetic-rules.md；口播稿与 vo/script；vo/cues 与 src/timing.ts；src/captions-data.ts；src/shots 各镜头顶部的 BEATS；<视觉参考静帧>；<用户原始需求>。
证据（已备好）：<证据目录>（联系表 sheet_*.png、cues_global.txt）。

必须逐条给结论：
P1 风格统一：「镜头 × 背景 / 字体 / 描边 / 配色 / 水波」核对表。相邻镜头之间的背景、字体、配色断层，不论 spec 是否允许，一律按「中」上报。
P2 字幕：与旁白原文逐字对照；同步偏差 >0.5 秒记一条；srt 与烧录一致。
P3 字幕遮挡：每个镜头在字幕在场时至少抽 4 帧，核对字幕条有没有压住文字、数字、标签、算式。同一批帧里再核对画面元素之间有没有互相压住：后加的卡片、真实素材、标签与原有面板、等式、数字之间的重叠逐条列出（入场动画中段也要看，弹入时位移最大）。
P4 上一轮改动的回归：<逐项列出>。
P5 素材（有 media/sources.json 时）：逐条核对画面内容与对应旁白是否相关；AI 生成素材另查手指与肢体变形、乱码文字、透视比例、与相邻镜头的风格断层，以及是否用 AI 生成了真实人物、品牌或事件（不允许）；能认出的人脸、品牌标志、水印、可读的他人文字逐条列出；画质（模糊、压缩块、拉伸变形）与相邻手搭镜头是否断层；media/CREDITS.md 是否包含所有需署名的素材，有 AI 生成素材时是否写明「部分画面由 AI 生成」。
P6 音频：按 <证据目录>/audio-report.md 逐项给结论。红项按「高」，黄项按「中」，「Gemini 试听（参考）」里的黄项按「低」，并写明需要用户试听的片段路径。报告里标「未验证」的检查，照抄进你的未验证项。
另做完整终检：数字逐一对照 spec；文字裁切、重叠、错别字、对比度、字号（辅助文字 ≥32 px）；方案一致性与命门参数；旁白与画面同步；20 岁普通人能否看懂；节奏（区分必要停留与空等）；镜头交界。

设计意图补充（不是缺陷）：<例如 BGM 有意比旁白低 10–15 dB；旁白慢所以有必要停留；用户已决定不加合规提示；月入类数字沿用口播稿口径并已用小字标明计入项>。

约束：
- 只读审查，只能在 <证据目录> 下写图片等证据文件。完整报告放在最终回复里。<若要求落文件：报告另存到 <证据目录>/report.md，先写文件再回话。>
- 证据精确到「镜头 id + 全局帧号 + 时间码」。没看到的标「未验证」。你无法听音，只报测量值。
- 严重度：高 = 数字或内容错误、坏帧、会误导观众；中 = 明显影响观看或理解、违反 spec、风格断层、字幕遮挡关键内容、字小到看不清；低 = 小瑕疵。

输出结构固定：1 结论（PASS/FAIL，有高或中就是 FAIL）；2 风格核对表；3 字幕结论；4 遮挡表；5 回归逐项；6 音频结论；7 问题清单（高中低，每条含镜头 id、帧号、时间码、现象、影响、建议修法）；8 已验证项；9 未验证项。
```

## 报告交回的方式

- 默认让审查员把完整报告放在最终回复里。有的子代理环境不允许写报告文件，要求写文件会让它写不出来。
- 必须落文件时（例如要存档），派单里写明报告文件路径（在它允许写入的目录内）和「先写文件，再回话」，子代理结束后第一件事检查文件是否存在。
- 子代理结束但没有报告（回复为空、文件不存在），视为失败，立刻重派并收紧要求。一个工程里第一次终检的子代理没写报告就结束，主会话白等了 20 分钟。

## 音频检查

审查员听不了声音，听感由 `check-audio.py` 转成测量值：

```bash
python3 scripts/check-audio.py <工程> --final <成片.mp4> --out <证据目录> --props '<与成片相同的 props>' --listen
```

- 合成必须有 `vo`、`sfx`、`bgm` 三个布尔开关，脚本用它们分轨渲染纯旁白和纯背景（BGM 加音效）。
- 测量项：整体响度与真峰值；逐句旁白比背景高多少 dB（每 0.05 秒一块，取中位数和背景压过旁白的时间占比）；成片与纯旁白分别做远端识别，比较差异字数（被盖住的句子在成片里识别会变差）；超过 2 秒的空白；段落接缝的爆音。阈值见脚本开头的说明。
- 判红只有三种情况：识别确认成片里听不清、背景大部分时间比旁白响、削波。其余声学测量只判黄，黄项的片段交给 Gemini 和用户听。
- `--listen` 把有问题的句子、每段的样句和接缝片段交给 agy（Gemini）试听，判断自然度、情绪、遮盖和读错。默认 `gemini-3.8-flash-low` 和 `--effort low`，因为试听不需要推理，这样省时间和额度。Gemini 的结论只作参考，不影响退出码。
- 用户只听报告里标出的片段（`<证据目录>/clips/`），不必听全片。交付说明写明哪些片段由用户听过。

## 经验

- 审查员只按 `audio-report.md` 判音频，不凭画面推测听感。
- 审查员只对照 spec 时，会放过 spec 本身带来的断层，所以 P1 要求它独立于 spec 判断。
- 数字口径沿用原稿时，让审查员检查「画面小字与算式是否一致」，严重度按「画面小字与算式是否一致」判。
