# 已初始化仓库：证据驱动对齐

先对比现状、改动和冲突。用户要求同步或优化时，直接执行范围内有证据、无冲突的修改；用户只要求审查时只报告。不得把二次进入当成必须重新授权。

首次安装走 `SKILL.md` 主流程。本文件只管二次进入。

## 判定已初始化

满足任一即走本轨：

- 同时存在根 `AGENTS.md` 与 `docs/constitution.md`
- 存在 `docs/SDD-Guide.md` 且根 `AGENTS.md` 已有 SDD / 宪法指针
- 用户说「对齐」「同步规范」「更新 AGENTS」「已经初始化过」

未初始化 → 首次安装。列清实际需要的文件，不以模板完整性扩大任务。

## 对比什么

对照 `file-map.md` 的相关项和当前代码/ADR；只有明确要求完整同构时才检查完整集，不对照 Clawith 的法律正文。

| 维度 | 现状怎么采 | 目标是什么 |
|---|---|---|
| 文件地图 | 列出已有 OS 文件 | 仅补影响本次目标的缺项，多余项不擅自删除 |
| 根 `AGENTS.md` 五节 | 是否有 Identity / 宪法指针 / 命令 / SDD / 映射 | 结构齐；命令、栈、路径与 `package.json` 等一致 |
| `CLAUDE.md` | 是否只有 `AGENTS.md` | 单行指针；多余规则并入根文件后删 |
| 宪法 vs 证据 | 每条 C 能否指到现行代码/ADR | 过期条款标冲突；新 ADR 未入宪法标更新 |
| 目录 `AGENTS.md` | 根 §5 映射 vs 磁盘上的文件 | 映射追上已有文件；**不为每个新文件夹自动新建** |
| 架构快照 | `docs/architecture/` 是否还像今天 | 覆盖写今日拓扑；旧决策留 ADR |
| 护栏 | `arch-guard.sh` 模式是否还能扫到 C4 等 | 按现行包装层路径改 grep，不抄别仓 |
| 双轨 | OpenSpec / superpowers 是否仍当新功能入口 | 保留有效入口；明确授权迁移时才档案化，不删目录 |
| 人工段 | `<!-- MANUAL ADDITIONS` | 原样保留 |

新子系统目录（自己的入口、所有权、失败语义）没有目录说明：在报告里列为 **建议**，默认不新建文件。用户点头才写。

## 分类

- **建议不动**：仍被证据支撑的条款、人工段、ADR、`CONTEXT.md`、存量 OpenSpec 目录
- **新增**：本次目标确实需要且不存在的文件，不因地图里有就补齐
- **更新（无冲突）**：过期命令、端口、栈、§5 映射漏了已有文件、架构快照过时
- **冲突**：两份都像对、不能静默合并。必须用户选

冲突例子：

- `CLAUDE.md` 里有本仓命令，根 `AGENTS.md` 也有，合并会丢哪边
- 宪法 C 条与更新的 ADR / 代码相反
- 用户改过的 `AGENTS.md` 结构不是五节，强行套模板会冲掉手改
- `arch-guard` 已有本仓规则，和模板骨架打架
- 仍在用 OpenSpec 开新 change，对齐会改入口

## 报告格式（复杂对齐时参考，无关章节省略）

```markdown
## 对齐报告 — {{REPO}}

### 1. 现在项目怎么样
- 初始化：是 / 否（依据）
- 栈 / 主目录：
- 已有 OS 文件：
- 已有目录级 AGENTS.md：
- 宪法条款（现行）：C1… 一句话
- 代码/ADR 里已变、文档可能过期的点：

### 2. 拟改动
| ID | 分类 | 文件 | 现在 | 拟改成 | 理由 |
|---|---|---|---|---|---|
| A1 | 新增/更新/建议不动 | path | … | … | … |

### 3. 冲突（必须你选）
| ID | 文件 | 两边分别是什么 | 若选 A | 若选 B |
|---|---|---|---|---|
| C1 | path | … | … | … |

无冲突就写「无」。

### 4. 执行状态
- 已授权且无冲突：列实际修改和验证。
- 仅审查：列建议，不修改。
- 关键冲突：列待决策项与推荐；只暂停受影响部分。
```

报告里每条改动写清路径。不要贴整文件 diff，除非用户要看某一条。

## 执行

用户限定 ID 时只改点名项，否则按已授权目标修改。仍禁止改业务代码。改完列实际路径；涉及护栏时运行 `arch-guard`，无法运行则报告原因，不冒充验证通过。

用户说「先不改」：结束。报告留在对话里，不落盘。
