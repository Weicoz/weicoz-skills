# 微信公众号运营专家样例

这些样例来自原 CodeBuddy 专家 `wechat-official-account-operator` 的定义和少量真实调用，用来校准输出结构。不要把样例中的行业事实当成通用事实。

## 原专家稳定规则

- 先判断账号定位、目标读者、业务目标和当前素材，不足时直接列出缺口。
- 不编造平台规则、行业数据、案例结果或政策口径；涉及最新规则时要求联网核验。
- 优先给可执行产物：选题表、标题组、文章大纲、开头、正文改写、CTA、发布计划、复盘指标。
- 标题兼顾打开率和可信度，避免虚假承诺、夸大收益和低质标题党。
- 默认结构：读者痛点 -> 关键洞察 -> 方法/案例 -> 行动建议 -> CTA。
- 改写文章时保留原事实和业务边界，增强表达、节奏、转场和可读性，不私自添加未给出的事实。
- 做增长建议时区分冷启动、稳定更新、活动转化、私域承接和商业化。

## 样例 1：缺信息输入

输入：

```text
我想做一个公众号，帮我给个运营方案。
```

实际专家输出特征：

- 没有直接给完整方案。
- 先追问账号定位、目标读者、业务目标、当前阶段、内容产能、私域承接、合规限制。
- 每个追问都解释“为什么影响方案”。
- 最后给一个可填写的信息汇总模板。

可复用结构：

```markdown
## 先补这些信息
| 信息 | 要问什么 | 为什么影响方案 |
|---|---|---|

## 信息汇总模板
定位方向：
目标读者：
业务目标：
当前阶段：
更新频率：
内容素材：
私域资源：
外部流量：
行业合规限制：
```

## 样例 2：选题输入

输入：

```text
账号定位：B2B SaaS 创始人增长笔记；目标读者：早期 SaaS 创始人；业务目标：获取咨询线索。请给 10 个公众号选题，每个包含读者痛点、差异化角度、素材需求。
```

实际专家输出特征：

- 选题围绕同一读者的连续痛点，不是散点标题。
- 每个选题包含读者痛点、差异化角度、预期目标、素材需求。
- 会说明选题之间的线索转化逻辑。
- CTA 示例会绑定咨询线索，例如回复关键词领取诊断清单。

可复用结构：

```markdown
## 选题表
| 选题 | 读者痛点 | 差异化角度 | 预期目标 | 素材需求 |
|---|---|---|---|---|

## 选题间的线索转化逻辑
...

## CTA 建议
...
```

## 样例 3：正文改写输入

输入：

```text
很多公司都在做 AI，但是效果不好。老板觉得应该上 AI，员工不知道怎么用，最后变成买了工具没人用。请给 3 个标题和一个可发布开头。
```

实际专家输出特征：

- 给 3 个标题，并标注适用场景。
- 改写开头更有现场感和转折，但没有新增“金额、效率、案例”等未给事实。
- 最后列主要修改点，并明确守住事实边界。

输出摘录：

```markdown
## 可发布开头
现在好像不提 AI 就落伍了。很多公司都在跟风做 AI，但实际效果却差强人意。

最常见的困境是：老板觉得应该抓紧上 AI，不能掉队；但工具引进后，一线员工却不知道怎么用、用在哪里。最后的结果往往是，花了大力气引入的 AI 工具，变成了没人用的摆设。

买了一堆工具，却没能跑通哪怕一个业务场景。企业落地 AI，到底卡在了哪一步？

## 事实边界
- 没有私自添加金额、效率下降、具体公司案例等未给定信息。
```

## 人工验收重点

- 缺信息时有没有停下来追问。
- 标题是否可信，不靠虚假承诺换点击。
- 选题是否能服务业务目标，而不只是“看起来能写”。
- 改写是否保留原事实边界。
- 增长建议是否区分冷启动、稳定更新、私域承接和商业化。

## 通用性覆盖

后续测试不要只用 B2B SaaS。至少覆盖：

- 个人 IP：重点看人格化定位、观点可信度、长期栏目和读者关系。
- 电商 / 本地生活：重点看产品卖点、到店或成交路径、活动节奏和不夸大承诺。
- 企业服务：重点看客户问题、决策链、线索钩子和咨询/销售承接。
- 高合规行业：重点看缺信息追问、资质/审核提示、待联网核验标记，不给确定性合规结论。
