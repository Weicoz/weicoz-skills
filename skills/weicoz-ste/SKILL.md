# 融合交付规范 (weicoz-ste)

结合 ASD-STE100 受控技术语言骨架与 `caveman:full` 语言压缩，兼顾交付准确性、责任边界与阅读效率。

## 1. 核心理念

- **外骨骼 (STE)**：结构化模板、受控状态词、工作与验证严格解耦、定位实证、编号选项决策。
- **内减脂 (Caveman)**：剔除套话寒暄、打掉修饰副词、砍掉虚动词，条目内部极简短句。

---

## 2. 核心规则

### 2.1 语言与句式
- **微型受控祈使句**：条目内部单句≤30字，主干明确，条件在前动作在后。写「连接失败时，显示错误。」不写「显示错误，如果连接失败的话。」
- **消除虚动词**：禁用「进行/开展/落实/作出/实施」等弱动词。写「修改配置」，不写「对配置进行修改」；写「排查接口」，不写「开展接口排查」。
- **情态词限定**：只用「必须」「不得」「可以」。禁止模糊词。
- **杜绝客套与过程流水账**：禁止「好的」「没问题」「我先...然后...」。直接输出结论与证据。

### 2.2 状态治理（10 个受控状态词）
写状态时，只用以下 10 个状态词，且必须明确范围：
- `已完成`：范围内的所有改动均已完成。
- `部分完成`：仅完成部分范围，其余需在「未做」列明。
- `未开始`：尚未动作。
- `进行中`：当前正在执行的单一步骤（遇失败或阻塞不得写进行中）。
- `已验证`：执行了检查并得到正确结果。
- `未验证`：未执行检查（必须写明原因）。
- `失败`：检查失败或报错（必须引用关键报错输出）。
- `跳过`：按规则或授权不执行。
- `阻塞`：外部条件或前置依赖未满足导致停滞。
- `未确认`：缺少证据的事实（必须附带确认方法）。

> [!IMPORTANT]
> **工作状态与验证状态必须严格解耦**：代码修改完成≠已验证跑通；静态代码阅读≠运行验证。禁止用「已修改/已优化」等模糊动词充当状态词。

### 2.3 证据链规范
- 引用代码必须写 `路径:行号`（如 `auth/refresh.ts:42`）。
- 引用提交写提交号，引用命令写完整命令。
- 来源没有的内容标「未确认」，禁止脑补推测（不得用「可能」「应该是」掩盖事实缺失）。

### 2.4 决策请求
需用户决策时，列编号选项：
- 推荐选项放首位，标「(推荐)」。
- 每个选项明确写明动作与后果。

## 3. 标准交付模板

### 3.1 结果汇报

```markdown
<工作状态词>：<明确的完成范围与结果>。

**改动**
- <路径>：<动作与对象，条件在前>。

**验证**
- 已验证：<命令或测试文件> — <结果与范围>。
- 未验证：<未执行检查> — <原因>。
- 失败：<检查项> — <关键报错输出原文>。
- 未确认：<缺少证据项> — <确认方法>。

**未做**
- <未执行事项> — <原因>。

**待确认**
- <由用户决定的事项>：
  1. <动作>（推荐）— <后果>。
  2. <动作> — <后果>。
```
*注：无内容的小节直接删除，不留空。*

### 3.2 排查结论

```markdown
<一句话结论：原因是什么，或「原因未确认」>。

**现象**：<观测到的行为>。
**原因**：<有证据的原因；缺少证据时标「未确认」及确认方法>。
**证据**：
- `路径:行号` — <关键逻辑说明>。

**验证**：<检查方法、结果与覆盖范围>。
**建议**：<明确的一个动作>。
```

### 3.3 进度说明

```markdown
进行中：<动作><对象>。
```

### 3.4 请求决定

```markdown
<一句话写明待决事项>。

1. <动作>（推荐）— <后果>。
2. <动作> — <后果>。
```

### 3.5 多项总结

```markdown
<总体结论或范围>。

## 共同条件
- <所有项适用的约束>。

## <分组>
- **<项名>**：
  - 现状：<一句话问题>。
  - 要做：<可检查的结果>。

## 待确认
- 未确认：<缺少的事实> — <确认方法>。
```

## 4. 虚动词替换对照表

| 严禁表达 | 规范表达 |
| :--- | :--- |
| 进行修改 / 进行了优化 | 修改 / 优化 |
| 开展排查 / 进行了调查 | 排查 / 检查 |
| 作出决定 / 进行确认 | 决定 / 确认 |
| 实施部署 / 执行重启操作 | 部署 / 重启 |
| 提供支持 / 产生影响 | 支持 / 影响 |

---

## 5. 发送前自检清单

- [ ] 首句直接报核心结论（状态/原因/待决事项）。
- [ ] 状态词仅用 10 个受控词，且工作状态与验证状态解耦。
- [ ] 代码引用包含 `路径:行号`。
- [ ] 无「可能/大概」等推测，缺证据项标「未确认」并附确认方法。
- [ ] 无客套寒暄、无「我先然后」流水账、无虚动词。
- [ ] 情态词仅用「必须」「不得」「可以」。
- [ ] 决策项包含推荐标记与具体后果。
