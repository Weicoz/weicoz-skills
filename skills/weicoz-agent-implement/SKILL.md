# 单票委派实现

派单方负责输入、启动、监控和验收；执行方负责该票实现及返修。不要把整份规格当一张票塞进本技能；整规格交给 `weicoz-agent-implement-spec`，单票可以引用规格作为上下文。

## 按当前 implement 建立任务

先完整读取当前环境解析后的 `implement/SKILL.md`，优先从 `~/.agents/skills/implement/` 查找；执行设备上的路径也要核实。找不到时检索该宿主实际技能目录，不能声称已加载。读用户指定的票据，引用不明确才澄清；外部票据先获取并确认标题。

当前 implement 生命周期是：按票实现 → 在约定接缝调用 `tdd` → 过程中跑相关测试及类型检查 → 收尾一次完整套件 → 调用 `code-review` 并修复 → 提交当前分支。原文更新时以现场原文为准；用户指令、项目规则和授权边界优先。没有 Skill 调用工具时，完整读取对应技能文件按其流程执行，不虚报调用。

派单前确定仓库、票据、验收项、允许改动范围、执行工作目录／分支、代理与模型、设备及已有授权。检查工作区和适用 AGENTS；不把他人未提交改动交给会格式化、提交或重置它们的执行方。单票可用干净且无并发写入的当前开发分支；需要隔离时使用独立 worktree，并指定唯一写入者。未提交的规格、样本仅按需复制，注明不得混入实现提交。

## 提示词

首行明确点名 **implement**，使用宿主实际支持的调用语法，例如：

```text
$implement 实现票据 `<票据路径或引用>`。
```

宿主没有确认支持该语法时，首行用可执行的文件读取指令：

```text
使用 implement 技能：先完整读取 `<执行环境中已核实的 implement/SKILL.md 绝对路径>`，实现票据 `<票据路径或引用>`。
```

后面只补仓库无法直接得知的上下文：

- 规格、决策、约定和样本的可访问路径；已核实且值得复用的事实。
- 用户指定的代理、模型、设备、范围与禁止改动目录；不要把用户模型换成宿主默认值。若仅后端，前端验收项明确留待完成，接口、字段和错误码仍按票完成。
- 当前分支／worktree、共享资源归属、检查与正常 hook 的安排、允许的提交行为。项目禁止未授权提交时，原文“提交”不能覆盖该限制；保留可审查改动并报告。不得跳过 hook 或为过关改检查配置。
- 未经授权不 push、发布、部署、调用付费服务或扩展范围。AgentGit 仅在用户要求或当前受管会话启用；不得自行建会话或推记录。
- 回报逐项验收证据、改动文件、检查命令与结果、提交（若有）、审查问题及处理、未做／未验证项。不要把 DONE 或退出码当成功。

## 启动与运行环境

正常委派统一允许任务网络，用于依赖下载和隔离连接测试；旧配置中的 `network_access=false` 不作为禁网限制。保留 workspace 隔离，不为联网改成全盘权限；启动前核对网络及共享重任务队列写权限。用户当次明确要求离线或平台强制限制时遵守；不得改现有代理、TUN 或机器全局安全配置。

保留用户指定的代理和模型；未指定时可默认 Codex，并使用该环境当前配置，不硬编码模型、上下文窗口或推理强度。先看本次宿主工具及 CLI 帮助再选启动方式：原生子代理能满足模型、目录、权限与隔离要求时可直接委派；否则使用实际可用的 CLI。原生代理不能满足明确模型要求时不得静默降级，查可用 CLI；都不支持就说明缺口。

原生子代理 ID 不是 CLI 会话 ID，启动子代理不等于执行过 `codex exec`。CLI 参数、恢复方式以现场帮助为准，不沿用未经验证的跨工具命令。记录实际方式、模型、工作目录、会话／进程／job ID、日志位置；日志与提示词放仓库外临时目录，不带凭据。

默认本机；用户明确指定或已授权远端（包括 M4）时，按 `weicoz-remote-dispatch` 处理同步、资源、续跑和取回。复用已有授权，不因阶段变化再问。远端授权不自动允许 origin push；核对 direct／origin 同步及脚本自动推送行为。用户禁止提交时，派单前确认脚本不会自动 commit／push，不能照抄依赖提交的默认 fetch 流程；用已有且已授权的传输方式取回未提交 diff 和新增文件，核对文件清单与内容完整性，取回前不清理 worktree，不另造同步工具。不要在本技能固化机器地址或最高权限参数。

长任务按宿主后台任务机制运行；需长期 shell／SSH 时遵守 Herdr 规则。启动后尽早核对日志或原生代理事件：票据和 implement 已读取、工作目录正确、确实在执行；只有创建会话不算启动成功。按项目锁文件准备 worktree 必要依赖，不盲目安装所有可选组件。

## 资源、监控与恢复

派单、续跑和新增重任务前，检查实际执行机的 CPU 负载／核数、可用内存与内存压力、swap、工作盘空间及现有重任务；远端不能只查本机。采用当前环境的资源门槛和宿主并发限制，不把会话数当容量，也不把某次机器数值固化为跨平台规则。资源不足时减少并行或延后重检查，不擅自迁机、杀他人进程、删数据或跳过必需检查。

派单方按统一周期复查未完成任务，默认 15 分钟、可以配置，再向用户汇报真实进展、文件／提交／检查、阻塞、下一步及执行机资源；阶段完成或异常及时提醒。远端任务采用 [Remote Dispatch 的发起方统一巡检约定](../weicoz-remote-dispatch/SKILL.md#3-发起方统一巡检与提醒)，不要求执行方定时自述。用户明确指定其他周期或宿主更高优先级沟通频率时按该要求；使用实际后台唤醒能力，不把内部日志或子代理消息当用户已收到报告。

超时先检查进程、日志、工作区与检查状态；支持恢复时在同一会话续跑，带上已有结果和剩余项。不要重复启动仍在跑的任务。确认属于本任务且已无用的残留进程才清理；会话无法恢复时才新建并交接上下文。持续无进展按新证据修复启动条件或更换可用路径，不机械重试。业务／授权阻塞只暂停相关动作，继续独立部分。

## 检查与验收

先读项目检查入口和提交 hook，安排一次正常完整套件：hook 已覆盖时复用其真实结果；hook 仅跑受影响测试时，另安排缺少的完整检查。不得禁用 hook，也不能以“一次”为由跳过修复后必要重检。新 worktree 的依赖与测试缓存可能不同，不能盲目复制选择性测试缓存或假定能命中。

完整检查按实际资源串行／排队；相关测试在开发和返修时按影响运行。派单方核验 diff、日志、测试和审查证据；证据可信且对应当前改动时无需机械重跑，新增修改、失败、冲突或未解风险才补针对性检查，项目明确要求的全套仍执行。

逐条对照验收项，核实 TDD 接缝与代码审查确实执行且发现已处理，检查越界文件、提交内容与实际副作用，能运行的关键路径做必要冒烟。问题交回原会话返修。单票完成不自动允许合并其他分支或关闭外部票据；按已有授权处理，并区分“实现完成”“验收通过”“已提交／已合入”。

单票若创建并使用了独立 worktree，验收交付后同样遵循上述规则：空间充裕时不主动打扰；仅在执行设备可用空间不足时才在汇报中主动提醒，且必须说明删除后果（无法原会话续跑、构建中间物与临时日志清除需重构），经用户明确二次确认不会再使用后方可清理，严禁擅自静默删除。

交付说明验收结果与证据、实际模型／设备／执行方式、剩余项和最小下一步；没有 CLI 或业务端到端实跑就明确未验证。
