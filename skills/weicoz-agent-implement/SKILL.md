# 单票委派实现

派单方负责输入、启动、监控和验收；执行方负责该票实现及返修。不要把整份规格当一张票塞进本技能；整规格交给 `weicoz-agent-implement-spec`，单票可以引用规格作为上下文。

## 按当前 implement 建立任务

先完整读取当前环境解析后的 `implement/SKILL.md`，优先从 `~/.agents/skills/implement/` 查找；执行设备上的路径也要核实。找不到时检索该宿主实际技能目录，不能声称已加载。读用户指定的票据，引用不明确才澄清；外部票据先获取并确认标题。

当前 implement 生命周期是：按票实现 → 在约定接缝调用 `tdd` → 过程中跑相关测试及类型检查 → 调用 `code-review` 并修复 → 按[实现会话检查约定](#实现会话检查约定)正常提交当前分支。原文更新时以现场原文为准；用户指令、项目规则和授权边界优先。没有 Skill 调用工具时，完整读取对应技能文件按其流程执行，不虚报调用。

派单前确定仓库、票据、验收项、允许改动范围、执行工作目录／分支、代理与模型、设备及已有授权。检查工作区和适用 AGENTS；不把他人未提交改动交给会格式化、提交或重置它们的执行方。单票可用干净且无并发写入的当前开发分支；需要隔离时使用独立 worktree，并指定唯一写入者。未提交的规格、样本仅按需复制，注明不得混入实现提交。

## 提示词

本机提示词以 [ticket-prompt.md](templates/ticket-prompt.md) 为固定模板，用 `scripts/render-prompt.py` 渲染；用 `--help` 查询参数。填写票据、各仓工作目录与本票分支、上下文指针、检查分工和专属约定；`IMPLEMENT_SKILL` 指向本技能的可访问 `SKILL.md`。有差异的技能入口写入 `EXTRA`，启动前核实全部指针可访问。完成判据：渲染成功且每项验收均能定位到票据或上下文。

可变部分只补仓库无法直接得知的上下文：

- 规格、决策、约定和样本的可访问路径；已核实且值得复用的事实。
- 用户沟通层（页面与交互设计、信息呈现、面向用户的文案措辞）默认由派单方／编排层负责；委派给实现会话的只是背后的逻辑与不涉及展示的接线，提示词里写明界面与文案留待派单方，实现会话可先建文案键与占位文字并在回报中列出。
- 用户指定的代理、模型、设备、范围与禁止改动目录；不要把用户模型换成宿主默认值。若仅后端，前端验收项明确留待完成，接口、字段和错误码仍按票完成。
- 当前分支／worktree、共享资源归属、允许的提交行为；保留模板中的[实现会话检查约定](#实现会话检查约定)指针。项目禁止未授权提交时，保留可审查改动并报告。正常执行 hook，保留项目检查配置。
- 未经授权不 push、发布、部署、调用付费服务或扩展范围。AgentGit 仅在用户要求或当前受管会话启用；不得自行建会话或推记录。
- 固定流程、Git 约定与回报格式由模板维护；非本机方式也保留这些约定。验收以证据为准。

## 启动与运行环境

本机 Codex 使用本技能三个脚本：`prepare-worktrees.sh` 建票据分支与 worktree、按锁文件准备依赖；`render-prompt.py` 渲染固定模板；`launch-local.sh` 做负载准入并启动会话。参数与默认值以各脚本 `--help` 为准。最短调用示例（仓库、路径和基线变量由编排方填写）：

```bash
skill="$HOME/.agents/skills/weicoz-agent-implement"
bash "$skill/scripts/prepare-worktrees.sh" --branch ticket/T01 --base "$base" \
  --ticket T01 --repo "app=$repo" --log-dir "$out"
python3 "$skill/scripts/render-prompt.py" --template "$skill/templates/ticket-prompt.md" \
  --set TICKET=T01 --set "WORKDIRS=app=$repo/.worktrees/T01；分支 ticket/T01" \
  --set "CONTEXT=$ticket_file" --set "IMPLEMENT_SKILL=$skill/SKILL.md" \
  --set-file "EXTRA=$extra_file" --set-file "CHECKS=$checks_file" --out "$out/prompt-T01.md"
bash "$skill/scripts/launch-local.sh" --name T01 --prompt "$out/prompt-T01.md" \
  --workdir "$repo/.worktrees/T01" --out "$out"
```

worktree 统一放在各仓库根目录的 `.worktrees/<票名>`：所有工具按同一位置查找，`du -sh <仓库>/.worktrees` 即可统计占用。脚本在该目录未被忽略时写入仓库的 `.git/info/exclude`；仓库自身的测试、lint、类型检查和镜像构建配置也须排除 `.worktrees/`。在主仓库清理时只用不带 `-x` 的 `git clean`，因为 `-x` 会删除被忽略的整个 `.worktrees/`。跨仓票在每个仓库用同一票名。`--root` 仅在项目另有约定时使用。多仓准备重复传 `--repo`；启动时用 `--add-dir` 传入其他本票 worktree 和必要的上下文目录。脚本按运行中 `codex exec` 的不同工作目录计数，达到 `--max-sessions`（默认读 `WEICOZ_MAX_LOCAL_SESSIONS`，再缺省 2）时等待。保留 `workspace-write` 隔离，默认开启任务网络；明确要求离线时传 `--offline`。正常联网仅用于任务依赖与隔离连接测试，保留现有代理、TUN 和机器全局安全配置。模型等 Codex 参数放在 `--` 后，按用户要求传入；附加参数不得覆盖已约定的目录、沙箱、联网和结果路径。

Git 分工（本机）：worktree 的 Git 目录在主仓库 `.git/worktrees/` 下，不在沙箱可写根内，实现会话 `git add` 报 `index.lock: Operation not permitted`；追加 `--add-dir <git 公共目录>` 实测时好时坏（2026-10-21），不作依赖。实现会话只改工作区；编排方审查后在本票分支提交，需要时先合入 integration 最新提交并按影响重检，再串行合入 integration。远端 rd 会话按 rd 流程在执行机提交。完成判据：本票提交由编排方生成，验收证据对应该提交。

保留用户指定的代理和模型；未指定时可默认 Codex，并使用该环境当前配置，不硬编码模型、上下文窗口或推理强度。先看本次宿主工具及 CLI 帮助再选启动方式：原生子代理能满足模型、目录、权限与隔离要求时可直接委派；否则使用实际可用的 CLI。原生代理不能满足明确模型要求时不得静默降级，查可用 CLI；都不支持就说明缺口。

原生子代理 ID 不是 CLI 会话 ID，启动子代理不等于执行过 `codex exec`。CLI 参数、恢复方式以现场帮助为准，不沿用未经验证的跨工具命令。记录实际方式、模型、工作目录、会话／进程／job ID、日志位置；日志与提示词放仓库外临时目录，不带凭据。

默认本机；用户明确指定或已授权远端（包括 M4）时，按 `weicoz-remote-dispatch` 处理同步、资源、续跑和取回。复用已有授权，不因阶段变化再问。远端授权不自动允许 origin push；核对 direct／origin 同步及脚本自动推送行为。用户禁止提交时，派单前确认脚本不会自动 commit／push，不能照抄依赖提交的默认 fetch 流程；用已有且已授权的传输方式取回未提交 diff 和新增文件，核对文件清单与内容完整性，取回前不清理 worktree，不另造同步工具。不要在本技能固化机器地址或最高权限参数。

用宿主后台任务机制运行启动脚本；脚本自身等待 Codex 结束，完成通知即收尾信号，随后读取结果与日志验收。需长期 shell／SSH 时遵守 Herdr 规则。启动脚本在日志出现 session id 后打印工作目录、模型、沙箱和会话 ID；300秒未出现则报错退出。核对日志中的票据和 implement 已读取、目录正确且确实在执行，才计为启动成功。依赖准备以安装日志与各仓结果为准；失败项修复后再派单。

## 资源、监控与恢复

派单、续跑和新增重任务前，检查实际执行机的 CPU 负载／核数、可用内存与内存压力、swap、工作盘空间及现有重任务；远端不能只查本机。采用当前环境的资源门槛和宿主并发限制，不把会话数当容量，也不把某次机器数值固化为跨平台规则。资源不足时减少并行或延后重检查，不擅自迁机、杀他人进程、删数据或跳过必需检查。

本机负载采样、核数、每核换算和准入等待由 `launch-local.sh` 处理；阈值优先命令行，其次 `RD_MAX_LOAD_PER_CORE`，默认值见脚本帮助。向用户汇报时引用采样行（1 分钟负载 ÷ 核数 = 每核负载，阈值），附结论并用一句话说明含义：每核小于 1 有空闲，等于 1 刚好用满，大于 1 有进程排队等 CPU；负载偏高时查占用最高的进程。负载包含部分 I/O 等待，不等同于 CPU 利用率。脚本判断负载与工作盘可用空间（下限 `WEICOZ_MIN_FREE_GB`，默认 10 GiB；`prepare-worktrees.sh` 不足即拒绝），内存与 swap 仍由派单方核对。worktree 占用看可用空间差，不看 `du`：pnpm 在 APFS 上克隆依赖，`du` 会把共享块按每个 worktree 重复计数；`--no-wait-load` 仅在编排方已完成准入判断时使用。Windows 使用 CPU 采样利用率，按该指标和阈值汇报。

巡检必须有具体载体，不得只靠「下次想起再查」。开工先记录本宿主的两项能力：任务完成通知、定时唤醒（后台作业或等价机制）。

- **有定时唤醒能力时**：派单后立即把一次 `rd watch <job>` 放进后台作业。它默认 900 秒返回一次，退出码 0＝完成、1＝告警、2＝该报进度（可用 `--timeout` 或 `RD_REPORT_INTERVAL_SECONDS` 调整周期）。退出码 2 时读 `rd status --details` 与 `rd logs` 尾部，向用户报一行真实进展（阶段、文件数、提交、阻塞、执行机资源），然后重新挂下一次 `rd watch`；0／1 时取回结果并进入验收。任务结束后终结对应巡检作业，避免重复监控。
- **只有完成通知、没有定时唤醒时**：用后台作业承载完成通知，并另挂一个「超时兜底」作业（如 `sleep <周期>` 后查一次 `rd status`，无进展则打印状态并以非零退出），让卡死也能触发一次唤醒。启动时如实说明「卡死只能靠兜底周期发现」这一边界。
- **两者都没有时**：在派单回报里写明无法定时巡检，只能靠用户发起或下一次操作时检查；不得声称已按周期监控。

无通知且超过周期时，查日志与进程后向用户汇报真实进展、文件／提交／检查、阻塞、下一步及执行机资源。阶段完成或异常及时提醒。远端任务同时采用 [Remote Dispatch 的发起方统一巡检约定](../weicoz-remote-dispatch/SKILL.md#派单流程)。用户指定的周期及宿主更高优先级沟通频率优先；用户汇报由派单方负责。

超时先检查进程、日志、工作区与检查状态；支持恢复时在同一会话续跑，带上已有结果和剩余项。续跑前用 `<CLI> exec resume --help` 核对参数（Codex 的 `resume` 不接受 `-s`，沙箱改用 `-c sandbox_mode="..."`）；续跑后读日志开头，确认会话 ID、模型和沙箱与原会话一致，再计为已续跑。不要重复启动仍在跑的任务。确认属于本任务且已无用的残留进程才清理；会话无法恢复时才新建并交接上下文。持续无进展按新证据修复启动条件或更换可用路径，不机械重试。业务／授权阻塞只暂停相关动作，继续独立部分。

远端模型故障先读 `rd result <job> --summary`；同类且无工作迹象的故障遵守现有续跑预算，纯上下文故障才显式接替会话。模型不可用时继续已授权的独立收尾，不改全局代理或凭据来绕过故障。

## 检查与验收

### 审查阻塞判定

每条审查发现附需求、文件位置、可达调用链或失败证据及用户影响。分清产品错误、测试接缝、宿主／网络条件和可选改进；只有影响验收、正确性或明确安全边界的发现阻塞合入。诊断可以依靠源码和日志，不要求一律先本地复现。生命周期／并发意见先沿实际调用方核对隔离、代际和终止顺序；不可达分支的防御性建议单列，不能当作已存在缺陷。扩大验收说明本次影响与现有证据缺口，复用仍对应当前输入的结果。机械检查交给现有工具，不向每张实施票复制审查规则。

### 实现会话检查约定

派单前读取项目检查入口和提交 hook。每个实现／返修会话通过模板指针读取本节；整规格编排共用此处规则：

> 开发与返修按影响运行相关测试和类型检查；完整测试仅由正常提交钩子执行一次，复用其结果作为本次提交的完整测试证据。会话内的手动检查保持针对性。检查默认串行；确需并发时采用小并发（最多 2 个，并服从执行机资源和项目更低上限）。保留正常 hook；失败后修复相关问题，再正常提交，报告钩子的实际执行次数、命令与结果。钩子未覆盖完整套件或本轮未获提交授权时，报告覆盖缺口，交由派单方统一安排验收。

需要监听端口、依赖外部服务或真实设备的检查，实现会话在回报中单列「需编排方／端到端执行」，不计为本票失败；相关功能仍保留未验证边界。编排方执行这些检查时，记录临时进程 PID 或监听端口，结束后核实归属并回收本次进程，确认已退出。

新 worktree 的依赖和选择性测试缓存须实际核实。若 hook 依赖覆盖记录或上次结果（如 pytest-testmon），派单前在执行机保留最近通过的选择记录，开工改代码前复制到 worktree（不提交）；同一锁文件与运行环境下先实测有效性，回报 hook 是否退回全量。每合入一票，用该 worktree 的有效记录刷新缓存。缓存失效时向派单方报告，由其调整后续排队和验收安排。

远端任务由派单方在本机读取 diff、核对验收项；需要补检时经 `weicoz-remote-dispatch` 派回执行机，合并冲突交回原会话解决。派单方复用对应当前改动的可信日志、检查与审查证据；新增修改、失败、冲突或未解风险按影响补检，项目要求的整体检查由派单方统一安排。

逐条对照验收项，核实 TDD 接缝与代码审查确实执行且发现已处理，检查越界文件、提交内容与实际副作用，能运行的关键路径做必要冒烟。问题交回原会话返修。单票完成不自动允许合并其他分支或关闭外部票据；按已有授权处理，并区分“实现完成”“验收通过”“已提交／已合入”。

单票创建独立 worktree 时，验收交付后处理 worktree、或设备空间不足时，先读 [Worktree 清理与用户二次确认规范](../weicoz-agent-implement-spec/references/worktree-cleanup.md)，按其中安全条件、归属与二次确认要求处理。

已授权的自有中间缓存按[缓存保留与回收](../weicoz-remote-dispatch/references/cache-retention.md)运行工具并留回执；这不包含删除工作树、job、当前产品、依赖或备份。

交付说明验收结果与证据、实际模型／设备／执行方式、剩余项和最小下一步；没有 CLI 或业务端到端实跑就明确未验证。
