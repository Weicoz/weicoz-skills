# 维护者备注

不属于使用说明（使用看 [SKILL.md](SKILL.md)）。这里只放**口径与实现细节**；
真实人员、比例、金额不写进来，只活在 `~/.config/weicoz-feishu-receipt-base/config.yaml`。

## 绩效口径三条

1. **按「实收」计提，不按「到账」**
   实收 = 当月到账 − 该笔要付出去的返点/转款。客户分期时跟着到账那笔走，
   按流水变动月份归月，不预提、不摊销。

2. **扣减用「应付全额」（已付 + 还欠），不是「当月实付」**
   写成只算当月实付，公司级行的扣减会小于项目行合计，两行对不上，看起来像算错。

3. **公司级分成基数 = 全公司当月实收**（= 各项目当月实收之和）
   每次核完对一笔：`Σ各项目当月实收` == 公司级行的当月实收。

## 公式上的两个坑

1. 飞书公式**做不到同表跨行聚合**。公司级行的未付部分只能取
   `SUM(项目收款表.[待返渠道款]) + SUM(待转莞云/其他)` 近似，不能引用其它行。
2. 公司级行的「当月到账」必须限定为**有关联项目**的入账
   （`NOT(ISBLANK(CurrentValue.[项目收款表]))`），否则没归类的零钱会混进基数。

## 护栏

- `lark_snapshot.py --performance`：快照额外带上项目开发分配表。
- `performance_guard.py <SNAPSHOT> --month YYYY-MM`：权重合计、实收/绩效非负、绩效公式一致、
  公司级与项目合计一致、到账项目缺行、停用行留旧数，逐项拦截；`ok: true` 直接给按人合计。
- `lark_snapshot.py --print-tables`：只打印配置里的三张表 ID，避免手打表 ID。
- `--dry-run` 不校验 Base/表/字段/选项存在，只预览请求体。

## 已知边界（改公式前先看）

- `返点及转款扣减` 的公司级分支按**全表累计待返/待转**扣：欠款跨月未付时，每月只要有到账就会再扣一次。
  目前只有「已付超应付按 0」的保护。
  实证：9 月 426,200 −（96,000 + 68,200）= 262,000 恰好对得上；10 月 37,900 −（3,000 + 68,200）= **−33,300**。
  只要当月到账小于累计欠款就会翻负。正确口径是「只在首次到账扣」，公司级基数取 `Σ各项目当月实收`。
  要改公式先单独授权，并接受历史月份重算。
- 不计绩效的标准项目用 `绩效比例(%)=0` + 备注写原因，不删行。
- 项目收款表里混用过「业务」与「开发人员」两套人名，核算前先确认是哪一列。

- 「项目开发分配」的历史人员选项保留，历史行仍在引用；离职者不再新增分配行，也不参与新月份核算。人员状态以私有资料核对，不缓存到公开 Skill。

## 员工环境

没有配置文件的机器上：不猜 token、不翻别处、不凭记忆写死；告诉使用者先照
`config.example.yaml` 建配置；只跑标准流程，不做任何分成计算。
