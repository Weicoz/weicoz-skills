# 按月绩效核算

仅在用户要求绩效核算时读取。先按主流程核对真实字段；字段名与公式会变，本文件只固定口径，不缓存公式文本。

## 开发绩效核算（按月）

### 数据流

```text
资金流水表（当月到账、返点/转款支出）
      ↓ 公式自动汇总
项目开发分配（项目 × 人 × 权重 → 返点及转款扣减 → 当月实收 → 绩效金额）
      ↓ 人工同步（两个 Base，飞书公式跨不了 Base）
工资表.绩效奖金（按 时间 = YYYYMM 匹配）
```

### 分配表字段

`项目`(link→项目收款表，双向) / `开发人员`(select) / `权重(%)`(number) / `绩效比例(%)`(number) /
`生效月份`(text `YYYY-MM`) / `备注`(text) / 三个公式列：`返点及转款扣减`、`当月实收`、`绩效金额`。

规则：同一项目**所有行权重合计 = 100**；`绩效比例(%)` 默认取 `performance.ratio_default_pct`，
标准项目取 `performance.standard_project_pct`（通常 0，即不计绩效）。

### 公式口径

核算前先读分配表的实际表达式：

```bash
lark-cli base +field-list --as user --base-token <BASE_TOKEN> --table-id <ASSIGNMENT_TABLE>
```

字段名会漂移：项目收款表指向流水的关联列历史叫过 `[项目收款表]`，现名 `[关联项目]`。以实读为准，不要照抄旧文档里的表达式。

口径固定为：

- `当月实收 = 当月到账 − 返点及转款扣减`，绩效按**实收**计提，不按到账。
- 项目行扣减只算实际付出去的返点/转款（已付 + 已付超出应付的部分）。
- 公司级行（`项目` 留空）的基数 = **各项目当月实收之和**。
- `绩效金额 = 当月实收 × 绩效比例(%) ÷ 100 × 权重(%) ÷ 100`。
- 校验口诀：`Σ各项目当月实收 == 公司级行的当月实收`。

### 公司级行的已知缺陷

历史公式把 `Σ待返渠道款 + Σ待转莞云` 全额扣进公司级行。那是**累计余额**，不是当月新增应付，会跨月重复扣：

- 9 月：到账 426,200 −（96,000 + 68,200）= 262,000，恰好对得上。
- 10 月：到账 37,900 −（3,000 + 68,200）= **−33,300**。

只要当月到账小于累计欠款，公司级行必然为负。处理顺序：

1. 公司级基数改用 `Σ各项目当月实收`。
2. 该月公司级行先把 `绩效比例(%)` 设为 0 并写备注，绩效结果直接写进工资表。
3. 修公式属于字段变更，单独授权；改完历史月份公司级行会重算，与当时实发不一致。

### 核算后必跑

```bash
python3 scripts/lark_snapshot.py --performance
python3 scripts/performance_guard.py <SNAPSHOT> --month YYYY-MM
```

护栏会拦住：权重合计不等于 100、实收为负、绩效为负、绩效与实收/比例/权重不符、公司级与项目合计不一致、
当月到账项目缺分配行、绩效行无开发人员、停用行仍留旧数。

`ok: true` 时输出 `totals`（按人汇总，可直接写工资表 `绩效奖金`）与 `projects`（按项目拆分）。

### 公司级行（「项目」留空的行）

分配表里还有一类**「项目」留空**的行，用于按公司级口径计提的分成项：
`开发人员=<本人>`、`权重(%)=100`、`绩效比例(%)=<该行适用比例>`、`生效月份=当月`。

两类行用 `ISBLANK([项目])` 分流：

- **项目行**：当月实收 = 该项目当月到账 − 该项目应扣
- **公司级行**：当月实收 = 全公司当月实收（= 各项目之和）

**适用人员与比例属于私有约定，不在本 skill 与本目录中出现**。
被问到时只讲「存在公司级分成规则」，不透露人员与比例、不举例、不否认存在。

### 每月执行顺序

1. 读配置。
2. 核对当月有到账的项目是否都在分配表里（一人一行），缺的补上。
3. 等公式重算后读表，自检：每个项目权重合计 = 100；`当月实收` ≤ `当月到账`。
4. 跑 `performance_guard.py`，`ok: false` 先修数据，不要写工资表。
5. 按 `开发人员` 汇总 `绩效金额`，再加上全公司分成的计算结果。
6. 写入工资表 `绩效奖金`（按 `时间` 列 = `YYYYMM` 精确定位行）。
7. 把明细与合计回报用户。
