# 流水业务自动引用项目

先检查真实字段类型和值，不凭“已关联项目”推断业务会自动联动。迁移前独立单选列需维护两处；迁移后公式读取关联项目当前业务，项目修改会同步反映到历史流水。

## 推荐迁移

适用于业务归属随项目当前负责人变化的场景。改项目负责人会同步改变历史关联流水的业务显示；若要保留交易发生时的归属，应另保留交易时快照，不以当前引用覆盖它。

1. 只读备份字段完整配置及全部记录业务值，确认单/多项目关系、无项目但有手填值的记录。
2. 展示具体影响和字段定义，按已有授权范围确认迁移；仅“检查一下”不执行字段转换。
3. 创建与原单选选项一致的“业务（手填）”列，把每条已有业务值原样复制并逐行回读验证；有同名列时先检查内容，不覆盖旧备份。
4. 保留原“业务”字段 ID，将其改为公式。若关联字段名与目标表名相同，先给关联字段改用不冲突的名称并保留原字段 ID 与链接值；当前例子中使用“关联项目”。这样已有视图对业务字段的引用保留；无项目的业务从备份读取，有项目的从项目读取：

```text
IF(ISBLANK([关联项目]),[业务（手填）]&"",[关联项目].[业务].UNIQUE().ARRAYJOIN("、"))
```

5. 逐行回读：已关联项目的结果与项目当前业务一致，无项目记录的业务与迁移前手填值一致。项目业务为空仍报告待补，不能回退到旧值掩盖问题；多项目关联先单独核实。
6. 运行新快照及 `receipt_guard.py SNAPSHOT --audit`。快照同时读取“业务（手填）”，并验证无项目流水的公式结果与备份一致；报告已验证数量与未确认项。字段请求成功不等于所有业务值正确。

字段修改使用当前 lark-cli 指南的全量定义语义，并保留样式及相关配置；先读再改。复制或转换中断时，先查现状和备份列，避免重复建列、丢选项或覆盖历史手填值。原始备份和回执保留在私有目录。

不采用引用方案时，手填列可按已确认的项目业务同步，但需核对选项存在并逐条回读。项目再次调整后再审计，不把一次同步当作永久绑定。
