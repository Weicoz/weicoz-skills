# 飞书收款入账与核算

收款流程：凭证 → 项目及分账证据 → 校验计划 → 用户确认 → 批量写入 → 回读。
下文 `$SKILL_DIR` 指本次读取的 `SKILL.md` 的真实父目录；解析软链，脚本从这个目录取，不从 generated 桩路径推测。

## 1. 配置与只读快照

先用 `which lark-cli`、`lark-cli auth status` 检查工具和身份。身份失效由用户认证；自动 refresh 可按 CLI 正常流程完成。

私有配置优先 `$WEICOZ_RECEIPT_CONFIG`，否则 `~/.config/weicoz-feishu-receipt-base/config.yaml`。配置结构见 [config.example.yaml](config.example.yaml)。
配置不存在时，告知用户从模板创建、权限设为 600；不复制示例人员与比例、不猜 token 或从别处翻找。

```bash
python3 "$SKILL_DIR/scripts/lark_snapshot.py"
```

脚本在内存读取 YAML，仅顺序读取项目表和资金流水表，逐页核对记录 ID 与字段列序；只读限流最多重试两次。产物保存在配置旁的私有 `reports/`，只回显文件路径和条数，不输出配置或财务正文。读取 YAML 复用已安装的 PyYAML；缺依赖时按本机约定补装，不在仓库写凭据。

首次快照作为计划的 `schema_before`；每批写入前重新取快照作为 `schema_current`。字段 ID、名称、类型或公式变化时重新生成计划。ID 相同不代表含义相同；旧“应付全额”列不能直接映射成新“已付”列。

## 2. 收集本次凭证与证据

- 银行短信、PDF、图片逐笔提取付款方、实际交易时间及其时区、金额、账户尾号、用途和来源页码/消息 ID；余额不计入收入。
- PDF 多笔流水先核收入列与支出列、相邻余额；腾讯验证款等只按用户指定的来源键排除，不把某家公司所有来款自动忽略。
- 项目按付款方、合同、备注和聊天上下文匹配。公司名相同但项目不唯一时，先只记未关联流水，不累加到猜测项目。
- 把本次到账、合同总额、累计已收分别记录。用户说“全款”等表述与凭证金额不一致时，核实另笔款是否到账；未知日期不补成当前日期。
- 需要微信证据时执行下一节；只凭银行/用户已明确确认的内容也可完成独立部分，不让图片问题阻塞所有入账。

### 微信文字与图片

先读取 `wx-cli` Skill。收款脚本按真实目录查找其 `scripts/wx.sh`：优先发现入口，再回退到 skill-tiers/library；可用 `--wx-skill-dir` 指定实际目录。

```bash
python3 "$SKILL_DIR/scripts/wx_preflight.py" check --chat '<会话>' --since YYYY-MM-DD --until YYYY-MM-DD
```

后续 wx 查询使用预检返回的真实 `wrapper`，不用旧文档的固定脚本路径。分别报告读取服务、文字、图片状态。先核 daemon，服务未确认运行时不让查询自动拉起后台进程；按现有 Herdr 管理方式恢复读取服务。预检只解密一个时间窗样本；同类密钥错误首次出现即停止该批图片，不逐张重复失败，不自动取钥、重签名、重启微信或扩大权限。

`images=no_sample` 代表没有验证样本，不能报图片可读；`text=ok` 也不证明图片可读。预检通过后，用 `attachments` 的不透明 ID 取图并实际查看，结合同一消息的会话、发送者、时间和相邻文字判断。文件传输时间、银行录入/发送时间与实际到账时间分别保留，不能相互冒充。

微信查询原始 JSON 留在本机私有目录；进入模型上下文前过滤：

```bash
python3 "$SKILL_DIR/scripts/wx_preflight.py" messages PRIVATE_QUERY.json --keyword '<项目关键词>'
```

只输出财务相关文字和图片消息元数据，省略含凭据的 XML、口令、验证码，隐藏手机号、长账号与链接。原图留本机，图片占位符不当作已验证凭证。

## 3. 金额与字段口径

先核实当前列名及含义。本校验器支持以下已付/待付分列结构；遇到旧结构先核对，不能只改名字或把全额当已付。

| 字段 | 含义 |
|---|---|
| 已收款项 | 累计真实到账 |
| 已返点渠道 | 已实际返给介绍业务渠道的金额 |
| 待返渠道款 | 已确认应返、尚未支付的余额 |
| 已转款莞云/其他 | 已转给莞云或其他代收/分账主体的金额 |
| 待转莞云/其他 | 应转但尚未支付的余额 |

实收 = 已收 − 已返渠道 − 待返渠道 − 已转其他 − 待转其他。
支付一笔返点时，相同金额从待付转到已付，并登记真实支出，实收不变；不得把同笔款同时重复扣除。
渠道返点与转款莞云/其他分别维护；供应商技术结算属于流水“结算款”，不混入渠道返点。当前小型校验器只覆盖收款及两类返点，其他业务走各自流程。

合同总额必须有合同或用户确认来源，不能默认等于到账。总额未知时，先记未关联资金流水、项目金额待补；若用户要求先建项目，先核待收公式有空值保护，缺保护时展示具体公式并按已有授权范围处理。待收显示负到账额不算通过。

历史空的返点/待付值代表未确认，不能默认为已结清。计划中的已收、已付、待付必须是确认的数字；已明确不欠才填 0。未付备注写明对象和余额，缺收款主体则写“主体待补”，不把业务联系人自动当收款人。

## 4. 生成并校验计划

用户调整过项目后，重新只读取快照并检查业务归属，不能沿用先前核验结果：

```bash
python3 "$SKILL_DIR/scripts/receipt_guard.py" PRIVATE_SNAPSHOT.json --audit
```

资金流水业务以关联项目当前“业务”为准，不从聊天对接人或旧备注猜。项目负责人为空、流水漏填/错填、指向多个项目都要报告；没有关联项目的历史手填业务保存在“业务（手填）”，审计需确认公式结果与备份一致。金额相符不代表业务归属相符。

流水“业务”为公式时，快照同时读取“业务（手填）”，并校验公式、备份字段类型、关联项目负责人及无项目回退值。公式引用字段必须与目标表同名时先消除命名冲突；当前流水项目关联列为“关联项目”。若流水业务仍是手填单选，检查不会自动联动；可按 [自动引用方案](references/business-binding.md) 展示具体迁移影响，经授权后转为引用项目的公式。字段类型变化不属于只读检查的隐含授权。

输入及来源格式见 [计划格式与校验](references/plan-format.md)。只把本次会改的项目放进计划，`existing_flows` 包含这些项目的完整可读历史流水。历史已付金额与流水不一致时单独核查，不重写旧账凑一致。

```bash
python3 "$SKILL_DIR/scripts/receipt_guard.py" PRIVATE_PLAN.json
```

必须通过：金额精确到分、收入合计等于本次凭证合计、来源排除与重复检查、已付与关联支出一致、累计已收加本次到账一致、待收空值保护、实收扣全额、两次字段快照一致、流水业务与项目业务一致。写后回读也检查人员，不能只核金额和项目 ID。
校验错误只输出分类，不输出正文。检查通过不代替用户确认，也不代表真实写入成功。

向用户展示收入、项目归属、两类应付/已付/待付、准备修改的字段及尚缺内容。已明确确认的动作直接继续，不重复征求同一范围授权；总额、分账对象或实际到账存在关键歧义时集中询问，独立部分继续。

## 5. 写入、回读与恢复

按 [批量写入与回读](references/lark-write.md) 用现有 lark-cli 写入，不自建自动重试写 API。普通收款不用加载绩效规则或修改工资表。

- 写前备份目标记录和计划，做 CLI dry-run 预览；dry-run 不证明字段、选项、记录存在。
- 新项目 ID 从实际响应取得，关联同一计划内的资金流水；未确认项目留空，不猜 ID。
- 写失败或超时先查状态，保留已创建 ID，只续办未完成部分，不重放整批创建。
- 写后重新取快照，将创建响应 ID 加入计划 `id_map`，校验实值与关联：

```bash
python3 "$SKILL_DIR/scripts/receipt_guard.py" PRIVATE_PLAN.json --after PRIVATE_AFTER_SNAPSHOT.json
```

回报创建/更新的表、记录 ID、金额和明确待补项。回读不符标未验证；未知金额、未读图片与认证阻塞分别报告。只清理本次临时请求文件，保留原件、备份和回执。

## 按需：绩效核算

用户要求按月核开发绩效时，读取 [绩效规则与公式](references/performance.md) 和 [维护者说明](README.md)。适用比例、人员及挂账从私有配置或实际表读取，工资表写入以本次授权为准。

## 保密与维护

配置、真实财务正文、聊天、图片、密钥、人员分成约定和回执留本机私有目录，权限目录 700/文件 600，不进 Wiki、普通索引或 Git。`private/`、`.gitignore` 仅提供索引/Git 隔离，不代表权限隔离或加密。
开源脚本、测试和示例只用虚构数据；配置不完整时返回可处理错误，不回显原始响应。破坏性删表、改字段类型、覆盖历史数据不属于普通入账授权。

维护后运行 `python3 -m unittest discover -s "$SKILL_DIR/scripts" -p 'test_*.py'`；本仓库 pre-commit 会在本 Skill 或检查入口变更时运行同一组用例。
