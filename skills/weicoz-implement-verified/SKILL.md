# 带验证闭环的实现

在 Matt 的 `implement` 外面加一层：前面锁纪律，后面接验证。Matt 原文不改，这里只写增量和覆盖项。

## 0. 准备

1. 读项目 `AGENTS.md` 的 `## 验证约定`。没有这一节时，按 `weicoz-verify` 第 1 节补写，再继续。
2. 读票据或规格。票据没有“完成判据”时，先在票据末尾补下面这段，再动手：

```markdown
## 完成判据（逐条回报“通过/失败 + 关键输出”）
1. 快检：`<验证约定里的快检命令>`，最后一行“结论：通过”。
2. <本票特有的断言：哪个流程、哪条性质、与什么比对>
3. <要看的截图或输出，及要看什么>
```

第 2 条按 `weicoz-verify` 的 `references/oracles.md` 选类型，写成可执行的检查，不写“功能正常”这类无法验证的话。需要新写端到端流程时，按 `weicoz-verify` 的 `references/e2e-authoring.md` 写，并先于实现写好。

## 1. 执行 Matt implement

单票读 `implement`，整份规格读 `implement-spec`。先按宿主常规方式调用；调用被拒（Matt 的这两个 skill 只允许用户手动调用）或找不到时，依次找 `~/.agents/skill-tiers/library/<名>/SKILL.md`、`~/.agents/skills/<名>/SKILL.md`，读第一个存在的，然后照原文执行。本文引用的其他 skill 同样按这个顺序找。

执行时叠加下面的覆盖项；与原文冲突时以本节为准：

| 原文 | 覆盖为 |
| --- | --- |
| 定期跑类型检查和单个测试文件，最后跑一次全量 | 红绿循环中每步跑相关单个测试（照 `tdd` 原样）；每轮写完跑快检；全检留到第 3 步（`weicoz-verify` 第 3 节） |
| 调用 `code-review` 审查 | 改用 `weicoz-code-review <基础分支> --repo <worktree 绝对路径>`，见第 2 步 |
| 调用 `tdd` | 改产品行为时照原文；只修测试本身（如 mock 漂移）时不需要 |
| 提交到当前分支 | 移到第 3 步全检通过之后；提交约定按项目 `AGENTS.md`，项目没写时照原文 |

另外遵守：

- 测试失败的处理按 `weicoz-verify` 第 4 节（修复上限与停止条件都以它为准），不得删测、跳测或放宽断言。
- 缺陷修复票：先写能复现缺陷的失败测试，确认它失败，再修。红绿细则照 `tdd`。
- 读项目 `AGENTS.md` “验证约定”里的高风险目录与禁改目录。改动触及高风险目录，在第 2 步审查时说明；触及禁改目录，停下报告。
- 需要改动票据“可写范围”以外的文件，或发现代码与票据描述严重不符时，停下报告。

## 2. 审查（提交前，对未提交改动）

顺序：一轮写完 → 快检通过 → 审查 → 全检 → 提交。

1. 调用 `weicoz-code-review <基础分支> --repo <worktree 绝对路径>`。它会 fork 到发起会话的目录运行，不传 `--repo` 就会审错仓库或报“ref 无法解析”。
2. 调用被拒或当前环境不能调用 skill 时，读它的 `SKILL.md`，在 worktree 里自己照做；规范文件按 `git show <基础分支>:<路径>` 读。
3. 审查返回“无可审查改动”，视为审查未执行，不得记为通过。检查 `<基础分支>` 与 `--repo` 参数后重跑。
4. 阻塞问题修完后，重跑快检；全检在第 3 步重跑。

## 3. 验证

1. 收尾一律跑验证约定里的**全检**。项目没定义全检时，报“未验证（缺：全检）”，不得说可合并。
2. 结论为“不通过”：按 `weicoz-verify` 第 4 节修复。
3. 结论为“未验证”：写清缺什么、需要谁做什么，不得写成通过。
4. 按 `weicoz-verify` 第 5 节标验证状态，按第 10 节格式汇报。

由子代理执行时，主会话验收必须自己重跑同一条命令，看结论行；子代理自述不算通过。

## 整份规格（implement-spec）

- 每张票的子代理回报快检结论行原文；主会话不凭自述放行。
- 全部票合入集成分支后，在集成分支跑全检。
- 审查：`weicoz-code-review <基础分支> --repo <集成分支所在 worktree 绝对路径>`，指向集成分支。
- code-review 的修复合入后，重跑全检。

## 何时不用

- 一两行的小改动：直接改，跑快检即可。
- 乐趣或方向还没确认的原型：用 `prototype`；游戏走 `weicoz-game-flow` 阶段 1。
