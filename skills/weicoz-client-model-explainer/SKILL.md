# 客户模式白话图解

## 产物与边界

输出一份让没有行业背景的20岁读者能复述的模式说明：谁参与、做什么、钱从哪里来、给谁、什么时候到账、系统提供什么功能、哪些规则尚未确定。

简短指用最少的话保留完整含义。默认覆盖全部功能、奖励、档位、限制、例外和阶段安排；只在用户明确缩小范围时省略，并标出范围。不要将某个客户的参数变成本技能的默认规则。

默认直接在对话交付 Markdown、ASCII 图和表格。用户要求文件或其他视觉格式时按其格式交付；“图文并茂”默认使用有解释作用的图，不自动制作网站、PPT或装饰插画。此技能只负责解释；功能清单、导图、报价、开发规格按用户另行要求交给对应专项流程。

## 1. 读完证据，建立覆盖清单

- 盘点用户本次提供的文件、补充消息与定案记录。复用当前会话已读取且未变的资料，不重复提取。
- 文档读取正文、表格、附注；检查含规则的嵌入图片。表格查看全部相关工作表、说明单元格、公式、单位与缓存值；公式结果不等于已执行重算。原生文本优先，只有图片或扫描件需要视觉/OCR。
- 大文件分段读取，并检查截断、隐藏内容或漏页；工具报错、部分读取不能算全文读取。无法访问的材料明确列为未读取，继续解释可确认部分。
- 在工作笔记维护覆盖清单：`来源位置 | 原规则/功能 | 条件与参数 | 说明中的位置 | 冲突或缺失`。来源位置用章节、段落、图片、工作表与单元格；每项都必须落入解释或未确认项。
- 覆盖人员与等级、用户流程、关系结构、全部奖励、资金池、钱包与积分、支付提现、商城订单、商家、账户权限、后台管理、统计、开关、期次与开发阶段；只列材料实际存在的内容，不凭清单新增需求。

## 2. 核实术语，分开“常见模式”和“客户规则”

- 用户要求找资料，或模式名称陌生、有歧义、存在同音错字时，查公开资料；搜索通用术语和候选正确名称，优先一手规则、原始方案、官方资料。
- 搜索时用抽象关键词，不向外部服务提交客户私密正文或整份附件。网络资料用于核实术语与典型结构，客户参数仍以客户材料为证据。
- 对照实际关系、计奖基数和触发条件后再判断名称；可以判断“包含此模式，还叠加其他机制”。只有客户自称时，写“客户称为……，现有证据不足以确认”。
- 网页的宣传、收益预测、合法性自述不作事实保证。引用支持该判断的具体页面；未能联网时说明术语未外部核实，不补造来源。

## 3. 先把账和流程拆清

不要把不同关系、资产或阶段混成一个概念。尤其分清推荐关系与安置关系、消费金额与计奖业绩、毛奖励与可提现余额、福利额度与实际到账、设计方案与已运行系统。

每项奖励提取：`谁符合资格 → 哪个动作触发 → 按什么数算 → 比例/档位 → 给谁 → 层数/次数/封顶 → 扣除/互斥 → 发放时间 → 停止条件`。未涉及的字段略去；决定结果而缺失的字段写未确认。

每项功能提取：`谁能操作 → 做什么 → 产生什么结果 → 受什么限制`。后台、商家、例外权限和第二期功能也要覆盖；“管理员可调”不意味着存在可任意猜测的默认值。

矛盾处理：并列两处说法及来源，写清对结果的影响。只依据用户确认或明确版本决策选择口径；文件新旧、段落靠后、表格更详细都不能单独证明优先级。保留冲突并继续解释独立部分，不要求先回答全部问题。

## 4. 用费曼技巧写成图解

按读者理解顺序组织，不照抄文档目录：

1. 一句话概括模式，再画参与者、动作、钱或权益流向的总图。
2. 从“假设你刚加入”讲一次完整流程；术语首次出现时就翻译，例如“PV＝用来算奖金的分数”。保留客户原名便于对照。
3. 核心机制用生活类比解释，紧接真实规则，明确类比不代表额外条款。不同关系分图画，箭头写明含义。
4. 所有奖励逐项解释；档位与比例用表格，触发与结算用箭头，关系用树，额度与期次用时间流程。每张图只讲一个问题，避免宽图和重复大段文字。
5. 用紧凑表格覆盖剩余用户、商城、商家和后台功能。列出开发阶段，范围有冲突就保留两版。
6. 最后集中列出未确认项及其影响，并给出可定位的来源；解释不冒充已确认的开发合同。

示意写法（参数必须来自当前材料，或清楚标为假设）：

```text
你 --介绍--> A      这条线：记“谁介绍谁”

       你
      /  \
    左队  右队      这棵树：记“人放在哪里”

符合条件 --> 算毛奖励 --> 扣除/封顶 --> 入账 --> 提现条件
```

用生活例子或心中复述检查读者能否回答：“我做什么才拿到钱？为什么拿这么多？什么时候拿不到？”不用强迫用户答题。全文保留机制全貌，删除重复话术、宣传词和无关技术实现。

## 5. 复算与完整性检查

- 每个算例带清晰单位和假设，核对计算基数、资格、封顶、扣款、发放周期。若只演示毛奖励，紧接说明实际限制，不能直接称为到手金额。
- 逐项对照覆盖清单：每个功能和奖励都有解释，限制和例外没有在压缩时消失，未开放和第二期项目没有被写成现状。
- 比例合计不满或超过100%时回查原文，不能自行补去向；对未配对余额、退款回退、首单判定、层数口径等缺失条件，不套用行业惯例补齐。
- 分期额度不写成保证返还；新资金流入不写成经营利润；文档内截图不写成已验证上线。只有执行了真实业务核验，才报告运行或兑付结果。
- 当资料无法读全、规则冲突或实发计算缺条件时，准确标出边界。交付完整解释与最小待确认清单，不因这些局部缺口丢弃其余内容。

维护本技能时，用 [references/acceptance-cases.md](references/acceptance-cases.md) 的虚构场景检查完整性、算例和冲突处理；客户附件、名称、私有路径和真实业务参数不进入技能仓库。
