# 多设备同步约定

## 命令与数据

源端使用 Python 3.11+，YAML 配置解析依赖 `scripts/requirements.txt` 中的 PyYAML；目标安装器使用 Node.js。Shell 迁移时目标须有 zsh；各 CLI 与原生依赖按目标平台另装。本工具按单一源单向同步，不常驻、不自动连接设备、不执行模型请求。

`package.py` 的 `--source-id`、`--revision`、`--device-id`、`--platform`、`--target-home`、`--output` 为 CLI 必填项。版本号 JSON 通过 `--versions` 输入。覆盖层与 `--keep` 只影响本次设备包；账号授权只通过明确的 `--include-auth` 表达，Kimi/agy 的设备 OAuth 状态始终排除。包目录须保持私有，manifest 与内容一同校验、传输。

`manifest.json` schema 2 记录公共源 ID、公共版本、设备 ID、设备包摘要、文件 SHA-256/权限、内部链接、版本基准、保留路径与停用项。SHA-256 用于完整性核对，不能证明来源可信；只使用可信路径和传输链路取得的包。

安装命令：

```text
node install.mjs <包目录> [--replace 相对路径 ...]
node install.mjs <包目录> [--replace 相对路径 ...] --apply --plan TOKEN
node install.mjs --status
node install.mjs --verify
node install.mjs --rollback 恢复点ID
node install.mjs --collect 设备状态报告.json ...
```

默认预览只读；令牌绑定包、目标现状、已有基线和逐路径替换选择。任何变化后重新预览。有冲突的预览可以查看，应用会失败；`--replace` 只接受本次包内的具体路径，不接受通配符。父目录为软链时停止写入，先核实实际配置根目录；不会穿过技能仓链接改文件。

## 冲突与保留

- 目标不存在：新增。
- 目标已与期望一致：跳过。
- 目标与上次安装基线一致：接受源端更新。
- 目标已有内容却没有基线，或目标偏离上次基线：冲突，停止覆盖。
- 配置源/设备 ID 与已有状态不一致：拒绝，不自动换源。
- 源端撤下旧路径：报告 `retained`，保留磁盘内容，停止管理该路径。
- `--keep` 路径：不打包源文件，不覆盖目标；整文件覆盖层按顺序取最后一份。

## 事务与恢复

状态位于目标 `~/.local/state/harness-config-sync/state.json`。同根目录的 `lock` 防止本工具并发写入；`transactions/<恢复点ID>/` 保存安装前文件、链接元数据、原状态、事务日志与安装报告，目录私有。

应用前完成哈希、路径、链接目标、JSON 与 Shell 检查，再备份所有更改对象。文件用同目录临时文件替换；每次写入前再次比较目标。异常时按事务恢复之前的内容与入口。新建的空父目录可以保留；配置、个人历史和旧备份不做自动清理。

正常回滚只接受当前最新事务，且目标尚未再次修改。未完成事务会阻止新同步，旧的失败事务不能覆盖后续基线。崩溃或掉电没有机会自动回滚；恢复时根据未完成事务日志处理，不能把进程退出成功当作验收。备份本身发生 IO 错误时保持现场并报告恢复点。

## 验证边界

`--status` 核对文件摘要、权限和入口关系。`--verify` 增加固定 CLI 的 `--version` 和 Kimi `doctor`，捕获输出但不回显配置正文；没有版本基准则版本一致性未验证。`--collect` 只汇总调用方提供的报告，报告时间代表采集时间，不代表设备此刻在线。

模型网络链路、登录身份、Hook 实际执行、全部 MCP/插件功能与桌面 UI 由迁移 Agent 在已授权目标另验。真实请求分别保留 `chat` 或 `respond` 等源协议，不擅自切换模型或协议。
