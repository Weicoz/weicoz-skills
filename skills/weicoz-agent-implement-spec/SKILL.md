# 整规格委派实现

派单方把整份规格交给一个编排执行方，负责监控和最终验收；编排执行方按 `implement-spec` 调度实现与合并代理。不要把 spec 当一张大票套用 `implement`，也不要只把所有票同时发出去。

## 读取与任务边界

先完整读取当前环境解析后的 `implement-spec/SKILL.md`，优先 `~/.agents/skills/implement-spec/`；核实执行环境也可访问。缺失时查宿主技能目录，不声称已加载。读规格、关联票据和适用 AGENTS，确定 issue tracker（可以是项目指定的本地 Markdown）、验收项、阻塞关系、工作分支与授权。

原文要求 issue tracker；先使用项目已规定的来源，不擅自改成外部平台。如果无法定位规格／票据或其依赖关系，先完成可做的只读梳理，再集中指出缺失输入；确实需要原文的 setup 工具时才说明，不把安装工具当所有项目的前置门槛。

当前主流程：任务 DAG 与 frontier → integration 分支 → 每票独立 worktree／分支的 implementer → merger 合入 integration → 刷新 frontier → integration 整体 code-review → 单个 implementer 修复审查问题 → 按 tracker 规则关闭／PR ready → 清理本次 worktree。现场原文更新时跟随它；用户／项目规则与授权优先。

## Git 授权默认值

用户明确要求委派实现整份规格，且当前指令或适用项目规则没有禁止时，授权包含该任务所需的仓库本地 Git 操作：建立基线提交、创建临时分支／worktree、逐票提交、将 integration tip 合入票据分支，以及由唯一 merger 合入 integration。该范围传给派单方、编排器与全部执行角色，不重复确认。阅读／审查本技能或询问委派可行性不构成启动授权。

仓库没有 HEAD 时，先核对基线文件清单，再建立本地基线。必要源码、配置、规格与票据可以纳入基线；基线提交与实现提交分开，不夹带无关改动、凭据、设备标识、签名、日志、二进制或私有产物。已有未提交工作与入口关系保留，正常 hook 照常执行。

用户或项目明确要求只读、不提交、不合并或禁止临时分支时，遵守更具体限制，不以默认值覆盖。本地 Git 授权不包含 push、远程 PR、部署、发布、付费或跨设备执行；这些动作按已有的对应授权执行。用户明确要求在指定仓库提交并推送时，执行该已授权范围，不再次确认，也不扩展到其他仓库。

## 给编排执行方的提示词

首行点名 **implement-spec**，并给出规格与票据来源：

```text
$implement-spec 实现规格 `<规格路径>`，关联票据位于 `<票据目录或 tracker 引用>`。
```

宿主不支持该调用语法时：

```text
使用 implement-spec 技能：先完整读取 `<执行环境中已核实的 implement-spec/SKILL.md 绝对路径>`，编排实现规格 `<规格路径>` 及 `<票据来源>` 的关联票据。
```

补充项目上下文指针、验收与范围、明确的代理／模型／设备、integration 基线与允许的 Git／tracker 行为。要求该约束传给 implementer、merger、探索和审查代理；用户要求所有代理同模型时覆盖全部角色。不能只给主编排器指定模型。保留宿主模型别名和可用能力，不固化某次选择为长期默认。

对单票 implementer 的任务可以首行点名 `implement`（先核实其原文），但必须附加 implement-spec 的 worktree 基线、TDD、同步 integration tip、交付与合并约束；单票 wrapper 不能替代整规格编排器。上下文主要传规格、票据、研究笔记、提交等指针，不复制大段已存在材料。可选探索笔记保存在仓库外且所有执行方能访问的位置；远端指针需实际同步，不假设本机路径可见。

## DAG、worktree 与合并

1. 建立票据状态和阻塞关系；frontier 仅包含所有前置依赖已验收并合入 integration 的票。对环、缺票、含糊依赖和越界验收项报告具体缺口；独立就绪票仍可推进，不能把阻塞票标完成。
2. 按项目分支规则确定单一 integration 分支，记录基线提交；若项目约定唯一开发分支，将它作为整合位置，不暗改主分支。按 Git 默认授权创建本任务临时分支／worktree；若明确禁止所有临时分支，串行复用允许的分支和角色职责，保留 DAG 与逐票验收，如实报告无法 worktree 并行，不因此停摆或绕过约定。检查未提交资料并按需复制，不混入实现提交。
3. 允许临时分支时，每票一个独立 worktree／分支与实现会话；开始前核实基于最新 integration。基线不符时在保留现有改动后安全同步，禁止照抄“reset”而丢弃用户工作。独立票可后台并行，共享文件／迁移编号／端口先分配归属。
4. implementer 按 TDD 实现，跑相关检查，报告完成前将 integration 最新 tip 合入自己的分支并处理冲突。不能用“代码已写完”跳过基线同步和验证。
5. 指定 merger 作为 integration 唯一写入者，串行验收并合入票据分支，防止多个代理同时操作 integration。冲突按意图解决并按影响验证，不能任选一侧覆盖。每次合入后更新状态与 frontier，立即调度新就绪票。
6. 全票完成后，在 integration 上调用 `code-review`；缺 Skill 工具时读取该技能执行。审查问题集中交给一个 implementer 修复，避免多个修复互相覆盖；修复后按影响重检并核实审查闭环。

宿主无法创建所需子代理或 worktree 时，优先核实可用 CLI 的能力。确实无法满足时如实说明缺口，可顺序实现已有角色职责但须保留 DAG、隔离、唯一合并写入者和证据，明确未实现多代理并行；不能伪称已启动 implementer／merger。

## 执行、资源与恢复

实际启动和监控复用 [单票委派的运行约定](../weicoz-agent-implement/SKILL.md) 中“启动与运行环境”“资源、监控与恢复”的通用部分；不把单票主流程或每票完整套件要求应用到整规格，检查安排见下节。未指定代理时可用 Codex，模型用执行环境当前配置；指定模型、设备和范围原样保留。原生子代理与 CLI 都按本次实际可用能力选，不将原生代理 ID 当 CLI 执行证据。

正常委派默认允许任务所需的依赖下载与隔离连接测试；实际核对任务网络和重任务队列写权限，不把工具的默认禁网误当成用户限制。用户或项目显式禁网时遵守；保留 workspace 隔离，不为联网改成全盘权限，也不改现有代理、TUN 或机器全局配置。

用户明确授权远端（例如 M4）才使用 `weicoz-remote-dispatch`；每次派票、续跑和重检查前核对实际执行机资源。遵守宿主并发上限；负载／内存压力／磁盘不足时收缩 frontier 的并发度或排队重检查，不改变 DAG，不擅自迁机、删数据、杀他人进程或绕过检查。远端脚本自动 push 也要纳入授权判断。

按用户指定周期汇报，未指定约每 10 分钟，宿主更高优先级沟通频率优先；里程碑和阻塞及时报。报告 integration 提交、已合入／执行中／就绪／阻塞票、实际执行方式与模型／设备、资源、检查及下一步。超时保存编排和子任务 ID、worktree、提交与票据状态，先核实哪些仍在运行再续跑，不能重新派出同一张在跑的票。

## 检查、授权与收尾

各票按自身验收项和适用项目要求检查；implement-spec 原文不要求每票全套，不能无依据跑 N 次完整套件。若该票明确采用 implement 且要求全套，或项目要求全套，则安排一次并复用正常 hook 的真实结果。不禁用 hook，也不为绕过失败改配置。整合后按项目要求完成 integration 全套与组合验证：各票独立通过不证明组合通过。修复／冲突／新失败按影响补检，不能把“一次”当免检；每台机器重检查依资源排队。

本地提交与内部合并按“Git 授权默认值”执行；PR 与关闭票据按对应 tracker 及已有授权执行。用户或项目明确禁止提交／合并时，先完成可行实现与检查、保留差异，报告哪些后续票因未合入而阻塞，不能宣布整规格完成。

只有 tracker 以 PR 关闭或用户要求 PR，且对外创建已获授权时，才在首次合入后创建 draft PR（空 integration 不创建），关联规格与票据。全部验收通过后才按授权标 ready；无 PR 则按 tracker 原有关闭方式处理。外部 tracker 写入同样服从已有授权，不以本地完成推断远端已关闭。

最终验收读取 integration 实际差异与各票证据，核实范围、依赖、TDD／review、正常 hook、测试与关键路径冒烟，并列出未验证边界。受范围限制排除的票／验收项如实留下，不能关闭整份规格。完成后仅清理本次创建、成果已保留且无未取回／未提交数据的 implementer worktree；不得删除未归档、未取回的成果、用户旧目录或备份；本任务临时文件确认无用、成果安全保留后可按授权清理。

交付 integration 分支／提交、各票状态与证据、实际 PR／tracker 状态、检查和清理结果、剩余项。计划、日志摘要和退出码不能冒充整规格已交付。
