# 游戏驱动、超分与串流优化

交付一份可追溯的逐游戏优化报告。把当前状态、配置建议、真实测量与未验证项分开；只做用户已授权的部分。默认简体中文，深度随需求，不以风格压缩丢失证据和边界。

## 先判定本次任务

| 用户意图 | 执行范围 |
|---|---|
| “讲讲／先告诉我／给流程／别开始／保存成Skill” | 解释、归档或计划；不连接目标机做新的检查、不启动游戏、不改配置 |
| “检查电脑并给建议” | 已授权目标的只读盘点；不更改驱动、DLL、游戏或网络 |
| “按这套方案开始测试” | 在已明确的游戏、主机、客户端和临时修改范围内测试；不重复索取已给授权 |
| “保留推荐值／写入设置” | 保存指定结果并回读验证；未明确保留时测试结束恢复原状态 |

首先确认重点是驱动/DLSS、游戏内部画质还是串流。用户已懂游戏画质且明确要K/L/M时，先给模型、覆盖入口、当前Profile及推荐组合，不再以降阴影等通用建议替代问题。

## 核心判断

1. **分开模型、输入尺寸、帧生成。** K/L/M是SR模型预设；质量/平衡/性能改变渲染输入；FG插入额外帧。DLL版本不是模型，更不是实时覆盖证明。
2. **旧卡先比较成本。** 截至资料日期，K为第一代Transformer，M/L为第二代；RTX20/30缺原生FP8，M/L开销更大。K是候选，不保证比原生CNN快。M重点面向性能模式，L重点面向4K超级性能；不按字母顺序判断更优。
3. **“推荐”不等于固定模型。** 历史官方映射为性能M、超级性能L、其余K；当前版本需核实。先固定模型比较，不让档位改变偷偷引入第二个变量。
4. **配置、组件、运行态分证据。** DRS读取、App缓存、DLL文件、加载模块、DLSS Overlay和客户端输出分别记录。未找到设置不等于关闭，缓存支持不等于实际可选或生效。
5. **串流以客户端验收。** 主机SR通常进入最终游戏帧；LSFG/驱动FG/原生FG是否被捕获要分别验证。不承诺小黄鸭一定有效，也不泛化为所有插帧都无法串流。
6. **保持输入响应和原生帧口径。** Presented、Displayed、基础帧、生成帧、主机帧时间、编码/网络/解码与真实端到端延迟不可混用。
7. **先定位瓶颈。** 降分辨率无改善时检查CPU线程、限帧、同步、编译、存储、显存预算和串流等待；GPU低占用不是CPU瓶颈的充分证据。
8. **不堆优化开关。** NIS锐化、DSR、模型、限帧、电源、同步分别试。禁用HPET/反作弊/安全软件、清缓存/清内存、DLL注入和双卡采购不列通用默认。

## 最小完整流程

1. 读取本次目标和已有证据，标明操作授权。资料不足先检查可读证据；真正影响测试的客户端、场景或控制能力缺口集中问一次。
2. 只读盘点硬件、驱动/App、已发现游戏、实际EXE、DRS关联、DLSS组件及当前串流条件。区别已安装、空目录、备份、缓存和重复路径。
3. 建立每游戏行：当前状态、支持证据、建议模型、模式候选、特殊风险、验证办法。无DLSS不硬套K/L/M；覆盖不可用就保留条件性建议。
4. 需要实测且已授权时，按操作规程选一款试点；备份、确认生效、单变量采集、动态画质、客户端对比。
5. 比较重复结果与波动，先恢复再交付；保留设置必须在本次授权范围内。中断/失败也报告实际恢复状态。
6. 输出报告、来源、配置差异、数据及回退记录。没有实测时不填预测FPS冒充结果。

## 资料维护与公开边界

本技能的历史案例起源于一台RTX2060 6GB串流电脑；硬件建议不是跨设备最优参数。历史实测状态仍是“未进行游戏A/B测试”。后续每次刷新要另记日期、版本与证据，不覆盖原始记录来伪造当时结论。

`local-case/`只保留本机资料；不使用`git add -f`提交，不把完整游戏库、主机地址、用户路径或存档上传。发布/打包默认仅使用Git跟踪文件，不能递归打包整个技能目录而带出本地附件。用户要求完整私人备份时，另交私人归档并核对清单。

不提供自动修改注册表、批量换DLL或自动启停远程服务的脚本。历史只读探针在附件中保留，复用前按当前官方NVAPI头文件检查ABI、设置ID和只读调用边界；禁止把它扩展为无备份批量写入器。
