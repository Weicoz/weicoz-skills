# 对标指标

## 表格模板

写进项目的 `docs/benchmark.md`，每次调生成器或关卡后更新“当前值”：

| 指标 | 参考值 | 证据 | 目标范围 | 当前值 | 达标 |
| --- | --- | --- | --- | --- | --- |
| 棋盘尺寸 | 约 22×30 | `reference/frames/f001.png` | 20–24 × 28–32 | | |
| 格子占用率 | ≥ 95% | f001 | ≥ 90% | | |
| 物体数 | 约 60 | f001 | 50–70 | | |
| 平均每根转折数 | ≥ 3 | f001 局部放大 | ≥ 3 | | |
| 规律度 | 相邻同向、直线段极少 | f001 | 直线物体 ≤ 10% | | |

参考值写不出精确数时写区间，并标“目测”。证据列必须指向具体帧。

## 常用指标

| 玩法类型 | 指标 |
| --- | --- |
| 网格解谜（拆线、移出、推箱、连线） | 棋盘尺寸；占用率；物体数；长度分布；转折数；方向分布；开局可走步数；最短解步数；死路率 |
| 排序 / 消除 | 颜色数；每列容量；空列数；初始混乱度；最短解步数 |
| 街机 / 躲避 | 同屏对象数；速度；生成间隔；预警时长；最小逃生空隙 |
| 所有类型 | 单局时长；失败惩罚；HUD 元素清单；首关到第 N 关的变量曲线 |

“开局可走步数”和“死路率”直接决定难度：可走步数越多、可安全试错，游戏越简单。

## 生成器输出指标

生成器生成一关时，同时输出该关的指标值。测试分两类：

```ts
// 1. 正确性：按 solution 回放必须清空棋盘
expect(replay(level, level.solution).cleared).toBe(true)
// 2. 对标：指标落在目标范围
const m = measure(level)
expect(m.occupancy).toBeGreaterThanOrEqual(0.9)
expect(m.avgTurns).toBeGreaterThanOrEqual(3)
```

第 2 类测试让“太简单”变成跑不过的测试，而不是等用户试玩后才发现。前几关可以低于目标，但曲线要写明：哪一关起达到参考水平。
