## 工具优先级与降级

制作本技能涉及的流程图时，严格按以下顺序选择工具：

1. **Excalidraw MCP/CLI 优先**：先检查刚安装的 Excalidraw 服务是否可用；可用时使用它创建、编辑、截图、导出和检查图表。CLI 入口：`npx -y mcp-excalidraw-server`，画布默认使用 `http://127.0.0.1:3100`。
2. **Draw.io MCP 降级**：Excalidraw 未安装、启动失败、端口不可用或无法导出/截图时，检查并使用 Draw.io MCP 创建、编辑、加载、导出和检查图表。
3. **ascii-art 降级**：Excalidraw 与 Draw.io MCP 都不可用、启动失败或无法导出画布时，使用 `$ascii-art` skill 生成 ASCII 图；先读取其 `SKILL.md`，再按其工具决策流执行。
4. **原生 ASCII 兜底**：`$ascii-art` skill 不可用时，直接按本技能的 ASCII 规范输出普通 ASCII 码图，并明确标注未使用 Excalidraw、Draw.io MCP。

不得在 Excalidraw 或 Draw.io MCP 可用时直接跳到 ASCII；不得把静态 XML 合法性检查冒充实际画布检查。

### 工具检查记录

交付时说明实际采用的层级：`Excalidraw MCP/CLI`、`Draw.io MCP`、`ascii-art` 或 `原生 ASCII`，并记录降级原因（如服务未安装、端口冲突、MCP 未配置、启动失败、导出失败）。

- 画布服务固定使用 `http://127.0.0.1:3100`，避免占用常见的 `3000` 端口；必要时通过 `EXPRESS_SERVER_URL` 指定。

# 树状泳道流程图制作规范

## 目标

把“谁在什么时候做什么、遇到什么判断、资料交给谁、最后得到什么结果”画清楚。泳道首先表达责任归属，其次才表达时间方向；不强制所有流程左进右出。

## 默认画法

采用示例式树状泳道：

- 泳道竖向排列，角色列从左到右。
- 每条泳道顶部放横向角色标题，标题不能竖排。
- 流程主线优先在同一泳道内自上而下排列。
- 发生交接时才跨泳道连线，使用短的正交线。
- 判断使用菱形，分支使用“是/否”“标准品/定制品”等短标签。
- 多条分支必须错开高度，不能让所有分支共用一条水平通道。
- 总览页只画业务入口和主要分支；详细流程拆到独立页面。

推荐结构：

```text
开始
  |
  v
判断？
  |---- 分支 A ----> A 责任泳道内向下执行
  |---- 分支 B ----> B 责任泳道内向下执行
  |---- 分支 C ----> C 责任泳道内向下执行
```

## 制作流程

### 1. 先整理业务事实

从需求文档或会议记录提取：

- 参与角色：客户、业务员、财务、仓库、工程、售后、ERP、第三方平台等。
- 每个角色的动作：一个框只写一个主要动作。
- 判断条件：金额、审核结果、付款方式、是否安装、是否成功等。
- 交接资料：订单、凭证、图纸、物流单、售后单、ERP 单据。
- 最终结果：完成、取消、退款、换货、人工补录、待确认。

不明确的规则写成“待确认”，不要在图上补猜测。

### 2. 设计树根和分支

先确定一个入口，例如“进入小程序”“提交报销单”“创建工单”。然后按业务判断拆树：

1. 入口和登录/创建记录。
2. 第一层业务判断。
3. 每条分支的责任角色和处理结果。
4. 异常、驳回、重试、人工处理出口。

不要把所有细节塞进总览页；总览用于讲清结构，分支页用于讲清操作。

### 3. 规划泳道

通常使用 4～6 条泳道。角色过多时按责任合并，例如：

- 客户 / 业务
- 小程序 / 管理后台
- 财务 / 仓库
- 工程 / 跟单
- 售后人员
- ERP / 售后系统

泳道标题使用客户能理解的业务名称，不使用只对开发人员有意义的内部简称。

### 4. 放置节点

- 节点放在所属角色泳道主体内，不能压住顶部标题。
- 同一泳道的连续动作优先垂直排列。
- 并行分支放在不同高度，不要堆在同一行。
- 节点文字写“动作 + 对象”，例如“财务核销付款”“上传转账凭证”“同步 ERP 受订单”。
- 长规则放在页面说明或备注，不把节点做成大段文字。
- 总览页每条分支保留 1～3 个节点即可；详细页面再展开。

### 5. 画连线

连线规则按以下顺序：

1. 同一泳道的连续步骤：从下边进入上边，垂直向下。
2. 跨泳道交接：从节点侧边出，横向到目标泳道，再从目标节点上边进入。
3. 分支：给每条分支分配独立的出线高度或转折点。
4. 回退：使用虚线或明显的回线路径，避免与主线重合。
5. 异常：使用红色或虚线，但仍要写明人工处理后的结果。

不要强制左进右出。只要责任清楚、时间顺序清楚、连线不遮挡，向上、向下、向侧面连接都可以。

### 6. 控制连线文字

连线文字只保留关键判断和交接条件，例如：

- `≤2万元`
- `＞2万元`
- `审核通过`
- `同步失败`
- `3次仍失败`

动作名称直接写在节点里。长连线上的长句会覆盖节点或让读者误判路径，应删除、缩短或移到页面备注。

### 7. 页面拆分

推荐至少包含：

- `00-业务树状总览`
- `01-标准品树状流程`
- `02-定制树状流程`
- `03-售后树状流程`
- `04-月结分销树状流程`
- `05-异常恢复树状流程`

流程少时可以合并页面；流程多时宁可拆页，不要在一张图上堆出互相穿过的线。

## Draw.io 实现注意点

### 泳道不要直接依赖竖排 swimlane 标题

为了稳定得到“顶部横向标题 + 竖向主体”，优先使用两个普通图形组合一条泳道：

1. 一个无文字的矩形作为泳道主体。
2. 一个高度约 28～32px 的矩形作为顶部标题栏。

这样可以避免 `swimlane;horizontal=0` 在不同 Draw.io 版本中出现标题竖排、泳道嵌套或自动改写父子关系。

示例：

```xml
<mxCell id="lane-customer" value=""
  style="shape=rectangle;rounded=0;fillColor=#ffffff;strokeColor=#60a5fa;strokeWidth=1.5;"
  vertex="1" parent="1">
  <mxGeometry x="20" y="90" width="150" height="850" as="geometry"/>
</mxCell>
<mxCell id="lane-customer-head" value="客户 / 业务"
  style="rounded=0;fillColor=#dbeafe;strokeColor=#60a5fa;strokeWidth=1.5;fontSize=13;fontStyle=1;align=center;verticalAlign=middle;"
  vertex="1" parent="1">
  <mxGeometry x="20" y="90" width="150" height="30" as="geometry"/>
</mxCell>
```

### 端口与走线硬规则（踩过的坑，必须遵守）

1. **出线方向必须指向目标**：跨泳道时从"面向目标的一侧"出线（目标在左就从左边出、在右就从右边出）。
   禁止"背离目标出线再折回来"——Draw.io 自动绕线会补一个反向小段，形成肉眼可见的小钩子。
2. **跨泳道标准走法**：源节点侧边出线 → 横移到目标所在列 → 竖直到目标的上下边进入。
   不要用"底部出线 + 底部横向通道 + 目标底部进入"这种写法，通道与入口外伸段冲突时会折返。
3. **长距离分支（跨 3 列以上）**：改成"源侧边出线 → 目标侧边进入"，避免竖线穿过同列中间的节点；
   同一目标有多条入线时分开用上边 / 侧边两个入口。
4. **箭头不要插进节点**：`perimeterSpacing=8` 必须配 `exitX/exitY/entryX/entryY`；
   箭头落点要停在边界外侧，入口前最后一段不能落在目标矩形内部。
5. **转折通道不要贴着外伸段**：人工转折点与端口外伸段至少留 16px，否则会出现 2px 级反向小段。
6. **写生成器而不是手拖**：端口与转折点用脚本按"行列坐标"算出来，改一次行列号全图重排，避免手改漏改。

### 交付前必跑的几何自检（脚本化）

用官方渲染器截图之前，先跑一遍几何检查（脚本可复用本仓 `项目目录名-泳道图几何检查.py`，按 .drawio 解析）：

- 节点互相重叠 / 节点压泳道标题 / 节点越出泳道
- 说明框压流程节点、图形越界
- 连线穿无关节点（保持 10px 视觉间距）
- **箭头插入节点**（入口前最后一段落在目标矩形内即报错）
- **折返钩**（相邻同向轴反向掉头，含 2px 级微小反向段）
- **端口落点**（exit / entry 必须落在边界 ±3px）
- **入口方向**（侧边进入必须横向、上下边进入必须纵向）

检查不通过就不要进入截图复核；截图复核时除整图外，必须再放大看流程末端与各分支汇合处。

### XML 基本要求

- 每页必须有 `<mxCell id="0"/>` 和 `<mxCell id="1" parent="0"/>`。
- 每页内部的 `id` 必须唯一；不同页面可以重复使用相同短 ID。
- 节点和泳道主体不要重叠；节点顶部应低于标题栏底部。
- 连线使用 `edgeStyle=orthogonalEdgeStyle`，并明确 `exitX/exitY/entryX/entryY`。
- 长距离跨泳道线需要加入转折点，不能直接横穿无关节点。
- 标签中出现 `&`、`<`、`>`、引号时必须进行 XML 转义。

## 避免遮挡的检查清单

### 结构检查

- [ ] 每个动作只有一个责任泳道。
- [ ] 每个判断都有明确的分支去向。
- [ ] 退回、驳回、取消、重试和人工处理有出口。
- [ ] ERP、支付、售后等外部系统交接写出单据或结果。

### 视觉检查

- [ ] 标题栏文字横向可读。
- [ ] 节点不压住泳道标题。
- [ ] 连线不穿过无关节点。
- [ ] 分支线不共用同一条水平通道。
- [ ] 连线标签不压住节点或其他标签。
- [ ] 同一泳道连续动作尽量自上而下。
- [ ] 总览页没有把所有细节塞在同一层。

### 实战问题沉淀：节点、箭头与画布边界

以下规则来自实际 Draw.io 复核中发现的遮挡和箭头错位问题，制作完成后必须逐项检查：

- **说明框必须避开流程区**：说明、备注、图例统一放在所有流程节点和连线的下方；先计算流程内容的最大 `y + height`，再预留至少 40～80px 间距，不能用说明框覆盖节点或连线。
- **页面高度要包住全部内容**：`pageHeight`、背景矩形和泳道主体高度必须覆盖最后一个节点、说明框及底部留白；不能只扩大背景而不扩大页面边界。
- **同一目标有多条入线时必须分入口**：不要让两条边都进入同一个节点的顶部中心，否则会出现箭头重叠、双箭头或像“箭头插入节点”的效果；改用顶部 + 左/右侧，或设置不同 `entryY`。
- **同层跨泳道优先使用侧边到侧边**：两个节点处于同一纵向层级时，使用 `exitX=1;entryX=0`（或反向）水平连接；不要从源节点底部绕到目标顶部，避免出现反向箭头或不必要的折返。
- **分支要先区分业务语义再连线**：正常完成、异常重试、退款、驳回等是不同出口；正常完成不能错误地经过退款/异常节点。每个判断分支都应直接连到语义对应的下一个节点。
- **异常回路使用独立通道**：重试、补回、人工处理等回路使用虚线、独立转折列和侧边端口；不得与主线共用同一条水平线，也不得回穿节点。
- **长距离交接要避开节点主体**：跨多个泳道时先走节点外侧的安全通道，再从目标节点侧边或顶部进入；转折点至少留出 20～30px 间距。
- **不要只看整图缩略图**：必须同时检查全图、流程末端放大图和每个分支汇合处；缩略图看似正常时，箭头头部仍可能压住边框或文字。
- **箭头与节点保留视觉间距**：Draw.io 连线建议加入 `perimeterSpacing=8`，并使用明确的 `exitX/exitY/entryX/entryY`；箭头应落在节点边缘外侧，不要插入节点边框或文字区域。
- **固定路径优先于自动绕线**：出现箭头跳位、线贴到节点底边或回路线反向时，使用 `orthogonalLoop=0` 配合明确转折点；不要完全依赖 Draw.io 自动路由。
- **长线标签加白底**：跨泳道长线使用 `labelBackgroundColor=#ffffff`，标签只写“签收、验收通过、同意退货”等短语，避免标签与泳道背景、节点文字混在一起。

## 验证流程

使用 Excalidraw MCP/CLI 时：

1. 检查服务状态：`EXPRESS_SERVER_URL=http://127.0.0.1:3100 npx -y mcp-excalidraw-server status`。
2. 启动服务：`PORT=3100 EXPRESS_SERVER_URL=http://127.0.0.1:3100 npx -y mcp-excalidraw-server start`。
3. 创建节点和连线后运行 `describe`，确认责任泳道、节点和连接关系。
4. 打开画布后运行 `screenshot`，使用原生图片查看工具检查遮挡、穿线、文字截断。
5. 发现问题先 `update` 修复，再重新截图；最后 `export --out <path>.excalidraw` 保存可编辑源文件。

使用 Draw.io MCP 时：

1. `start_session` 启动会话。
2. `load_diagram` 加载 `.drawio` 文件。
3. `list_pages` 检查页面数量和名称。
4. `export_diagram` 分别导出总览页和关键分支页 PNG。
5. 使用原生图片查看工具检查实际画布，而不是只看 XML。
6. 发现遮挡后，优先调整节点纵向位置和连线转折点；不要用裁剪、隐藏溢出或缩小到不可读来掩盖问题。

Excalidraw 与 Draw.io MCP 都不可用时，先使用 `$ascii-art` skill。若该 skill 也不可用，才执行原生 ASCII 兜底。

使用 `$ascii-art` skill 时：

1. 先输出或保存 ASCII 总览。
2. 维持角色泳道、判断、分支、交接和异常出口结构。
3. 宽度遵循 ASCII skill 的终端安全限制；过长文字拆行或放入说明。
4. 交付时标注 `ascii-art 降级`，不输出未经验证的 Draw.io 截图声明。

原生 ASCII 兜底时，至少执行：

```bash
xmllint --noout path/to/diagram.drawio
```

并使用 Draw.io / diagrams.net 实际打开检查。

## 常见错误

### 把泳道当成普通分栏表

只有角色列，没有树根、判断和分支，读者无法知道先后关系。修复：先画入口和判断，再放角色动作。

### 所有线都左进右出

跨泳道线会穿过其他节点，图看起来像电路线。修复：主流程在泳道内向下，横线只表示交接。

### 一张图堆完所有流程

标准品、定制、售后、分销和异常互相穿线。修复：总览保留分支，详细流程拆页面。

### 文字写在长连线上

标签会覆盖节点或其他线。修复：动作写进节点，边上只留判断词和关键状态。

### 只验证 XML，不看画布

XML 合法不代表节点位置合理。修复：必须导出 PNG 或在浏览器中打开，做真实视觉复核。

## 最终原则

先保证“谁负责、先做什么、判断后去哪、失败怎么办”能一眼读懂，再补颜色和装饰。泳道图的合格标准是责任和路径清楚，不是连线数量多。
