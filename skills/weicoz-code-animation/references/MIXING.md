# 开做之前要定的事

不用逐条问用户。能从上下文推断的自己定，只有会改变成品的才确认（时长、比例、要不要声音）。

## 1. 六个参数

| 参数 | 默认 | 什么时候必须确认 |
| --- | --- | --- |
| 时长 | 8 秒 | 用户说"短片/预告/讲解"→ 按用途定：卡点 6–10s，解说 30–120s，片头 3–6s |
| 比例 | 1920×1080 | 用户提到抖音/小红书/视频号/手机 → 1080×1920 |
| 帧率 | 30 | 要放到 60fps 平台且动作很快 → 60（渲染时间翻倍） |
| 文案 | 用户已给 | 没给就先由你写，交付时标注"文案为占位，可替换" |
| 声音 | 无 | 用户提到 BGM/配音/解说 → 必须确认音频来源与授权 |
| 风格数 | 1 | 用户说"几种风格混"→ 最多 3 种，并指定衔接物 |

## 2. 成片规格（默认值来自库内 V 系列规范）

- 视频：H.264 MP4，`yuv420p`，1920×1080，30fps，时长精确（8s = 240 帧）。
- 音频：有声音时 AAC 48kHz 立体声。
- 响度：−14 LUFS 积分响度，真峰 ≤ −1 dBTP。
- 字幕：中文一行不超 18 字；有配音时逐字或整句出现，按 §3 停留。

## 3. 文字上屏的硬指标

- 1080p 下字号 **≥ 20px**；正文建议 36–48px，标题 72px 以上。
- 停留时间（中文）：`字数 ÷ 4.5 + 1.5` 秒。10 个字 ≈ 3.7 秒。
- 有配音：`max(1.8s, 语音时长 + 0.6s)`。
- 一屏只讲一件事；同一行塞两种信息量就会读不过来。
- 收尾帧至少停 0.8 秒，否则观感像被切断。

## 4. 声音怎么处理

1. **先问要不要**。用户没说就默认无声，并明确告知"当前无音轨，需要可加"。
2. **只用有授权的素材**：用户提供的音频、明确免版税的曲库、或用代码合成（Web Audio 正弦/噪声/琶音）。
3. **不得**从视频平台抓音乐、不得用来源不明音频。
4. 合成音效的常用做法：短促正弦做"滴"、白噪声包络做"唰"、低频正弦下滑做"咚"。合成很简单，够用。
5. 有声音就必须做响度归一：`-af loudnorm=I=-14:TP=-1`。`render_mp4.sh --audio` 已内置两遍归一（先测后放），手写 ffmpeg 时要自己跑两遍，单遍差 2 LU。
6. 无声片的判断依据是"静音也能看懂"：所有关键信息都在画面上，不能只靠旁白。

## 5. 竖屏不是横屏裁一刀

| 项 | 横屏 16:9 | 竖屏 9:16 |
| --- | --- | --- |
| 画布 | 1920×1080 | 1080×1920 |
| 主视觉位置 | 居中或三分线 | 上 2/3，底部留字幕区 |
| 一行字数 | 18 字 | 12 字 |
| 安全区 | 左右各留 60px | 顶部 160px、底部 320px 不放关键内容 |
| 节奏 | 一镜到底可慢 | 每 1.5–2.5s 必须有一次变化 |

## 6. 交付清单

- `index.html`：单文件，可改可重渲。
- `out.mp4`：按 §2 规格。
- 一句话说明：风格 ID、时长、比例、是否含音轨、文案是否为占位。
- 需要时附关键帧截图（`shot.sh` 出图）供快速查看。

## 7. 别做的事

- 别把 341 条风格一次塞进上下文：先检索，只读命中的那一两条。
- 别凭记忆复述风格提示词：必须读 `library/` 里的原文，配色和参数都在里面。
- 别在没验证 `?t=` 的情况下直接出片：会渲出一堆重复帧。
- 别承诺"像某部电影"却不写来源：O 类提示词里已经标了片名与摄影师，照抄即可。
